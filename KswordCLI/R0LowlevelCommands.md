# R0 low-level CLI controls

All commands support `--backend r0` and `--json`. The CLI never falls back to R3 for these commands. Inspect `status`, `lastStatus`, and the returned evidence; exit code 6 indicates an incomplete result or a write whose readback did not match.

* `r0 io-timer start|stop --driver NAME --driver-object VA --device-object VA --timer VA --confirm` uses the identities from an I/O timer snapshot. The driver revalidates all three addresses.
* `r0 platform-edit --scope N --index N --table VA --expected VA --value VA --confirm` uses a supported HAL/WDF platform snapshot entry and atomically verifies the expected slot value. The returned table, slot, previous and current values are the operation evidence.
* `r0 debug-output-control --action query|start|stop [--confirm]` queries or changes capture. Start and stop require `--confirm`; start clears the existing buffer. Use `r0 debug-output` to read records.
* `r0 research-topic --topic N [--max-entries N]` returns one topic's live context and evidence. Valid topic IDs are defined by `shared/driver/KswordArkResearchIoctl.h`; max entries is 1..16.
* `r0 token-privilege query --pid PID [--creation-time FILETIME]` returns the target process creation time and complete primary-token privilege LUIDs and attributes. `r0 token-privilege enable|disable|remove --pid PID --creation-time FILETIME (--luid LUID | --name NAME) --confirm` binds the operation to that creation time and reads it back. Removal cannot be undone for that token.
* `r0 process-protect query` returns the complete rule/trust table and capability status. `r0 process-protect apply --data-file PATH --confirm` reads a binary `KSWORD_ARK_PROCESS_PROTECT_CONFIG_REQUEST` defined in `shared/driver/KswordArkProcessProtectIoctl.h`, validates its size, version, counts, strings and enabled rule semantics, then replaces **both entire tables** and reads back the result. Populate `size` and `version`, then the global flags, rule and trusted counts, scan interval, and arrays using the exact current Windows protocol layout. Entries omitted from the file are removed. The kernel currently clears both tables if it rejects rule semantics; the CLI validates the known rules before sending, but inspect state after any failure. An out-of-range scan interval is normalized to the driver's default. Capability status must be inspected separately from whether the configuration was stored.
