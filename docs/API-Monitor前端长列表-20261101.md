# API Monitor 前端长列表与贴底修复

## 范围与结构

入口：监控 → WinAPI → API 事件。页面归属参数执行页及监控结果列表，继续复用 ParameterWorkspace、StyleJoinedResultTabs、TableActionTableView、Full 表格操作条、ThemeItemForegroundDelegate。覆盖快照页和 Agent Hook 引擎不在本次变更范围内。参考现有 ETW 的 EtwEventTableModel 和内核回调监控的模型／代理实现，保留既有参数、工具条、列宽、筛选、菜单、详情与完整导出入口。

事件表从 QTableWidget 迁到 WinAPIEventTableModel＋WinAPIEventFilterModel，只为可见单元格取值与绘制，不再为每条记录创建六个 item、永久 QModelIndex 与过滤字段副本。普通采集按最多2048条批量追加，旧行一次批量移除，固定行高且不自动换行；完整详情仍可查看和导出。普通追加与筛选不 reset 模型，排序、选择和共享表格操作继续使用原生模型身份。

## 回跳处理

存在两条需要协调的前端路径：Qt 在当前选中行被淘汰／筛掉时会自动定位到替代行；表格的异步筛选、行高或布局在本批追加结束后还能改变滚动范围。仅在追加函数返回前 scrollToBottom 不能保证随后仍然贴底。

勾选“保持贴底”时关闭 Qt 当前项自动定位，并在批次结束和滚动范围变化后合并一次零延时贴底。执行时重新校验勾选、可见性与右键菜单屏障；取消勾选会使排队的旧贴底失效，恢复原生键盘导航。普通浏览在旧行移除后按事件身份、像素偏移和横向位置恢复；切页返回和异步筛选不能借旧锚点把贴底视口拉回去。菜单打开期间继续接受规范记录，显示提交延后，不为菜单重建整表。

## 保留与筛选

保留最近最多1,000,000条事件，文本估算预算默认约512 MiB，可在“事件保留与归档”手动调整。估算包括行文本、搜索文本和基本记录开销，不是整个进程的RSS硬上限；代理索引、临时筛选、导出快照、待显示队列及分配器另占内存。旧的24,000条待显示队列仍有独立丢失计数。已移出的记录不在表格导出范围内；后续版本为新会话增加独立JSONL原始包归档，保存在应用本地数据目录，可通过页面打开。

完整筛选按2048条／4ms切片捕获不可变字符串值，由共享 AsyncOperation 后台匹配，再以最多512条／4ms切片更新 AcceptedRole。代理只按变化范围处理可见性，不反复创建单元格或同步重扫全部字符串。新到事件直接按最新条件接受，旧结果按筛选代次和源ordinal拒绝，已淘汰行和清空前结果不能误套到新行。隐藏页面暂停筛选显示提交，菜单屏障保持原有行为。
