下一层任务见[施工清单A1／A9](ActionAnalyze施工任务与契约落点.md)。用户新增的[环境实验行动方案](ActionAnalyze反反虚拟机与环境实验行动方案.md)以新sample冻结profile和实际接口覆盖，原始基线与实验所见分别保存；只为各采样保留可核验证据，不借此提前实现跨采样自动比较、热重载或外部回滚。

## 1. 已确认的产品层级

用户明确：断点、采集结果等统一包含在一个“分析项目”里，一个项目可以包含多次采样；多次采样的横向比较暂列待做。项目成为长期工作单位，解决跨运行会话复用断点、配置和调查资料的问题。

```text
分析项目
├─ 项目配置：调查起点说明、采集方案、断点定义、规则与调查预设
├─ 配置修订：已保存版本与当前草稿
├─ 采样 1：实际配置快照、环境、原始事件、行为、传播关系、停点与证据
├─ 采样 2：独立的实际配置快照、环境、结果与证据
└─ 后续采样……
```

“分析项目”“一次采样”“运行会话”分别承担持久资料、一次采集事实、当前控制所有权，不能只给既有 session 换名称。

| 对象 | 所有内容 | 生命周期 |
| --- | --- | --- |
| 分析项目 | 稳定 projectId、名称、配置修订、断点定义、采样目录及资料引用 | 保存后跨程序启动存在 |
| 一次采样 | 稳定 sampleId、所属项目、配置与环境快照、事件／行为／关系、调查及证据、完整性与结束状态 | 新采样创建独立记录；结束后可离线查看 |
| 运行会话 | controller/session/epoch、真实进程线程、驱动 file、Agent 租约、停止与恢复责任 | 由当前存活的本端控制器及真实后端持有 |

一个项目包含多次采样不表示首版支持多次并行采集，或允许绕过驱动单例和来源冲突。先支持在同项目中创建、运行、结束和重新打开不同采样；并发执行能力另按后端验证。

## 2. 项目配置与每次采样的实际配置

项目保存可复用的采集方案、断点与规则选择、调查预设及适用范围。编辑形成项目草稿；保存项目不自动把修改发布到运行目标。

开始新采样时，冻结实际项目配置／断点修订、规则包及hash、来源、预算、调查预设、失联策略，以及显式选择的R3原生／普通R0后端。按[双后端设计](ActionAnalyze双后端独立全流程设计.md)保存所选／实际后端及能力快照；R3不以驱动在线作为前置，R3不调试驱动。绑定真实对象并检查所选后端和必需来源，完成准入后才报告Ready。

运行中允许的目标／断点修改仍走显式提交、生效 ACK 和回读，写入本次采样的配置变更记录，保留 desired/effective 修订及时间。旧事件、停点与证据继续引用当时实际生效的配置。

“应用到本次采样”和“保存为项目配置”是两个明确动作：只调本次不会无提示改写下次默认配置；保存到项目也不会反向重标历史采样。首版行为规则包随采样冻结，不提供活采样规则热替换入口；对已提交输入可新建独立analysisRun重算，不能覆盖原判据或触发原控制动作。断点显式apply与规则包替换分别处理。

## 3. 断点跨会话复用

项目保存断点的稳定定义身份、定位条件、触发阶段、谓词、作用范围、动作和启用状态；每次采样单独记录解析及武装结果。

| 层次 | 保存内容 | 新采样行为 |
| --- | --- | --- |
| 项目断点定义 | breakpointDefinitionId、定义修订、定位与条件、动作 | 从项目继承并重新校验 |
| 本次断点绑定 | 本次进程／线程／映射身份、实际地址、后端及配置修订、武装／失败结果 | 为本次目标重新生成；不能继承旧运行句柄 |
| 命中记录与停点 | sampleId、定义与绑定引用、实际现场、stopId、处置及恢复结果 | 留在原采样中作为历史证据 |

API／行为条件按其语义重新解析。首版定位建议明确为精确API＋阶段、精确模块身份＋RVA／匹配PDB符号、本采样region/contentVersion＋offset或强实例绝对地址，详见[开工总表§6](ActionAnalyze完整开工审查与实施总表.md#6-断点定位与动作计划)。实际后端能力逐项校验；ASLR后不直接复用旧VA，模块不匹配或定位歧义时显示待绑定／不支持。裸PID、TID、绝对地址以及旧动态载荷区域仅属于相应对象实例，若没有可靠重绑定依据，不自动用于新目标。

这样跨会话保留的是用户的断点意图及配置，真实断点按新实例重新建立。历史 stopId、挂起计数、异常令牌和恢复所有权始终留在原运行会话；项目文件不能授予新进程继续旧目标的权限。

## 4. 每次采样独立保存的结果

一次采样关联以下资料，列表、传播图、字段详情、调查文件及后续导出均保留所属 sampleId：

- 采集起止时间、结束原因、目标实例、OS／架构／保护条件、实际后端与组件／协议身份。
- 初始配置快照、运行期已接纳配置、逐来源实际生效版本、断点解析／武装结果及覆盖变化。
- 实际收到的原始事件、字段与丢失账目、聚合行为及规则依据、传播关系与归因强度。
- 断点命中、用户／内部停止组、实际控制结果、结束时恢复状态及未决责任诊断。
- 寄存器／栈、内存区域及版本、转储、实际保留的网络资料、调查结果和关联证据。

未知、部分失败、未采集与真实空结果继续区分。事后无法补造未采流量、未观察到的写入或已丢失的现场。采样未正常结束时，保留其部分资料及异常状态，不把项目打开成功解释为采样完整。

原始证据和已保存配置快照不被后续采样覆盖。项目索引及当前显示窗口不复制每次采样全部内容，历史按采样分页读取；证据身份至少能解析到项目、采样、对象／区域版本及原事件。历史停点文档是离线资料，显示它不触发实际恢复或重新武装。

## 5. 用户工作流

1. 新建或打开分析项目，查看采样列表与项目配置；只打开资料不启动驱动、Agent 或目标。
2. 编辑、校验并保存断点和采集方案，显式创建新采样。
3. 新采样取得稳定 ID 和配置快照；绑定当前目标并检查能力，之后执行采集与准入。
4. 实时查看当前采样，命中后调查、受控推进或继续；所有结果落入该采样。
5. 结束采集后处理真实停止／恢复责任和归档状态，逐项保留结果。
6. 稍后重新打开项目，查看既有采样，沿用项目断点和配置创建下一次采样。

历史查看对象与正在运行的控制对象分别显示。切到旧采样不会悄悄改变调试条的目标，也不凭当前表格选中项向另一次采样发控制；实时控制请求仍绑定真实运行会话及停点。项目关闭不等于已经释放控制责任，继续执行原有明确的会话收尾策略。

用户界面新增的是项目与采样的组织关系；既定瀑布流、中央 Tab、传播图、调试条和共享详情继续沿用。真实入口和控件布局在 UI 实施时按共享规范设计，本轮不创建页面。

工具栏入口见[原图清单与当前 12 项范围](ActionAnalyze工具栏逐项功能核对.md)。取消／重新启用跟踪保留项目断点定义与原有证据，在当前真实对象上重新绑定，缺口保留在本次采样；逐过程、逐语句、跳出的临时执行责任属于运行会话，不保存成下次默认武装。回滚与热重载按用户决定延期，不新增对应按钮、基线或任务存储；下一次采样由用户明确创建，不承诺环境自动还原。横向比较仍为待做。

## 6. CLI 与三端边界

CLI 也以项目组织资料：创建／打开项目、读取和保存配置、列出／读取采样、在项目内开始新采样，再使用同一个存活控制器执行运行期命令。有限 capture 同样归属明确项目，并创建一次独立采样，不把散落输出目录作为唯一业务身份。

持久请求／响应与归档带 projectId、sampleId 和配置修订；驱动／Agent 的 session／stop 授权保持原契约，由本端保存映射，不为项目名称额外复制一份驱动协议。对历史采样的只读请求不需要存活目标；控制请求仍须完整运行会话与 stop 前提。

Qt、Win32、CLI 分别实现本端项目与运行会话管理。项目资料可以按共同文档格式设计，但不引入公共业务 runtime、共享宿主或跨端活停点接管。具体目录、记录格式、打包扩展名、索引、提交恢复和跨端兼容的实施建议见[项目存储格式与恢复设计](ActionAnalyze项目存储格式与恢复设计.md)。该契约仍待实现及黄金文件验证，不宣称已有格式兼容。

## 7. 横向比较：明确待做

多次采样之间的行为、传播图、内存、网络及断点命中差异比较统一列为后续工作，本阶段不实现比较算法或比较页面。

首版保留稳定项目／采样身份、原始证据、规则与断点定义版本、实际目标和环境、采集范围、完整性及缺口。未来据此判断两次采样是否可比；不能仅按标题、相同 PID／VA 或“这次没有显示某行为”推断差异。预留数据依据不等于比较能力已经交付。

## 8. 实施与验收要求

本节均为后续验证，尚未执行：

- 同项目完成两次独立采样，结果／证据不会覆盖，分别可重新打开并追溯实际配置。
- 重启控制端后项目断点定义仍在，新采样重新绑定；ASLR、PID／TID 复用和模块不匹配不误用旧目标。
- 运行期改断点时，本次实际修订、项目草稿／保存修订和历史采样互不静默覆盖。
- 切换历史／实时采样、关闭项目或 CLI EOF 时，运行控制身份与恢复责任正确。
- 部分采样、归档失败、证据缺失和未正常结束分别显示；存储中断后不把不完整采样标成功。
- 大量历史采样不全部载入内存，当前采集与 R0 恢复不等待历史搜索、项目索引或慢磁盘。

后续模块按职责落在各端 `ActionAnalyze/` 内，建议区分项目文档／配置、采样索引和既有归档，运行控制仍由 Session／ControlCoordinator／StopLedger 持有。只在实际需要时建立 `.h/.cpp`，不为项目概念先造通用工作区框架。本轮仅更新设计文档与共享记忆，不改变产品、语言包、工程或既有测试产物。
