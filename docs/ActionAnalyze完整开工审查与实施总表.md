## 1. 距离开工还差什么

可以开始数据格式、解析器、归档、历史查询及长程 CLI 的独立工作；完整追踪／自动控制接入仍有四类前置工作：

1. **把设计变成机器可校验契约。** 字段目录、方法目录、JSON Schema、二进制布局、规则 AST、项目读写黄金文件，连同正反例一并冻结。此前“schema、过滤、文件格式实现时再定”不能继续作为实施依据。
2. **分别实现并实测两套真实后端。** 按后续[双后端要求](ActionAnalyze双后端独立全流程设计.md)，R3独立完成受支持用户态全流程，不等待R0修复；R0的单primary、恢复丢账、原保护／临时挂起、watchdog／cleanup及Qt消费门禁在R0产品化前修复。两后端各验线程门控、执行前插桩及失联恢复，不能用文档或另一后端结果代替。
3. **补齐来源、规则和依赖矩阵。** 每个操作入口、每个规则必需字段、每端真实能力和不支持原因逐项登记；完整目录收集、许可闭环和可运行规则集合分别验收。
4. **明确两项处置体验并建立实测基线。** 结束调试的目标处置与步进锁依赖的默认行为见§13；CPU、内存、停顿、归档吞吐及 UI 目标先有可运行基线，再冻结公开阈值。

“设计可分工”“代码可构建”“来源与控制可开通”“完整产品可交付”是四个不同门槛。当前可以规划并启动前两者的适用部分，不能宣称距离交付只差页面。

首批工单、独立依赖、同步下断切片及 E01–E16 环境探测交付顺序见开工基线。停点快照首份正反例草案随 A0 单独发布。[工程开工基线](ActionAnalyze工程开工基线.md) · [已发布的 A0 基础契约](../schemas/action_analyze/base-contract-v1.md)

## 5. 运行状态与动作仲裁

会话至少独立保存 `controller=alive/closing/unresolved/closed`、`capture=preparing/running/stopping/stopped/failed`、`control=running/held/stepping/rearming/recovering/unknown`、`archive=healthy/lagging/failed/sealing/sealed/partial`。界面状态由这些事实组合，不能用一个paused或绿色Ready覆盖。

新采样：保存配置快照→能力与冲突检查→准备归档及控制预留→绑定根→部署必要来源→逐目标实际配置／覆盖／探针确认→Ready。失败保留partial采样、错误与自有资源；未Ready不自动放行受支持迁移闸门。不可提供原操作前同步闸门的来源只登记已发生行为。

本端 `ControlCoordinator` 唯一提交变更；每目标／页面事务串行、多个无依赖只读作业可并行。锁序建议会话注册→对象责任→页面事务；不持锁等待管道、驱动完成、GUI、磁盘或符号。事件生产线程只提交有限事实／意图，不直接调用同步GUI或跨目标递归锁。

暂停、继续、步进、取消跟踪、关闭竞争时先冻结请求目标及expected修订；只有一个操作取得提交权。关闭拒绝新准入；已提交控制查询真实结果后清理。暂停用户责任与内部屏障分别计数，完成调查／临时推进不解除用户保持。取消提交后不假称“操作没发生”。

| 竞争 | 确定的建议顺序 |
| --- | --- |
| 调查与continue/step | 调查先获stop现场只读lease时，必要原始捕获完成前返回busy／等待票据；不等符号下载。continue先提交则拒绝旧stop调查或显式改live快照 |
| 退订与现有hold | GUI每次选择keep/release-owned，机器参数必填；先处理精确责任再退原因引用，其它追踪原因仍在则不卸载 |
| 两次continue | 同ID查原结果，不同ID对同已消费stop报冲突；不多执行Resume |
| 保护／映射外部变化与恢复 | 校验mapping/content/protection代次与预期当前值；不把旧保护盲写进新映射，冲突保留recovery-required |
| 退出与迟到ACK | 保留句柄／原生身份确认退出再退休；旧ACK仅归原epoch，不作用新实例 |

显示冻结、来源采集暂停、用户停止组、内部探针屏障四者分别命名和查询；不能把旧WinAPI移除Hook的“暂停”接到线程停止按钮。

本控制EXE、精确peer、归档／恢复所需对象不加入自身停止集合；不能仅按exe名字排除。若传播观察涉及自有控制对象，记录事实与明确不可控原因，不删除证据或自动循环部署。

### 5.1 起点、部署与权限

启动EXE用精确路径／PE身份、参数数组、工作目录、环境白名单和当前token；不将任意字符串拼成shell命令。脚本显式选择解释器路径／版本与脚本hash，参数同样数组化；PowerShell产生的外部修改仍不承诺回滚。启动可受控创建后绑定真实创建身份，原CREATE_SUSPENDED责任单列，loader初始化与Agent部署依赖须实测，不能保证先注入再发生全部业务。启动器失败与目标已创建但部署失败分别报告，后者不默认杀进程。

附着／多根／指定线程每项先绑定创建身份与所有者，明确从当前时刻开始、已有行为不可补造；运行中新增走相同Ready事务。目标定义保存选择意图，sample保存实际实例。多根同进程合并原因引用与资源，结束一根不撤其余根仍需的来源。会话暂离可只读打开旧采样，不能自动附着旧PID。

Agent和broker部署冻结PE machine、文件版本／hash、协议与声明hash；控制端点核验真实peer、创建时间、session/epoch及挑战，句柄继承只白名单。现有broker父子校验不直接删掉来接收任意传播PID，应由授权的admission事务提供独立目标依据。文件hash和心跳不证明受分析进程内Agent未篡改，信任边界在结果中保留。

query不自动提权／加载驱动；枚举、注入、上下文、内存读取、ETW/TI、DELETE_TCB各报实际权限。权限改变／UAC重启／驱动服务重启不透明接管旧会话，先正常收尾再新控制器／epoch；无法回读的结果保持unknown，不降成R3。PPL/AppContainer/跨用户／Session等组合先按能力unknown或unsupported，只有实测后纳入公开矩阵。

## 6. 断点定位与动作计划

项目定义和本次binding分别存储；binding有 pending/resolved/armed/partial/stale/failed/disabled 状态及后端真实机制。定义可包含：

- 精确API身份＋阶段＋有界谓词，entry不得依赖return值。
- 精确模块身份＋RVA；符号必须匹配PDB GUID/Age并解析唯一位置；名称歧义返回待绑定。
- 当前采样的regionId/contentVersion＋offset或当前强实例绝对地址；没有跨采样定位依据时明确不可复用。
- 指定停止现场的栈／返回槽位watch，绑定frameInstance／stackRegionVersion／有效时段，默认关闭，使用实际剩余DR能力；帧退休／栈切换即退役，不跨采样继承裸地址。
- 语义命中后请求暂停：保存触发证据和实际暂停时间，不能叫“早先API调用前已拦住”。

动作计划按 `record → request-hold → capture-volatile → queue-analysis → notify` 描述依赖；不是每规则默认都执行全部动作。首版只开放明确白名单：记录／标注、请求暂停、选定预设调查、保存受限区域证据、提示。不给规则任意PowerShell、shell、网络请求、自动终止或外部回滚能力。昂贵调查合并同stop/同范围请求，保留每个触发引用；冷却只抑制重复动作，不抹掉命中统计。

同步谓词命中由受支持后端保留原调用／异常事实并停驻，语义引擎异步结果只申请后续控制。若多个规则同时命中，同一停点一次建立责任，记录多条原因；规则优先级不覆盖用户已有hold。条件false与unknown分别处理；未知默认不执行具有副作用的肯定命中动作，必要准入条件unknown则保持闸门。

## 7. 收尾与故障建议

| 场景 | 首版建议行为 | 验收边界 |
| --- | --- | --- |
| 关闭工作台Tab／切历史采样 | 仅隐藏或切投影，活会话继续，在任务中心可见 | 不丢唯一控制所有者 |
| 点击终止调试 | 默认建议停新准入／采集，释放本会话自有控制责任，保留样本运行；显示逐项恢复与归档状态 | 产品默认待用户确认；不等于杀样本 |
| 停采但保留暂停 | 允许明确 `stopPolicy=keep-owned`，本控制器继续存活且可达recover | 不允许唯一所有者退出后假称keep成功 |
| 正常迁移／步进超时 | 保留真实闸门／停点，停止自动推进并报告依赖／预算原因 | 不自动放全组、不自动终止目标 |
| stdin EOF／输出失联 | 建议open时显式选择release-owned orderly-close；机器端不能临时弹窗 | 必要后端恢复不可实现时，准入前拒绝无人值守停驻计划 |
| 控制EXE被强杀 | 按所选后端真实owner-death能力报告；R3的NX在途Explorer负控已失败，R0 cleanup仍待实测 | 正常close不代替任意死亡恢复；IPC Job杀自有子进程不作为生产恢复方案 |
| 满盘／归档失败 | 拒绝新采集／新武装，保留控制／恢复，按既定结束策略收尾并partial | 不为落日志而阻塞恢复；不自动删旧证据 |
| 恢复失败 | 未决责任保留、暂停新准入，仍有可达查询／精确重试 | 不清账、不报告clean，不能无限无人可达地等待 |
| 系统休眠／恢复 | 标中断、重校时钟、回读对象／探针／覆盖，失效不继续旧推进 | 电源回调不执行GUI／慢I/O；R0必须独立证明 |

Ctrl-C建议取消当前前台可取消job，Ctrl-Break提交orderly-close，handler仅signal；重复信号合并，不自动升级强杀／放行。stdout阻塞先停普通订阅并记输出gap；broken pipe直接进入失联策略，持续背压建议10秒告警、30秒触发预定关闭（初始阈值非硬时限）。输入仍畅通时允许查询／恢复，实际ACK交付仍可能失败。

生命周期失联与普通等待超时不是一套处置。计划必须声明各自策略和后端可实现性。规则、项目文件和历史stop记录不能授权新进程接管旧owner的责任。

## 8. 调查、内存证据与专业工具

默认“一键调查”建议为有限快照预设：所选已关联对象／所选stopGroup内的寄存器、至多64帧的可用用户栈、模块和映射目录、命中区域字节及邻接映射描述、已有句柄／文件／网络关联摘要。每进程默认原始字节预算16 MiB、整作业64 MiB／30秒，2个采集工作者；上限是初始提案，不承诺时延。未成功停止的对象只做明确标为live的查询。

完整进程minidump／full dump、全地址空间扫描、YARA、反编译、全盘／注册表搜索单列预设并显式启用；不能默认由“一键”启动。按先保存易变现场、后符号／内容分析执行。每子任务保存输入、来源、采样时段、实际后端、输出格式／hash、partial和原始错误。

原始区域dump使用 `.bin`＋metadata，内存洞在sidecar区段表标 absent，不补零冒充读取；标准minidump使用真实`.dmp`与流类型，不能给原始字节换后缀。候选shellcode只叫候选，保留边界依据／入口与实际保存区间。

栈分析复用既有DbgHelp锁和符号缓存，按精确模块PE/PDB核验；符号网络下载独立队列、取消与预算，不占控制路径。无符号仍保留原地址；扫描猜栈与真实unwind分层。反汇编记录解码器版本／架构／字节来源，未知指令不猜长度；步过／跳出必须有可靠边界，不能用显示反汇编行替代真实控制机制。

专业工具导航携带sample/object/regionVersion/evidence引用。历史证据优先离线打开；切到现场须重新确认同一强实例。已有调试器忙时不抢attach，不创建第二个Wait/Continue消费者。尚未从页面抽离的能力列adapter待办；构建隐藏控件不算后台化。

当前源码有具体前置重构：`ProcessDock/ThreadStackWindow.cpp`捕获自行R3挂起／恢复且部分helper忽略恢复错误；`KswordCLI/R3ThreadStack.cpp`仅native AMD64、WOW64拒绝；`MemoryDock/MemoryDock.RegionDump.cpp`虽有分块／提交仍是页面成员。抽取无UI入口时先接新stop快照／R0临时责任，保留旧页面流程回归，不能直接给旧函数套后台job。

网络资料首版默认仅规范连接／DNS／HTTP元数据及已存在来源实际捕获的字段，不凭长度生成正文。原始包捕获为显式可选来源，若接入则PCAPNG加接口／方向／时钟／snaplen和丢包说明归本sample，禁止从全机包仅凭弱PID归属自动称进程流量；TCP重组、TLS明文及解密不作为已有能力。无包来源时按钮仍只能显示“未采集正文”。

栈破坏单列`stack-integrity`调查预设及规则类别，细节见[专项设计](ActionAnalyze栈破坏与控制流劫持发现设计.md)。主链同时包含同进程的输入／写入→栈控制槽位→实际／候选转移→后续影响，不要求发生远程写或生成新RX页。栈空间耗尽、可信保护触发、疑似pivot和已观测控制流劫持分别表述；仅数据攻击延期不排除返回地址等控制数据破坏。本期不承诺任意成品EXE的全部越界写前检测／全部ROP识别。

## 10. 预算、阈值与可观察性

数值是首个可运行版本的可调初值，用于暴露边界；尚不构成性能承诺。原文“实测再确定”继续适用于公开SLO，不能以新增默认值当已测。

| 资源 | 初值建议 | 达限行为 |
| --- | --- | --- |
| 本端数据工作集 | 逻辑预算256 MiB：接收48、规范／对象48、规则64、归档32、UI48、调查摘要16；控制预留另8 MiB | 每模块同时按条数／字节／年龄；RSS含Qt／分配器等另测，不称硬进程上限 |
| 活目标／关联线程 | 32进程、4096关联线程目录 | 超限停止自动扩展，原有跟踪与责任保留；目录容量不是可同时停止4096线程 |
| R0停止容量 | capability报告实际预分配槽数，不预设已支持32进程 | 每新探针先预约，满拒准入；既有恢复不受遥测配额挤占 |
| 规则 | 编译准备8 MiB、总状态64 MiB、单规则4 MiB；数量按能力／依赖实际编译，细限见筛选契约 | 报budget／incomplete，不静默假称未命中；同时受全局内存准入约束 |
| UI | 可见原始窗口50000行／32 MiB、图2000节点／8000边、瀑布2048密度桶 | 窗口移出／图聚合／历史分页，非采集丢失 |
| 投影提交 | 三视图共享每次4ms目标、最多每50ms合并一次，输入操作优先 | 分批延期、合并；测耗时与输入延迟，不称120Hz |
| 归档／空间 | 默认sample软配额10 GiB、project软配额100 GiB；可用空间低于max(1 GiB,卷2%)进入告警／停止新采集策略 | 不自动删除项目／证据，控制恢复保留；预算含blob、索引／WAL、staging／trash及包partial |
| 原生等待 | 准入10秒告警、30秒停止自动等待；每步1秒／10000指令；调查30秒 | 普通超时保留真实hold；这些不是底层调用硬超时保证 |
| 作业 | 2个采集、2个解析／索引工作者；单对象同类在途合并 | 排队有界、取消合作收尾；控制线程独立 |

采样快照保存最终解析后的每项预算，界面显示实际用量／最旧积压／丢失层次。高内存或慢盘不会触发静默减少必要传播证据；可选内容截断另报，必需来源无法维持则暂停新准入／停止采集并partial。

256 MiB为所有数据模块的共同逻辑预算，上表分项是默认分配，某专项的独立最大值不额外增加总额。接收含乱序窗口32 MiB／65536事件；规则编译8 MiB与状态共同从规则64 MiB准入；归档32 MiB含SQLite page cache／reader、解压与写缓冲；UI48 MiB含输出投影队列。CLI累计请求identity账本最多32 MiB记入控制元数据预算，独立于不可挤占的8 MiB恢复预留，capabilities同时列出这两项与数据预算，不能把256 MiB当总RSS承诺。调查64 MiB是作业累计输出字节而非必须常驻内存，分块流式写入；blob4 MiB块、pack／hash缓冲、解析临时值及索引WAL都计入相应内存／磁盘实际用量。

指标包括原始事件率、源丢失／suppression、规范化／语义／归档水位、队列峰值／最旧年龄、每事件唯一分配字节、规则状态与退出后回落、Agent退役代码增长、控制实际停止／恢复时延、UI提交与输入响应。分别测P50/P95/P99及最大值与测量时钟，不把ACK耗时当所有线程停住耗时。

基线场景：无规则／少量／全部适用、宽范围、多根／循环传播、文本密集、慢读stdout／stderr、慢盘／满盘、目标退出、隐藏页、连续筛选／滚动／图选中、休眠恢复及1小时稳定采样。独立三端报告，停止／恢复不因诊断输出满而阻塞。运行试验先自有良性目标，R0等环境。

## 13. 真正还需要用户决定的默认行为

其余工程细节使用本文及专项文档的具体建议，不逐个把字段名／扩展名交给用户选择。下面两项影响目标运行，尚无用户明确默认：

1. **终止调试：建议默认“停止追踪并释放自有暂停，保留目标运行”。** 可另选“停采并保持本控制器存活”，不能默认杀样本。恢复失败保留控制器与诊断，不宣称已结束。是否另提供明确终止所选进程动作，可在产品实施时按既有入口复用，不扩成全组自动清除。
2. **步进锁依赖：建议默认“只放选定线程，超时回到可控停点并报告依赖，需用户显式许可才扩大放行”。** 并非已保证任何线程都能立即停回；后端不能可靠重新截获时拒绝开始。允许依赖线程前进的模式会降低组冻结保证，必须单独授权并记录。

这些建议在计划schema中为显式参数；用户未选定时，不据此启动有停驻副作用的无人值守会话。纯格式／查询／归档／R3解析与CLI假后端工作可继续，不把待决定项扩大成全部停工。

性能阈值、R0 支持范围与完整线程门控待实验。A0–A3、来源审查及 R3 验证可以独立推进。普通 R0 已指定验收来宾，实测结果待登记。[验收范围与运行环境](ActionAnalyze工程开工基线.md#验收范围与运行环境)
