# ActionAnalyze 工具栏逐项功能核对

[缺口G05–G08／G14](ActionAnalyze规划缺口复查与补齐任务.md)是本表12项动作的追加判据：异常继续与页保护恢复、TF／DR／临时断点仲裁、通用step的返回边界及后台分析器取消分别验证。不增加工具栏项，不用固定叶函数夹具替代这些产品条件。

日期：2026-11-24。状态：原图 14 项已登记；按用户最新决定，回滚外部操作及热重载延期且不显示按钮，当前工具栏范围为其余 12 项。网络改为进程级断连。下文为产品契约，尚未实现整套产品或运行验收。

## 1. 用户要求与当前缺口

用户明确：“回滚样本操作、热重载……那张 PPT 右上角的工具栏每一个都要具体实现”。此前主规划及产品全景把该处概括为调试条，主要展开暂停、单步、继续和一键调查，没有逐项落实 PPT 工具栏；回滚样本操作与热重载被遗漏。

用户随后补发原图，右上主行有 13 个图标，下方另有“全局继续”，合计 14 项。链条及三个箭头分别是重新启用跟踪、逐过程、逐语句、跳出。用户最新调整优先于原图：回滚外部操作与样本热重载暂不实现，也不添加占位或禁用按钮；例如 PowerShell 修改组策略等副作用并无通用可靠撤销方案。网络改为断开进程网络连接，避免影响 AI 经 SSH 连接调试环境。本记录保留原项编号用于追溯。

## 3. 每个工具项必须补齐的契约

按真实功能分别记录：原图位置与名称 → 用户任务 → 所作用的项目／采样／运行对象 → 参数与状态前提 → 显式执行 → R0／R3／采集／归档责任 → 实际结果与部分失败 → 取消及失败恢复 → 验收证据。

用户后续要求[两套正式独立后端](ActionAnalyze双后端独立全流程设计.md)：R3用户态全流程不等待R0，R3不调试驱动。工具项由采样已选后端执行，逐项核对能力／身份／事务／恢复，按钮不暗中换后端。快捷键按运行时控制规范注册，各端业务独立，CLI复用本端类型化入口，不新建公共宿主。

### 3.1 重新启用跟踪

取消跟踪不删除项目断点定义与既有证据。重新启用时使用请求时冻结的真实对象，重新检查创建身份、映射和内容版本；旧 PID／TID／VA 已失效则报告失效，不静默绑定同名新对象。项目断点定义按本次目标重新解析、武装，复用断点意图，不复用旧 binding 或 stopId。

状态依次为 Requested／Preparing／Ready 或 Partial／Failed，按实际生效范围显示。只有必要来源及探针回读就绪才报告 Ready；重入已有跟踪的对象不重复取得资源或挂起。取消到重启之间记录监控缺口，历史查看不触发重新启用，不默认解除当前用户停点。

### 3.2 逐过程、逐语句与跳出

三个动作分别对应步过、步入和返回当前调用帧。默认以当前汇编指令／调用为可验证执行粒度；源码行模式只有取得匹配符号和行映射后才能声明，具体粒度必须显示。不能用行为列表的下一条日志或时间线跳转代替目标真实推进。

请求冻结projectId／sampleId／session／epoch／stopId、所选后端、线程实例和起始现场。步进前检查该后端能否真实继续及重新截获；能力不足明确失败，不静默切到另一后端。TF／临时断点按实际方案记责，不覆盖用户断点，不把临时断点存为项目定义。

逐过程在普通指令上前进一步，调用指令则等待对应返回边界；跳出需要可靠的当前帧及返回信息，递归、尾调用、栈展开不确定性分别处理。同返回地址被其它线程或调用帧到达不能充当完成证据。逐语句进入调用目标，停止位置必须来自真实现场。

期间发生用户断点、异常、线程／进程退出或预算到限时，以真实原因停止并回读，不强行报告步骤完成。超时／取消不等于目标已停止；仍在运行或结果未知时明确显示，另走受控停止和临时资源清理。页面 NX 屏障、重设防、其它自有保持及外部挂起计数继续分别记账；不能因步进就释放全部对象或关闭必要监视。

## 4. 进程网络断连

当前动作只处理明确选中的进程实例及请求时冻结的连接，不扩大到整机、SSH 服务或其它关联进程。逐项保留 PID／创建时间、协议及端点身份，执行前再次核验，返回成功、已结束、失败或不支持；连接表观察与实际执行之间存在竞态，不能只靠旧 PID 或列表行号。

“断开已有连接”和“持续阻止新连接”分别是不同能力。先验证 R3 可实现的已有连接断开；不把它声明成持续网络隔离，也不宣称 UDP／IPv6 与 IPv4 TCP 天然拥有相同删除接口。样本可能立即重连，结果中记录实际断开和后续新连接。持续阻断若后续纳入，另设计按进程的生命周期和撤销责任。

用户经 SSH 调试的工作流必须保持非目标连接可用；不通过清空全机连接、关闭网卡或防火墙全局变更来实现本按钮。若实际选择本身包含管理连接所有者，界面应明确列出实际影响，不能笼统保证任何选择都不会影响 SSH。重新建立连接由应用负责，按钮不伪装为恢复原 TCP 会话。

本机 R3 自有回环 TCP 实验返回 `SetTcpEntry=317`，当前进程未提权；12 项权限拒绝路径断言通过，目标及非目标连接仍可通信。整体记录为 BLOCKED_PERMISSION，成功断连、IPv6／UDP 及真实 SSH 均未验证；不为完成测试自动提权。

## 5. 回滚与热重载延期

用户明确暂不实现这两项且不添加按钮，原施工建议停止推进；本阶段不新增基线备份、系统副作用撤销、自动收尾派生进程或样本自动重跑框架，也不增加对应 CLI 方法。PowerShell、组策略及间接系统修改进一步说明当前无法承诺通用恢复。

调试器须归还自身持有的挂起、TF／临时断点及页保护。实际动作回执按本机 R3 与指定来宾 R0 分别验收。[验收范围与运行环境](ActionAnalyze工程开工基线.md#验收范围与运行环境)

## 6. 与分析项目及采样的关系

[分析项目](ActionAnalyze分析项目与多次采样设计.md)统一保存断点定义、配置和多次采样。用户可手动开始下一次采样并重新绑定断点；这不承诺环境已回滚，也不恢复旧停点。多次采样横向比较继续列为待做，当前没有热重载任务或回滚计划的持久化要求。
