## 验收范围与运行环境

完成全范围验收后才能最终关闭。分批实施、合入和验证可独立推进。未通过或阻塞的验收项保留在总账中。R3 验证在本机执行。普通 R0 的驱动加载和运行仅限 `E:\VMs\Windows11-24H2`，确需变更配置时先登记范围和恢复方式，保留版本、构建和运行证据。历史报告按各次授权与实测范围引用。

普通 R0 运行验收受来宾 OS 版本阻塞。指定来宾的 Windows 11 24H2 报告 OS 版本 `26100.9711`。驱动入口以 `RtlGetVersion` 读出的 OS build 为准，要求 `26300`。源码中出现的 `26100.9711` 是映像版本。即使 SYS 就绪，当前来宾仍无法通过 OS build 检查。[驱动版本检查](../KswordARKDriver/src/features/kernel_noattach/kernel_noattach_hook.c)

环境记录显示来宾已有 `TESTSIGNING`，KSwordARK 驱动服务未注册，驱动未加载。现有产物的来源与该验证批次不匹配，配套签名候选产物未暂存。普通 R0 的 29 项外部判据仍未运行。

## 2. 同步下断第一条实现切片

| 环节 | 工程边界与交付物 |
| --- | --- |
| 准备 | 本端 `ControlCoordinator` 建立 `BoundStopRoute`。所选后端先绑定实际进程、线程身份、站点、配置版本、现场槽与释放责任，再发布可用绑定。没有路由或超过可预留规模时拒绝同步绑定 |
| 命中 | 既有 Agent 内的受支持入口执行有界判定，保存有限 `HitRecord`，命中线程直接到登记停点。最小切片用一个确定、可独立计数的调用边界；入口和返回两种情况分别编入夹具。Agent 不需要发出遥测确认才能停住 |
| 接管 | R3 外部原生事件循环拥有事件，校验真实站点、进程、线程及现场槽后入账。手动 `control.pause` 也进入同一协调者。Agent 路由只引用控制器已绑定范围。`origin-held` 和组结果分别记录 |
| 分组 | 记录请求集合、实际附带暂停和内部探针屏障。`held-complete` 只在冻结集合中的存活成员逐项确认后成立，真实已退出成员保留 `exited`。全组已退出报告 `ended`，部分无法确认报告 `held-partial`。R3 原生事件期间整个命中进程暂停，跨进程时记录实际偏差 |
| 继续 | 由外部所有者按原责任释放。已提交无法确认时先查原请求。命中现场槽损坏时仍须处理真实原生事件，禁止因缺附加字段把停点从账本移除。恢复结果与真实再次执行分别取证 |
| 发布 | 逐端／逐后端启用能力，包含允许的停止范围、可持容量和实测故障行为。直接停点路线已定，R0 当前缺该路由实证，原生调试事件中控制端死亡仍有失败记录 |

首轮验证拆为 `call-enter`、`call-return`、异步动作对照、仅命中线程逻辑范围、会话范围、多进程中一项失败、停止所有者故障。正式发布前量出未命中 Hook 成本、命中线程到原生停点、组完成、继续、区域重设防及目标扰动。冻结的用户集合和完整区域屏障采用独立判据。[同步与性能详细契约](ActionAnalyze同步全局断点与性能复查.md)

## 3. 环境探测工程范围

「反反虚拟机」的首批产品能力是可复核的被动环境探测证据。环境实验按新采样单独记录，先在自有 detector 验证。所有条目均先登记 `入口／阶段 → 原值与类型 → 来源能力 → 证据级别 → 旁路 → 终止条件`。对主动阶段的工程选择采用以下顺序，保留逐入口通过条件。

| 探测面 | 第一批工程产物 | 后续准入或研究退出条件 |
| --- | --- | --- |
| E01 WMI | 方法／对象、成功返回、CIMTYPE／VARIANT 及同名属性负控 | 先完成同步 Get 的类型、所有权及目标独立所见验收。异步／数组单列能力 |
| E02 注册表 | 句柄与视图、成功返回类型／实际长度、查询／枚举区分 | 用自有良性测试值验证原失败与短缓冲行为，存在性实验需要完整开查枚举视图 |
| E05 固件、E07 设备查询 | provider/table 或 IOCTL 身份、两段长度、实际返回、结构验证 | 固件与 WMI 证据一致后再评估限定 profile，未知表、结构与异步路径保持逐项限制 |
| E06 资源规模、E08 网卡 | 按实际 CPU group、卷／盘、adapter 实例保存真实报告值 | 物理容量、拓扑或路由一致性无法保证的接口只公布观察能力 |
| E03 文件设备、E04 进程服务模块、E13 用户环境、E15 网络 | 被动观察入口与对象身份。E15 加本地已知测试端点的证据归属 | E03/E04 的一致枚举可行性单独评审。主机／网络状态保留真实证据，远端判定单列缺口 |
| E09 指令、E10 时钟、E11 等待、E14 反调试 | 静态候选与实际站点观察分开，双线程／多时钟、真实等待结果及诊断扰动 | 局部站点合法性、资源预约、进程外时钟负控独立验证。跨接口透明时序保持研究状态，失败记录适用站点和不可覆盖路径 |
| E12 活动 | 完整 POINT、调用结果、会话和 DPI／计数回绕 | 以自有输入数据验证类型及错误语义，真实用户输入、全机效果留在实验范围之外 |
| E16 多信号 | 关联实际查询与自有预定义分支证据，保存混杂因素和退出原因 | 对照独立证明后分别标 `observed`、`substituted`、`seen`、`path-observed`，证据缺失保留未知 |

RAV0/1、被动字段与规则线索可随 A0/A5 开工。RAV2 先交 profile 校验与冲突报告。RAV3 起始顺序为 WMI、注册表、固件，逐项过 X01–X03。有限站点、计时和其它面由 RAV4 与 X04–X06 独立交付，组合证据及撤销进入 X07。具体接口、任务和原始输出沿用环境专项。[E01–E16、RAV0.1–RAV6.1 与 X01–X07](ActionAnalyze反反虚拟机与环境实验行动方案.md)
