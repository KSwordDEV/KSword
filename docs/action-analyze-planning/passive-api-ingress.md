# ActionAnalyze 被动 WinAPI 归档接线

首批接线是 CLI 活会话中的独立只读来源。输入限于用户明确授权、自有且已存在的本地生产归档 `events.jsonl`。归档生产、部署、采集器生命周期及任何目标控制由外部所有者负责。ActionAnalyze 读取指定文件、记录证据、报告本端状态。Qt 和 Light 按下文顺序接入，产品验收按端登记。 [11 项产品验收清单](../ActionAnalyze产品验收清单.md)

## 当前实现与缺口

| 层 | 已核对的能力 | 接线前提 |
| --- | --- | --- |

## 显式绑定与身份

- 绑定一次冻结项目、配置修订、采样和本端活会话代次。输入授权包含一个明确路径或已授权句柄、归档写入方的会话标识、该归档唯一调用方的 PID 和创建 FILETIME。进程和生产会话身份须由授权方独立提供。通用契约另保留机器／启动身份及其可得性，CLI 将缺项列为未知。[基础身份契约](../../schemas/action_analyze/base-contract-v1.md)
- CLI 首片在 `r3` 控制器的 JSONL `session.open` 中接受 `apiArchive` 对象，其键为 `path`、十进制字符串 `sessionIdentity` 和必须为 `true` 的 `authorized`。外层使用既有的 `projectId`、`title`、`pid`、`creationFileTime` 及可选 `durationMs`，预期修订沿用 `expected.revisionId`。该来源与 `providerId`、`sysmonTargetGuid` 互斥。`path` 指向本地卷目录内一个既有 `.jsonl` 文件，使用只读句柄和卷／文件 ID 固定输入。完成文件资格核对后才以已核验的修订登记项目采样。归档内容核对从第一轮开始，身份或包错误可以在较后行才发现。
- 文件从第 1 行开始读取，打开时可见长度单列，既有积压和跟随期新增文件字节共享同一文件序列。原包时间为来源声明，尾读时间为本端处理时间。不能用读入时间断定历史积压在本次启动后才发生。每行须核对 `readerPid`、外层 `pid`、原包 `pid`、创建时间和原包会话标识。第一条不符即停，并报告已验证前缀。仅比较归档与授权声明的一致性，不从中授予任何目标控制权。
- `ApiMonitorClue` 从原包重算。控制／覆盖包、未命中包保留在证据流中，线索表只投影命中类别。调用角色仍是归档声明，目标实例、实际操作效果、后续执行与因果归属保持未知。对指定本地归档的显式授权声明由调用方负责，归档自身的内容和 CRC 不承担授权凭证职责。 [线索目录及回放结构](../../shared/evidence/ApiMonitorClue.h)

## 交付、预算和损失

原 `sourceSequence` 为从 1 起的连续 JSONL 行号，包含覆盖和控制包。源传输有独立的丢失信号。样本事件 ID 由 `sampleId + eventOrdinal` 生成，Stored 封装序号、段号、源行号及 UI 位置分别计量。重放或重新提交同一绑定时，按 `(sourceId, sourceEpoch, sourceSequence)` 和精确原包做幂等校验。相同键相同包可安全重试，键相同包不同须报告冲突。文件游标推进只代表校验，项目持久水位才代表已提交。在文件仍可读且前缀不变的前提下，允许从已确认边界前重读并至少一次交付。CLI 首片在同一租约中串行交付，失败停采并保留失配计数，跨进程续写和自动重试要等可持久化的绑定和检查点。

| 位置 | 初始预算与过载行为 |
| --- | --- |
| 文件尾读 | 单个在途 `Poll`，每轮限 64 KiB／50 个包，半行限 8 KiB。当前无新字节时沿会话调度退让。同步本地 I/O 的实际耗时受系统影响。 |
| 归档交接 | CLI 首片同一所有者最多积压 256 个定长包，另有控制／尾记槽位。单批至多 50 行，剩余空间不足时先提交当前批次，再轮询。不挤掉旧行，也不接第二批到满队列。未来跨异步队列须同时记条数和实际字节，满时优先暂停拉取。 |
| 归档失败 | 保留最早失败水位和具体错误。已验证但未通过项目回读的行另报计数，字节落盘但缺回执时标记未确认。终态写入也可能失败，可回看的范围止于最后已核验前缀。 |
| UI 与协议输出 | 屏幕窗口、分页和订阅各自有界。预览淘汰和输出背压都有独立状态，归档工作不等待 UI 消费。查询使用冻结采样 ID 和已发布水位。 |

计数独立保存为本次可见字节／完整验行、已交接、已提交、未确认、显示淘汰、归档前暂停／过滤（可确认才给数）、源报告丢包和结束时未知尾。`EventsDropped` 只接受不倒退的累计下界，缺通知为未知。连续归档行、写入方最终行数以及最后一次为零的报告只能约束已生成归档所含的数据。源未写下的行为保持未知。

## 截止、归档和重读

1. 本端到期、显式停止、输入结束或传输失联时，在已打开的源句柄上冻结一次可见字节终点。CLI 首片以最多 4 次额外尾读及约 250 ms 的协作排空预算为初值，每轮前检查时间。同步 I/O 在途时报告实际耗时。保存已完成的行，半行只记录长度，超过截止边界的新增字节留在源文件。若预算未读到边界，列出已验证字节和待验范围。停止跟随使用独立 `cutoff`，当时无可信写入者回执则源终态未知。
2. 只有同源真实写入所有者交付成功刷盘、关闭且带最终 `written()` 的回执，读端才排斥新写入并验证最终连续行数及完整换行。已关闭而没有成功计数为 `UnconfirmedEnd`，写入失败关档为 `WriterFailed`，半行或计数矛盾为截断或回执冲突。CLI 首片的 `writerReceipt` 为 `null`，`coverage` 为 `unknown`。本端完整地保存并回读所选前缀时 `capture` 为 `stopped`。遇到坏行、半行、未排完或归档失败时为 `partial`。
3. 先登记冻结采样，再由现有单写者写入 Stored raw 段。首片使用 `api-archive-follow-plan-v1`、`api-archive-packet-v1` 和 `api-archive-follow-end-v1` 保留每个 1,000 字节包、源文件 ID、行号和本端回读状态。分段写完、刷盘并逐包回读核验后更新进程内回执。旧 `api-monitor-clue-import-end-v1` 是关档导入专用格式，ETW 检查点也是独立契约。首片可用通用 `archive.inspect` 检查段的封装。三端语义级回读前，须冻结 API 的 `raw`／`records` 依赖与检查点，并把缺检查点或未验尾部呈现为未发布。[项目方法契约](../../schemas/action_analyze/method-contract-v1.md)
4. 读者固定 `projectId/sampleId/configRevision`、源绑定和提交水位，从首段逐个验证身份、端点、CRC／散列、序号连续性及全部依赖。后段失败留住此前已核验前缀。原位重读使用上次提交的选择，权限失败或异源文件保持现有记录和选中证据。源仍可重读时可显式创建新的被动采样，原样本的截止、缺口及证据保留。
5. 先做 CLI 准入、实时查询、截止与原包分段回执。再完成共享格式与 CLI、Qt、Light 的同样本重开；最后给 Qt 的现有时间线、Compact 结果表和共享字段详情接实时投影，Light 在现有虚拟列表／原生详情旁接本端活所有者。所有端显示来源、范围、末次采样和是否已提交。筛选、切页和选中行只改变视图。背景任务登记回读真实所有者状态，界面从结果快照按代次提交。 [桌面总览](../ActionAnalyze总览交互与验收.md) · [运行时控制](../运行时控制开发规范.md)

## 验证矩阵

| 层级 | 正控 | 负控及判据 |
| --- | --- | --- |
| 共享尾读 | 自有生产格式的逐字节原包，行跨块续读，非命中／覆盖包随行计数。 | 坏 JSON／Base64、超长、序号跳跃或重复、混入后代、PID 重用及创建时间缺失在首次问题位置停读。回执早到、最终计数不符、截短与半行分别报错。 |
| CLI 活会话 | 使用明确授权的既有本地生产归档，等待同一文件新增观察，查询可见字节、已核验行数、最近一条 API 线索和段坐标。原包通过 Stored 核对。 | 缺授权、非本地或非普通文件、错误会话或进程实例、过代请求、混用 ETW 参数分别拒绝。空尾持续显示等待，读权限或格式故障报告独立状态。 |
| 限额和截止 | 慢写与积压维持单个在途，停止后原包、读取量和已存量可对账，继续追加留在原文件。 | 密集追加、半行跨截止、写满或检查失败、期限内无法追完、客户端输出关闭时，保留核验前缀且公开积压、未确认和未知尾。 |
| 项目与三端展示 | CLI、Qt、Light 同一已提交样本逐包核对，来源筛选、详情、分页、重读和导出引用同一坐标。 | 错代、未发布段、缺引用、坏尾、换项目与异步迟到结果保留原结果。分别验 Qt 的首帧／窄窗／DPI／双主题和 Light 的真实窗口、旧入口及键鼠路径。 |
