# ActionAnalyze 十一项达到 70% 的路线图

目标是让 11 项各自达到 70%。第 3 项的 70% 指原归类与展示口径；三端已验第一条行为释义，混合来源和更多行为规则仍待验。第 8 项为 85%。每项达到下表的正式入口和验收门槛后再更新百分比。局部夹具继续登记实际范围。

本路线把本机无驱动的正式 R3 路径作为第一阶段里程碑。普通 R0 保留独立交付条件，当前为 0/29，指定来宾版本低于 26300 准入要求。若里程碑要求 R3 和普通 R0 同时达到 70%，须补齐适配来宾和对应实测回执后才能关闭。三端各自持有活会话，跨端共用证据契约及只读回放格式。前端入口为 Qt「监控 → 行为分析」、Light「监控 → ActionAnalyze」和 CLI `analyze session`。[当前进度](../ActionAnalyze产品验收清单.md) · [施工任务](../ActionAnalyze施工任务与契约落点.md)

## 开工顺序与并发

| 优先级 | 并发工作线 | 首批产物 | 依赖到位后立即接入 |
| --- | --- | --- | --- |
| 开工 | 协调者 | 从现有契约冻结最小字段集合。项目、采样、修订、对象实例、来源状态、原始坐标、停点修订及恢复结果各有明确所有者。约定同一自有样本和预期输出。 | 维护公共契约、工程登记及交付集成。各线先使用已确定的接口，待定字段由协调者定点补齐。 |
| 同批 | 采集会话 | 第 1、2 项。先把现有受支持的 Agent 接入和真实 Ready 回执绑定到新采样，同时接通已有授权生产归档的实时原包写入。 | 第 1 项的 Ready 通过后，串起从所选起点到实时 WinAPI 和 ETW 混合采样，提供给第 3、4、9、11 项。 |
| 同批 | 调试与恢复 | 第 6 项。把正式 CLI 的单绑定控制扩展为有明确成员及恢复责任的停止组，先取得正常继续、退出及故障清退证据。 | 第 5 项先准备只读区域、线程及证据身份。第 10 项先准备带阶段约束的条件求值。两项绑定真实停点时共同使用第 6 项接口。 |
| 同批 | 网络归档 | 第 7 项。复用网络归档格式，接通项目会话的授权流量输入、实际字节和分段提交。 | 以同一采样接通端点检索、完整字节回查和桌面重开，向总览交付已提交水位。 |
| 同批 | 跨进程证据与桌面图 | 第 4、9 项。强身份归并和离线关系投影可分两人做，Qt 与 Light 分别实现同采样的关系分组及定位。 | 生产遥测到位后复用已验证投影，接入实际跨进程证据和实时增量。 |
| 同批 | 规则和表达式 | 第 10、11 项。统一阶段字段及三值结果，先跑通现有规则的冻结、离线回放和命中证据。 | 第 6 项提供停点接口后接条件判断。第 2 项提供生产原包后接活规则执行。 |

**关键路径有两条。** 「起点就绪 → 活 WinAPI → 跨进程证据 → 桌面实时关系图」和「停止组与恢复 → 脏页停点与新线程接续」。活规则与条件停点在各自前置接口可用时接入。网络链独立推进，第 3、8 项只复测本次受影响的入口。

按真实目录分配写入范围。采集线负责 `Cli/LiveSession.cpp`、`Cli/PassiveApiCapture.cpp` 及各端会话适配。调试线负责 `Control/`，网络线负责 `Archive/NetworkEvidenceArchive.*` 及网络来源适配，证据线负责 `Detection/` 及桌面证据组件，规则线负责 `Rules/`。以上 CLI 子目录位于 `KswordCLI/ActionAnalyze/`。Qt 总览和 Light `ActionAnalyzePage.cpp` 各安排一名合入所有者，其他工作线交付适配接口。公共 schema、CLI 方法目录、工程登记由协调者集中合入。

每条线交付时写明改动路径、可用接口、可验入口及复跑命令。接收方按接口可用性开工。开发和验收可交叠，例如桌面关系图区验收时继续写实时采集适配。共享固定构建输出、GUI 配置、活项目或来宾的任务由验收方排队，其余有独立资源的任务并行。共享产物构建后，由多个只读用例复用。第 3、8 项沿用已有基线，仅在本轮涉及其路径时安排定向回归。

## 每项达到 70% 的门槛

| 项目 | 正式交付范围 | 验收结果 |
| --- | --- | --- |
| 1. 起点注入（x64／WOW64 合作启动已验） | 自有目标主动装载 Agent，冻结目标身份及本轮配置，返回真实就绪状态。 | 正式 CLI 已验启动就绪与首个业务调用；Qt／Light 保留既有合作直连回执。非合作外部自动注入为无。 |
| 2. WinAPI 回传（60%） | 自有 Agent 在样本运行期间持续回传，原包分段写入项目。CLI 和两个桌面端在受支持入口开始、停止及重开。 | 正式 CLI 已分别对 x64／WOW64 核对三段普通原包，验证同时只读回查和缺末段保留前缀。三端保留既有单段互读实证，新版桌面分段运行及持续高负载待验。 |
| 3. 分类与展示（原口径 70%） | 保持五类回放和桌面定位。行为规则独立展示可核验释义。混合采集保留独立 API、ETW 筛选和来源。 | 已验三端同一采样的访问拒绝规则正负例。还须用同一混合采样检查分类、释义、坐标及坏段恢复。 |
| 4. 跨进程转移监控（20%） | 只从 KSword 自有采集组件读取证据。保留来源观察、待确认候选、强实例关系和执行证据的各自依据。 | 一个已核实的关系和一个仅有候选的反例皆可回查。覆盖 PID 重用或身份不足，历史回放对账原始锚点。遥测不足时保留缺口，不启用外部 Sysmon 作为回退。 |
| 5. 脏内存断点和新线程（30%） | 无驱动 R3 的受支持自有调试范围内，正式入口观察写入变化；首次停点后新线程进入同一会话。 | 正式 CLI 已验 1／2／4／8 B 对齐数据导出、范围外及同值写负例、后建线程触发、旧令牌拒绝和正常退出。桌面运行、任意私有页及跨区待验。 |
| 6. 全局下断与恢复（30%） | 正式控制冻结明确进程及线程集合，公开已持有、部分持有、待恢复和已释放结果。桌面可走显式停止和继续。 | 受支持的两个目标成员可对账。过期令牌被拒绝，正常继续不重复释放。取消、目标退出和控制者中断均有可复核结果。责任未完成时终态保留未清退。 |
| 7. 流量抓取与归档（30%） | 自有回环通信触发实时归档，保存方向、端点、出站 IP 及实际保留字节。使用正式项目入口重开或读取完整字节。 | 对账 IPv4、IPv6、收发方向和已知内容。验证元数据有效但无字节、截断、来源丢失和坏尾。Qt、Light 和 CLI 回查同一采样。 |
| 8. ETW 遥测归档（85%） | 保持连续采集、独立事件筛选、覆盖回执和项目重开。 | 混合采集接入后定向复测 ETW 停止排空、末段对账，以及 UI 关闭或查询暂缓时的采集责任。 |
| 9. 底部树状图（40%） | Qt、Light 能展开当前采样的候选、来源上下文和已核实关系，使用现有总览和详情定位原始记录。活采样接入有界增量。 | 两端同一采样验证原始坐标、鼠标与键盘、筛选后保留身份、切样清除旧节点、归档重开及实时更新。 |
| 10. C# 风格表达式及条件停点（55%） | 明确支持的语法子集，将冻结的表达式绑定到真实断点的可用字段及事件阶段。 | 正式 CLI 已核对冻结 RIP 的真、假、RAX 未采集的未知及 UTF-8 错误位置。桌面活条件及多目标绑定未实现。 |
| 11. 行为规则预置（65%） | 五类基础预置在已提交段上产生命中、规则 ID、覆盖状态和原始坐标。 | 正式 CLI 已核对合作采集的累计回执、离线回放与归档图的同一坐标。桌面活规则实测、合作规则版本随计划登记及更广规则覆盖还未闭合。 |

## 最短集成批次

1. 首批合入候选和来源上下文的桌面浏览、原始记录定位，以及已实现的 CLI 完整字节回查。并行写第 1、2、6、7 项后端，确认独立验收能读到当前工作树。
2. 第一条实时链闭合时交付第 1、2 项，同时拉动第 4、9、11 项。第 7 项按自身采样和终段归档独立交付。
3. 第二条实时链先闭合第 6 项，再让第 5、10 项对同一停止组分别取证。第 5 项的区域和新线程接续各有验收回执。
4. 用正式 Release 串起新项目、实时采样、规则与调试、停止、重开和证据回查。提交证据覆盖的批次至 `ActionAnalyze`。交付范围及发行门槛沿用原验收清单。

本轮可单独转交五项验收。AA-03 覆盖合作目标的 Agent 就绪和 CLI 线索归档。AA-04 覆盖 Qt 与 Light 的归档分组定位。AA-05、AA-06、AA-07 分别覆盖 CLI 规则回放、实时回环网络元数据和合作目标条件断点，均可复用 AA-03 的构建。验收前的百分比沿用已登记的产品证据。[本轮验收交接](validation-handoff.md#本轮转交提示词)
