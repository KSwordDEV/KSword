## 1. 总目标与本轮边界

在 KSword 已有 ARK、内存、驱动、Cross-view、ETW、WFP、安全状态和调查功能上，补齐“采集事实 → 解释差异 → 关联对象 → 保存证据 → 离线复核”的完整使用流程。优先深化已有实现，不创建同名重复模块，不以代码行数、agent 数量或额度消耗作为成果。

本轮交付分为 P0、P1、P2。P0 聚焦完整性、Cross-view 和内存证据的准确性；P1 聚焦时间线、网络规则解释、安全状态与快照比较；P2 聚焦 dump 与实体关系。质量要求贯穿各阶段。阶段可以分别交付，但不能把 P0 完成称为全部 roadmap 完成。

原有虚拟化 roadmap 是另一份任务。当前本地正在开发的 Intel/AMD 虚拟化实现与验收要求不得被本文件重置、缩减或替代；这里也不把虚拟化功能重写成新目标。不自动改系统安全配置，不自动重启工作机，不新建持久服务，不上传用户数据。

所有新审计流程默认不修改被观察对象；允许的写入仅限用户选定的本地证据/日志、用户明确启动的测试程序自身资源，以及隔离测试环境内明确列出的自有临时对象。读取本身可能造成缓存、驻留或时序变化，不能宣传为完全无副作用。

### 1.1 已核对的现有基础

公开 README 已列出 R3/R0 进程和线程 Cross-view、Driver integrity/module Cross-view、PTE 翻译与可执行内存扫描、WFP/NDIS/网络内核视图、ETW/风险中心和安全策略页。[R1]

仓库共享记忆还记录了 Light 的 `Core/EntityRef`、`Ui/EntityNavigation`、`Ui/EvidenceSession`、跨进程 `Core/DriverLease`，以及 Callback Monitor 的独立游标和丢失统计。[R3][R5] 这些记录说明存在可复用基础，但不等于本规范中的增强项已实现或实测通过。

本次没有读取用户开发机的未提交变更，也没有运行 Windows 程序。因此本地当前工作树必须作为实施依据；公开提交号只说明本文件查阅来源，不要求把本地分支退回该版本。

### 1.2 明确不承诺的事情

不承诺查出所有 rootkit、确定所有内存的分配者、还原任意包的完整真实 WFP 路径、从有限 dump 确定每次蓝屏根因，或证明同一内核提供的多份结果绝对可信。遇到证据不足时，正确交付是显示限制与原始事实，而不是编造确定结论。

不以“增加了页面”“实现了接口”“能编译”“写了测试文件”作为完成。必须贯通所需的真实采集、生产分析逻辑、UI 操作、保存/重开及对应验证；缺少环境的部分必须保留待验证状态。

## 3. 验收状态、环境和证据

实现状态使用：`未开始`、`开发中`、`已实现`。验证状态使用：`NOT_RUN`、`PASS`、`FAIL`、`BLOCKED`。`已实现` 不等于 `PASS`。

每条验收记录至少含：编号、实现位置、测试或操作步骤、目标环境、实际结果、预期结果、日志/样本路径及未解决问题。不同环境分别记录；一台机器通过不能自动覆盖另一种硬件或配置。

`PASS` 必须覆盖该编号要求的全部验证层。离线算法测试通过、现场尚未运行的条目，总状态仍不是 PASS；可以在子结果里分别记录。负面测试中的预期拒绝/不支持可以 PASS，但它只证明正确拒绝，不能算正向功能可用。

`BLOCKED` 只用于确实缺少资源、权限或环境。遇到代码自身失败写 FAIL，不得改为 BLOCKED。未运行写 NOT_RUN。不能通过删掉用例、放宽预期或把必需项改成可选来变成通过。

适用性另外记录：`required` 或 `not_applicable`，默认全部 required。某睡眠模式硬件确实不存在等情况可标不适用并附依据，但不得拿它代替本来要求的硬件验证。任务范围的改变必须单独向用户说明，不能由实现 agent 暗改。

### 3.1 必须区分的环境

- E0：不依赖真实驱动的解析、规则、状态机、导入导出和回放自动测试。
- E1：实际开发机/测试机的普通用户和管理员无驱动环境，验证 R3 能力与降级。
- E2：授权测试机中匹配的新驱动已真实加载，验证声明支持的 R0 和 UI 流程。
- E3：VBS/HVCI 实际运行的配置，验证有支持的能力及其正确降级；不能为测试自动关闭保护。
- E4：兼容旧驱动/旧客户端组合，验证协议与现有功能未被破坏。
- E5：生命周期、Verifier、临时规则和故障注入的隔离测试环境。
- E6：真实且有使用权限的 dump 样本及对应调试引擎。

记录每个环境实际的 Windows build、架构、CPU/逻辑核、内存、驱动版本与符号标识、安全配置、工具链及测试模式。不得用“Windows 11”或“最新版”代替精确信息。首轮不扩大现有 OS 支持声明；本轮引入的新高版本 API 必须符合现有动态解析/能力降级规范。

### 3.2 完成判据

模块完成 = 所有适用必需编号满足要求 + 必需正向环境有实测 + 对应失败/降级行为有测试 + UI 能使用 + 保存结果能复核 + 没有未解决的崩溃、越界、身份串用、假成功或无界资源问题。

阶段完成 = 本阶段全部必需模块完成，并满足受影响的 F/Q 项。全部 roadmap 完成 = P0、P1、P2 都完成；仍有必需 BLOCKED 项只能报告“实现完成，部分实测待补”，不能报告全部验收通过。

## 4. 数据约定与共同判定规则

对象身份：进程/线程绑定启动和生命周期；文件身份、驱动映像身份、对象地址、连接五元组与名字各有适用范围。身份不完整就保留弱关联，不用字符串相似度补成确定对象。

证据 envelope：记录来源 id/版本、采集时间范围、源状态、范围/数量/截断情况、对象引用和原始值引用。事件另含源时间、接收时间、来源序号和可用关联标识。所有 64 位整数与地址必须无损保存。

事实与解释：原始观测保存不改；规则输出含规则 id/version、命中的事实和解释。差异不等于恶意；同源一致不等于独立确认；来源失败不等于对象不存在；符号缺失不等于地址非法；非映像可执行不等于注入；签名有效不等于实际策略放行。

采集失败、分析无法判断和正确的空集合必须在 UI、导出和报告中保持不同语义。任何必须字段缺失都不能靠默认 0、空串或“正常”补齐。

刷新、导航与保存：每个快照/任务有独立身份，现场刷新生成新观测；离线会话不可被现场刷新覆盖。页面关闭不等于可以抛弃后台引用；取消需要安全释放而不是强制卸载驱动。

### I · 内核完整性检查深化（P0）

**目标：** 对明确选中的模块、代码范围和关键入口，回答哪里不同、比较依据是什么、哪些差异可解释、哪些不能判断；不是承诺检测所有内核篡改。

**本轮包含：** 复用已有 Driver/Kernel integrity、inline/IAT/EAT、IDT 等能力；增加比较依据校验、PE 映射归一化、可解释差异、覆盖率和统一证据。

**不包含：** 自动修复代码页、移除第三方 hook、写 SSDT/MSR/IDT、恢复回调、关闭安全功能；扫描所有内核页并给出绝对安全保证；从哈希猜测恶意。

**依赖与复用：** F；使用已有反汇编器和 PE 解析器，缺陷可修，不能再引入第二套。

#### I-01 模块身份匹配

要求：比较前核对架构、映像大小、版本/调试标识等可用信息及文件身份；磁盘同名文件不自动视为加载时的对应版本。必要信息不足时降低比较可信度。

验证：提供正确文件、同名异版、被替换文件、无磁盘文件、无 PDB 的样本。

通过条件：只有匹配依据充分的区域进入可归一化比较；错误版本不会被批量报为 hook。

验证：使用节大小不等、零填充、截断、重叠或越界节的样本。

通过条件：合法范围映射准确；畸形映像被拒绝或局部跳过，绝不越界读取。

#### I-03 重定位与加载变更

要求：对支持的 x64 重定位精确归一化；IAT 等运行期写入单独解释。不能粗暴忽略整页、整节或所有跳转指令。依据 [M1]。

验证：同一 PE 在两个基址建立测试映像，再改变一个非重定位字节；加入不支持的重定位类型。

#### I-05 差异定位和上下文

### X · Cross-view 差异解释与复核（P0）

**目标：** 把现有多视图结果从简单不相等升级为可复核、能处理竞态与同源性的差异解释。

**本轮包含：** 首轮强制覆盖进程、线程、加载驱动；句柄、设备、网络按已有可靠 collector 适配，只有达到同样证据要求才标注支持。

**不包含：** 开发隐藏进程/驱动来制造测试；全物理内存盲扫；宣称两个 API 返回一致就排除 rootkit；为了凑三视图复制同一数据。

**依赖与复用：** F；复用现有 Cross-view 页面与 collectors。

#### X-01 来源独立性可见

要求：每个视图说明入口、底层证据来源、依赖链和共享关系。同一个 collector 的两层包装不是两个独立来源。

验证：把同一个底层快照经两种 UI/API 包装输入，另给一份真正不同来源的证据。

通过条件：前两者归入同源组；报告同时显示视图数与来源组数，不靠重复视图提高可信度。

验证层：源码核对＋离线自动测试。

#### X-02 进程实例关联

要求：关联进程必须优先使用启动标识＋PID＋创建时间；地址作为本次辅助证据，不用于跨启动匹配。创建时间缺失时明确关联弱。

验证：测试 PID 复用、同名进程、仅一个视图有创建时间和系统特殊对象。

通过条件：不会误合并或错误报告隐藏；身份不足保留候选关系。

验证层：离线自动测试＋目标环境实测。

#### X-03 线程所属与生命周期

要求：线程匹配必须绑定进程实例及可用线程创建信息；对线程退出、进程退出和权限不足分别处理。

验证：持续创建/结束自有线程并抓取多视图；离线构造 TID 复用。

通过条件：生命周期竞态不升级为确定隐藏；残缺所属信息不会挂到同 PID 新进程。

验证层：离线自动测试＋目标环境实测。

#### X-04 驱动实例关联

要求：区分加载模块、DriverObject、DeviceObject 和磁盘服务配置，不要求一对一对应。模块列表缺项与无 DriverObject 是不同现象。

验证：输入一个模块多个对象、服务存在未加载、无设备驱动对象、模块卸载等样本。

通过条件：差异类型准确，不把合法多对多结构报告成 rootkit。

验证层：离线自动测试＋现场样本核对。

#### X-05 复采样确认

要求：首次缺项标为待复核；默认在至少两个后续采样中尝试复查，并记录间隔。只有身份、来源状态和观察区间满足要求才判为持续差异。

验证：样本分别在一轮、两轮后出现，另一个持续缺失；目标在复查前退出。

通过条件：瞬态、持续差异、对象已结束、无法复查四种结果可区分；不能把固定等待时间当恶意判据。

验证层：离线自动测试＋目标环境实测。

#### X-06 失败不是缺项

要求：视图超时、拒绝访问、截断、符号不支持均不得当作“该视图确认不存在”。

验证：使一份视图空成功、另一份失败、第三份只返回上限数量。

通过条件：只把成功且完整覆盖目标范围的视图用于缺项推断；其它显示未知。

验证层：离线自动测试。

#### X-07 解释证据可展开

要求：每条持续差异可展开各视图命中情况、采样区间、原始记录、身份依据和复核历史。

验证：选择一个离线持续缺项样本和一个真实无差异对象。

通过条件：从结论可回到每条源记录；无差异结果也可核对覆盖，不只是红绿图标。

验证层：离线自动测试＋目标环境实测。

#### X-08 可重放的检测正例

要求：在离线快照副本中删除一个视图里的已知进程、线程或驱动记录，作为显式测试数据；不能把数据改写器编进生产采集路径。

验证：对三类对象分别运行固定输入和预期结果。

通过条件：准确指出被删除对象及受影响视图；不得用条件编译伪造生产结果通过。

验证层：离线自动测试。

#### X-09 高频创建退出场景

要求：自有负载连续 10 分钟创建和结束进程/线程；记录已知活动及采集丢失，不拿系统里未知对象假定干净。

验证：在受支持测试机上运行自有可识别负载，并对抽样实例复核。

通过条件：已知实例不因 PID/TID 复用或采样时差被标为确定恶意；无法解释的差异保留事实与限制。

验证层：目标环境实测。

#### X-10 实体扩展不降标准

要求：句柄、设备、网络只有在定义了对象身份、来源语义及复核行为后才接入统一判定；未接入的现有页面继续可用。

验证：核对扩展清单；对每个宣称支持的实体重复失败/复用/瞬态三类用例。

通过条件：每个宣称支持的实体都有测试；未支持实体清楚标注，不用空表冒充完成。

验证层：源码核对＋自动测试。

### M · 内存证据与地址翻译深化（P0）

**目标：** 从进程或内核地址出发，展示实际读取的区域、映射依据、可用的页表证据和可解释线索，并能保存后离线核查。

**本轮包含：** 复用现有 MemoryDock、R0 读取、PTE/VA 翻译和可执行内存扫描；补充来源、读取状态、区域/映像关联和有界分析。VAD 私有结构仅在已验证 profile 下支持。

**不包含：** 新增长期任意物理内存映射、写 PTE、修改页权限、扫描 MMIO、绕过 VBS/VTL、把所有 private RX 当成注入；无来源就声称追溯任意 pool 分配者。

**依赖与复用：** F；I 的 PE 解释可复用但不得互相等待形成循环。

#### M-01 区域信息语义

要求：展示 base、size、state、type、protection、allocation base、映射路径及来源；R3 区域查询与 R0 VAD 证据分开。

验证：自有程序创建 reserve、commit、mapped file 和 image 区域并记录真值。

通过条件：字段符合各自来源；未读取 VAD 时不显示“VAD 已验证”。

验证层：离线自动测试＋目标环境实测。

#### M-02 安全读取与部分结果

要求：使用仓库规定的 KswordARKRuntimeReadMemory 等既有封装，在合法 IRQL 分块读。保留返回状态和实际字节数，不能以异常包装的直接解引用替代。依据 [R4][M2]。

验证：测试页边界、不可读区域、部分复制、目标退出和数据变化。

通过条件：不越界、不蓝屏；缺失字节明确表示；完整成功与部分成功不混用。

验证层：自动测试＋R0 变更时隔离实测。

#### M-03 VA 翻译上下文

要求：每次翻译保存进程实例、地址空间/页表根来源、时间和已支持的分页模式；失效上下文禁止复用。

验证：同 VA 在两个进程映射不同内容，再结束一个进程。

通过条件：两者翻译不串用；退出后只显示历史观测，不声称仍有效。

验证层：离线自动测试＋目标环境实测。

#### M-04 分页边界与大页

要求：实现与声明一致的页表层级；覆盖 4 KiB 和 2 MiB 翻译，1 GiB 在硬件/模式允许时按能力处理。不支持模式明确拒绝；不伪造物理地址。

验证：固定离线页表样本测试普通页、大页、非 canonical 地址、缺项和保留位异常；现场对可获得映射核对。

通过条件：已支持样本逐层索引、偏移和结果正确；不可翻译给理由；未能实测的大页单独列未验证。

验证层：离线自动测试＋目标环境实测。

#### M-05 非驻留与观测副作用

要求：缺页、过渡态和软件页表项与有效硬件映射区分。只做页表查看时不为了凑结果读目标页；显式读内存可能改变驻留状态，需与之前观测分时记录。依据 [M2]。

验证：提供 present、not-present、过渡态样本；先观察再读取可分页区域。

通过条件：不从无效项生成 PA；不会把两次不同时间观测包装成原子快照。

验证层：离线自动测试＋目标环境实测。

验证：断开符号、使用错版 profile、制造循环和不合理区间的离线树。

通过条件：明确不支持/数据异常，保留可用 R3 结果；不回退猜偏移。

验证层：离线自动测试＋目标环境实测。

#### M-07 可执行区域线索

要求：支持 private executable、image 代码差异、起始地址/映射归属不一致等有证据的规则；规则逐条列出事实，不靠单个属性直接判恶意。

验证：正常自有 JIT/RX 区域、普通映像、已知改写的离线映像均入样本。

通过条件：JIT 等仅显示特征与上下文；真正差异精确呈现；未知归属保持未知。

#### M-08 区域、模块与页表联动

验证：完成一条 Process→Region→Image/Bytes→Translation 的操作链，再离线重放。

通过条件：各页引用同一实例/快照；离线缺项明确显示未保存。

验证层：离线自动测试＋目标环境实测。

#### M-09 内核 pool 归因边界

验证：输入多组件共用标签、没有标签、只有范围命中的样本。

通过条件：所有者字段按直接证据/候选/未知区分，不生成假调用栈。

#### M-10 扫描预算

#### M-11 离线字节和隐私

验证：保存含不可读孔洞的测试范围，关闭目标后重开。

通过条件：可用字节逐位一致，孔洞仍是孔洞，文件无越界范围；离线打开不需要管理员或驱动。

#### M-12 现场翻译验证

要求：实际地址翻译须以受控映射或可用调试工具作独立核对；离线样本只能证明解析算法。无法稳定核对的地址标明限制。

验证：在测试机为自有进程选取稳定映射，保留查询记录及独立对照。

通过条件：真实地址上下文与结果有可复核记录；没有环境时为 BLOCKED，不复制离线期望值。

### T · 统一时间线与调查会话（P1）

**目标：** 让用户捕获一次明确范围的系统活动，停止后仍能按进程实例和时间找到发生过的事、查明采集缺口并离线重放。

**本轮包含：** 复用 ETW、Callback Monitor 与已有文件/注册表/网络事件；首轮必需进程、线程、映像、文件、注册表、网络六类中在目标 profile 下明确支持的采集。六类各自的必需支持配置在开工映射中固定，不能事后删类。

**不包含：** 另写第二套内核回调队列；默认全系统无过滤采集；自动开机常驻、服务化部署；将时间邻近当成因果关系；把事件列表包装成完整攻击链。

**依赖与复用：** F；现有多游标 callback ring、ETW ownership 和采集器生命周期必须保留。

#### T-01 会话生命周期

要求：明确新建、开始、暂停显示、停止采集、保存、打开；暂停显示与停止采集不能是同一个含糊按钮。

验证：按各状态启动、暂停、继续、停止，并在各阶段关闭页面/程序。

通过条件：状态与后台实际行为一致；停止后不再记入新事件；暂停期间的缓存/落盘策略可见。

验证层：离线自动测试＋目标环境实测。

#### T-02 事件类型与原始数据

要求：事件统一 envelope，但保留 provider、event id/version/opcode、原始字段和解析版本；未知事件版本不套旧结构。

验证：六类已声明事件各取固定样本，另输入未知 schema。

通过条件：已支持字段正确；未知事件可保存为未解析记录，不错位解析。

验证层：离线自动测试＋目标环境实测。

#### T-03 源和 UI 过滤分离

要求：界面区分采集过滤与显示过滤；后者不能让导出误以为被隐藏事件不存在。

验证：采集两个自有进程，只显示其中一个，再分别导出可见结果和完整会话。

通过条件：两种导出数量及说明符合选择，原始会话不因 UI 过滤损坏。

验证层：离线自动测试＋目标环境实测。

#### T-04 时间语义和乱序

要求：跨源排序保留源时间、接收时间、精度与可用校准；乱序迟到可补入但不得改写原始时间。不能宣称跨 CPU/源严格全序。

验证：注入乱序、重复时间、时钟校准变化和两个启动周期。

通过条件：排序确定可解释；原始时间不丢失；用户能识别迟到/不确定顺序。

验证层：离线自动测试。

#### T-05 进程复用与事件归属

要求：事件绑定进程实例；缺进程开始事件时建立“身份不完整”的临时实体，不将事件静默归给当前同 PID 进程。

验证：丢掉一个开始事件、重放 PID 复用以及目标已结束后的迟到事件。

通过条件：不误归属；补齐证据时关联过程可追踪。

验证层：离线自动测试＋自有进程实测。

#### T-06 丢失、跳过和截断

要求：分别记录源端丢失、驱动 ring 覆盖/争用、R3 队列丢弃、解析失败、过滤掉、保留策略删除。来源只能报告总计时不编造精确丢失时间区间。依据 [R5][M3]。

验证：自动测试强制 ring 覆盖及队列溢出，现场查询 ETW 会话统计。

通过条件：缺口可见且不重复计数；不得把部分轨迹显示为完整；0 也有可解释的统计来源。

验证层：离线自动测试＋目标环境实测。

#### T-07 不干扰现有消费者

要求：统一时间线有独立游标/租约；停止它不得停掉已有 File Monitor、Callback Monitor 或他人 ETW 会话。

验证：同时运行旧监控与新时间线，依次停止、重开任意一方。

通过条件：另一方仍采集；只清理本功能实际拥有的会话与引用，不使用全局 stop。

#### T-09 可靠保存与重开

验证：保存后关闭进程和驱动，在离线状态重开并对比统计和抽样事件。

### C · 离线崩溃转储分析（P2）

**目标：** 打开本地 Windows x64 内核转储，给出可核查的崩溃事实、栈与模块证据，并明确哪些推断被转储内容限制。

**本轮包含：** 首轮支持现有 DbgEng 可解析的 x64 small kernel dump 与 kernel memory dump；基础事实、符号、线程栈、模块和报告。IRP/锁等在转储包含数据且解析支持时显示。

**不包含：** 重新实现完整 WinDbg、自动上传 dump、自动执行用户/文件提供的 debugger 命令、为验收让工作机蓝屏、凭栈顶模块宣判责任。

**依赖与复用：** F；优先复用现有崩溃/符号代码。DbgEng 是可选依赖，仅影响此模块。依据 [M6]。

#### C-01 可选调试引擎

要求：优先采用独立受控 helper 承载现有可用 DbgEng；明确探测位置/版本，缺少引擎时本页不可用但主程序正常。

验证：有引擎、缺引擎、错误架构、引擎初始化失败各运行一次。

通过条件：错误精确，主程序不退出；不从未知路径加载 DLL，不自动下载二进制。

验证层：离线自动测试＋目标环境实测。

#### C-02 文件识别与支持范围

要求：识别支持的转储类型、目标架构和基本头信息；不支持的格式明确拒绝。首轮不把用户态 minidump 当成内核 dump。

验证：合法 small/kernel dump、用户态 dump、空文件、截断文件及随机文件。

通过条件：分类正确，不崩溃、不按扩展名硬解析；未支持格式不冒充解析成功。

验证层：离线自动测试＋目标环境实测。

#### C-03 崩溃事实

要求：展示 bugcheck code、四参数、目标 OS/build、可用的时间/uptime、转储类型；缺字段注明缺失。

验证：同一文件用可用 WinDbg 读取 .bugcheck 和基本目标信息进行对照。

通过条件：事实字段一致；时间或 uptime 缺失时不填 0 冒充真实值。

验证层：真实 dump 对照测试。

#### C-04 符号精确匹配

要求：保留符号匹配标识、加载结果和缓存来源；错误 PDB 不可用于给出确定函数/行号。网络符号下载须用户启用、可取消、有限时。

验证：正确 PDB、错误版本、无网络和部分模块无符号分别测试。

通过条件：正确符号可用；错版不误用；无符号仍显示模块＋偏移与可用事实。

验证层：离线自动测试＋目标环境实测。

#### C-05 栈与模块

要求：显示地址、模块、函数/偏移、展开状态与可用参数；无法展开的部分保留边界，不拼接猜测帧。

验证：选至少两个已知转储，与同版本引擎的独立交互查询对照。

通过条件：可用帧与模块一致；损坏/缺失栈明确停止；优化导致的归因歧义保留。

验证层：真实 dump 对照测试。

#### C-06 可疑模块解释

要求：模块在栈上、故障 IP 所属模块、Verifier 明确报告等证据分开；只生成调查线索与依据，不输出无校准的责任百分比。

验证：使用普通故障、可能延迟内存损坏、只有 ntoskrnl 栈顶的样本。

通过条件：不把 ntoskrnl 或最后一帧直接当根因；证据不足写无法确定。

验证层：真实 dump 对照＋文案检查。

#### C-07 缺失内存的边界

要求：small dump 不保证包含 IRP、锁、完整进程或 pool；页面按真实可用性展示，不能靠扫描其它文件补全而不说明。依据 [M7]。

验证：对缺 IRP/锁/对象页的文件执行对应查看。

通过条件：明确“转储未包含/当前无法解析”，不生成空对象当真实数据。

验证层：真实 dump 对照测试。

#### C-08 超时、取消与隔离

要求：调试引擎卡住、符号服务器阻塞、扩展解析失败不得卡住 UI；仅可结束本模块拥有的 helper，不终止其它 debugger/构建任务。

验证：注入 helper 停顿、断开通信、取消符号查询。

通过条件：UI 按预算响应，保留部分结果并明确中断；再次打开可恢复。

验证层：离线自动测试＋目标环境实测。

#### C-09 不可信路径与输出

要求：路径、转储文本和符号名按数据处理，不拼接 shell 命令；报告 HTML 转义；只允许实现内固定的必要分析命令。

验证：文件名与模块名含引号、分号、换行、HTML、DML/命令样式文本。

通过条件：无命令执行、无脚本注入、无报告外部资源自动访问。

验证层：离线自动测试。

#### C-10 已知来源样本与导出

要求：测试样本须有来源/取得权限说明；没有真实样本就列 BLOCKED。保存报告注明引擎版本、符号状态、输入身份和分析范围。

验证：对每个声明支持的类型完成一次从打开到导出的实际流程。

通过条件：报告可重核；模拟解析结构不能替代真实格式验收；没有自动把 dump 打包上传。

验证层：真实 dump 对照测试。

### G · 实体关系与跨页调查（P2）

**目标：** 把现有实体连接成可点击、可解释的调查关系，让用户从一个对象继续查，而不只是多一张好看的关系图。

**本轮包含：** 复用 EntityRef/导航；进程、线程、模块、文件、句柄、驱动、设备、服务、网络、证据记录之间的已有直接关系。首轮用现有 Qt/Win32 UI，不引入网页前端。

**不包含：** 无依据补齐关系、全系统自动无限展开、3D 图、把时间邻近绘制为确定因果；为图重写所有页面。

**依赖与复用：** F；T/N/D/C 逐项完成后可增加对应关系，但基本导航不得被后续模块阻塞。

#### G-01 边的语义

要求：每条边含关系类型、方向、时间有效区间、证据引用和确定性；不同关系不能用一条“相关”边混掉。

验证：输入 owns、loads、maps、opens、candidate-owner、temporal-neighbor 等样本。

通过条件：图/列表能区分且可筛选；缺证据关系不显示为确定。

验证层：离线自动测试＋UI 实测。

#### G-02 生命周期和旧对象

要求：不同启动周期、不同 PID 创建时间、地址复用对象分开；历史边不能自动套到当前对象。

验证：重放同 PID/地址多实例，再从历史边打开现场。

通过条件：保留历史对象；现场身份不匹配时拒绝自动定位到新对象。

验证层：离线自动测试＋目标环境实测。

#### G-03 最小可用调查链

要求：交付三条链：Process→Thread/Module/Handle；Device→DriverObject→Driver image→可证实的 Service；Connection→Process instance→Timeline。无数据环节明确缺失。

验证：自有目标或已授权现场完成三条链并保存会话。

通过条件：每一步可打开来源详情；不能只画出节点而不能导航。

验证层：离线自动测试＋目标环境实测。

#### G-04 有界展开与性能

要求：初始只显示目标及一跳关系；默认最多 200 节点/500 边，更多需用户明确展开；计数不能暗示已加载全部。

验证：输入 10,000 节点/50,000 边的离线数据集，反复展开、折叠和筛选。

通过条件：界面保持第 7 节响应预算；超限说明和继续加载有效，不隐藏真实总量状态。

验证层：离线性能测试。

#### G-05 孤立与未知不等于异常

要求：缺少 owner、对象已卸载、来源未采集与实际不一致分别表示。

验证：输入四类节点。

通过条件：不存在“无边就恶意”的规则；孤立节点仍可查看原始证据。

验证层：离线自动测试。

#### G-06 离线和跨视图一致

要求：关系图、列表、详情和导出引用相同实体 id/证据 id；离线展开只使用已保存数据。

验证：同一会话在图和列表选同一对象，保存重开并比对。

通过条件：身份与关系一致；不偷偷现场查询或执行目标操作。

验证层：离线自动测试＋目标环境实测。

#### G-07 可用性与既有风格

要求：提供可排序的关系列表作为图的等价操作方式；键盘能选择、打开详情、返回；主题/语言沿用现有体系。

验证：只用键盘走完一条链，在现有中英文和明暗主题检查。

通过条件：无需依赖颜色区分关系，地址可完整复制，没有新增硬编码字体/主题旁路。

验证层：UI 实测。

#### G-08 图是证据视图不是分析真值

要求：所有推断可展开规则和来源；图布局位置、节点大小与颜色不增加未定义的风险含义。

验证：同一数据换布局和排序，比较导出结论。

通过条件：分析结果不变；没有把视觉相邻当成逻辑相关。

验证层：离线自动测试＋UI 审阅。

这些集成用例补充第 5 节，不替代逐项测试。测试数据必须有唯一 run id、来源与生成方法。自动构造的样本只在测试路径使用并明确标记，不得出现于生产采集结果中。

### A. 正常现场调查

在 E2 启动自有测试程序，采集进程/线程/映像，查看完整性、Cross-view 和内存证据。选择一条结果跳到原有详情页，再保存会话。结束测试程序并关闭驱动后离线重开。

预期：对象身份正确；来源和覆盖可核对；离线不依赖管理员/驱动；过期对象不能被导航成同 PID 的新进程。关联 F、I、X、M、D、G。

### B. 确定可知的差异

在离线捕获副本中，修改一个非重定位代码字节，并从一个视图移除一个已知对象；不修改运行中的内核。独立保存期望 RVA、原/新值、对象身份和来源。

预期：完整性定位到正确字节；Cross-view 定位到正确视图缺项；两者证据与预期一致，生产路径没有读取测试真值的特殊分支。关联 I-03/I-05、X-08、Q-01。

### C. 瞬态对象与 PID/TID 复用

离线重放确定的复用事件；现场运行 10 分钟自有进程/线程快速创建退出负载。不能要求现场一定在某秒发生特定 PID 复用，确定复用由离线样本覆盖。

预期：不同实例不串用；瞬态缺项经复核后分类正确；权限错误不计作确认缺失。关联 F-03/F-09、X-02/X-03/X-05/X-09、T-05。

### D. 错版或缺失符号

对 PE、VAD/PTE 相关解析与 dump 分别提供匹配符号、错版符号和无符号状态；断开网络但保留 UI 操作。

预期：可用的无符号功能继续工作；依赖私有结构的能力明确不可用；没有猜偏移、错误行号、永久等待或自动改工具链。关联 I-01、M-06、C-04/C-08。

### E. 页边界与部分读取

自有进程分配确定内容的两页，第二页设为不可读或释放；请求包含边界的范围。内核地址失败路径通过受控 fixture/授权环境验证，不随机触碰 MMIO。

预期：实际成功读取的范围可见；其它位置保持孔洞，不填零伪造；进程退出后错误状态清楚。关联 M-02/M-05/M-11、F-05/F-06。

### F. 旧驱动和权限不足

分别运行普通用户、管理员无驱动、兼容旧驱动、新驱动环境。用明确的 collector 失败样本补齐无法现场触发的返回状态。

预期：能力级降级；无假空集合；现有 R3 页面、导出和证据查看不被整体阻断。关联 F-05/F-07、S-07、Q-04。

### G. 时间线受控工作负载

运行 T-11 辅助程序，采集前确认 collector 已就绪。用独立真值日志对照事件语义与关联；不要按机械 1:1 事件数检查系统活动。

预期：已支持范围内的受控操作可以找到相应事实；预期负载下不可解释丢失为失败。把一次操作映射到多个事件或汇总事件的规则在跑前固定，不能看到结果后改预期。关联 T-02/T-05/T-11。

### H. 人为过载与多消费者

离线强制队列满与 ring 覆盖，现场同时运行已有监控和新时间线；停止其中一个。

预期：明确丢失/覆盖统计，不伪造完整轨迹；独立消费者继续工作。可预期过载下正确报告丢失的用例可通过，但不能用它代替规定吞吐下的无不可解释丢失验收。关联 T-06/T-07、Q-07。

### I. WFP 临时规则

仅在 E5，由用户明确授权为自有 loopback 测试创建带唯一标识的动态规则。列出新增对象，再运行匹配/不匹配连接，最后只删除本次对象。

预期：静态候选、实际事件与未知动态判断分开；不影响其它规则；清理记录可复核。关联 N-01 至 N-08。

### J. 配置与运行状态冲突

输入 Configured 为真、Running 为假的固定样本；现场对可用配置用公开查询核对。测试不需要主动关闭/开启安全功能。

预期：显示“已配置、未运行”及来源，不能显示保护正在生效。未知枚举值原样保留。关联 S-01/S-05/S-08。

### K. 会话写入中断

对自有测试程序在批次提交前后受控终止，注入磁盘满/无权限，再打开副本。

预期：已提交部分保留；丢失/不完整状态明确；不开启自动修复源文件行为。关联 T-09/T-10、D-06。

### L. 快照变化与重启样本

用明确真值的离线数据模拟排序变化、ASLR 变化、collector 失败和真实字段变化；现场在授权对象上做一次前后变化对照。

预期：排序/装载基址本身不产生错误逻辑变化；未知不是删除；真实变化能定位到字段。关联 D-01 至 D-08。

### M. 真实 dump

分别打开合法 x64 small kernel dump 和 kernel memory dump，使用同版本调试引擎独立对照 bugcheck、模块与栈；再测试损坏文件及缺符号。

预期：可用事实一致；缺内存限制明确；不凭栈顶模块输出确定根因。没有真实样本则 E6 项保持 BLOCKED。关联 C-01 至 C-10。

### N. 退出、恢复与长期任务

在 E5 运行受控采集 30 分钟及 50 次启动/停止循环；执行系统支持且获授权的 3 次睡眠/恢复。退出其中一个客户端时另一个继续查询。

预期：无本轮相关崩溃/死锁/持续无界增长；所有权与引用释放正确；恢复后的缺口与状态真实。30 分钟通过不代表长期稳定已被证明。关联 Q-05/Q-08/Q-10/Q-11。

### O. 不可信输入

向生产导入/解析入口投喂固定畸形样本：长度溢出、截断、深递归关系、重复 id、恶意文件名、HTML/DML 和路径穿越内容。

预期：拒绝或保留为数据，不执行命令、不写出目录、不崩溃/无界分配。关联 F-07/F-08、C-09、Q-12。

## 7. 性能目标与测量方法

以下是拟定的验收阈值，必须由实际测试决定是否达标。不得把它们写成项目当前性能，也不得在跑不动后自行调低。确实与现有支持目标冲突时，单独报告测量结果、瓶颈及建议修改，保留原条件未通过。

### 7.1 测量环境

使用 Release x64，在记录过配置的同一台机器上运行，不同时进行大型编译或其它已知重负载。记录 OS/build、CPU/逻辑核、内存、存储介质、驱动、安全配置、页面/采集范围及数据 seed。预热一次，正式运行三次，分别保留结果，不只展示最快一次。

CPU 百分比定义为本功能相关进程的 CPU 时间增量除以墙钟时间和逻辑处理器数量。R0/ETW 额外成本不能全算到 UI 进程，因此真实采集同时报告系统 CPU 同机前后差值；不把它当成严格隔离的精确归因。内存至少记录进程 private bytes、峰值、队列占用及本功能 tracked allocations。

### 7.2 固定负载

L1 表格与快照：100,000 条实体记录，字段规模固定在生成器说明中；包含至少 5 类实体、地址和长路径。数据已就绪后测选择/筛选/排序，交互反馈 p95≤200 ms；后台计算可更久，但必须给出进行中状态且 UI 不冻结。

L2 时间线回放：使用固定 seed 生成 1,000,000 条事件，单条序列化 payload 不超过 512 B；总数包含有限异常/未知版本样本，比例在生成器中固定。经生产入口持续 10,000 条/秒输入至少 60 秒，完成解析、必要关联和本地保存；该规定负载下应用自身队列不得发生不可解释丢弃。目标 p95 从接收到可检索≤1秒。单次全程目标 private bytes≤1 GiB；不能为凑上限去加载所有 UI 行对象。

L3 查询：在已落盘的 1,000,000 条事件会话上，对已建立索引的进程实例＋时间范围查询，首屏返回目标≤1秒；在 100 次预定义查询中至少 95 次达到。另报首次冷打开耗时，不把热缓存结果当冷启动结果。

L4 关系视图：后台数据 10,000 节点/50,000 边，首屏最多 200 节点/500 边，加载后反馈 p95≤200 ms。超过默认展开上限必须请求继续，不自动绘制全图。

L5 真实采集：使用 T-11 受控负载验证 collector 语义和没有不可解释缺失。它与 L2 完全分开，不能据 L2 宣称实际 ETW/R0 达到同吞吐。另以实际可承受的阶梯负载记录开始丢失的条件，作为测量结果而非硬编性能保证。

### 7.3 取消、资源与运行时间

点击取消的可见确认≤200 ms；正常分块扫描目标在下一个安全批次结束，本地可中断工作目标≤3秒。不能安全中断的系统/驱动请求必须显示准确等待状态、保持有界和允许其它 UI 工作，不准为追这个时间强行卸载驱动。外部 helper 可在发出取消后 5 秒无响应时由 owner 结束；只能结束本任务拥有的实例。

新增功能未启动采集且界面静止 60 秒时，平均 CPU 增量目标≤整机容量的 1 个百分点；既有后台监控的成本必须分开记录。活动采集同时报告吞吐、延迟、CPU、内存、丢失，不能只报其中最好的一项。

预热后执行 50 次生命周期循环和 30 分钟持续负载。本功能确定可枚举的 live handles/tasks/subscriptions/allocations 回到预期静止状态；缓存留存必须有上限与解释。进程 private bytes 或系统缓存无需机械回到启动前数值，但任何单调持续增长都要定位，不能用“缓存”两个字豁免。

## 8. 多 agent 分工与顺序

集成 owner 负责最小共享接口、协议分配、工程文件、公共导航、阶段集成构建及验收状态。它不需要重写各模块，也不能只收子 agent 一句“完成”就通过。

建议功能组：I/X 一组、M 一组、T 一组、N/S/D 一组、C/G 一组；每组在实际文件不冲突时才并行。F 只做这些组需要的最小共享能力，Q 随修改验证。不要为了用满额度把同一工作拆成多个相互竞争的实现。

先完成 F 的数据语义与各组入口约定；随后 I/X/M 可并行，T 可并行搭建复用适配；P1 在对应来源可用后集成；P2 的 dump 引擎与关系视图可按依赖独立推进。阶段未通过不阻止无依赖工作的实现，但禁止将混合半成品标成阶段完成。

每个 agent 开始时说明要改的文件与对应编号；共享头/语言文件/项目文件由 owner 合并。不得互相覆盖、删除或格式化其它 agent 的工作，不得对共享工作树执行破坏性清理。是否使用独立 worktree 按现有环境决定，不额外制造必须人工操作的流程。

构建采用原有任务/日志会话，保存一次命令与日志位置，只有需要时读取增量或末尾信息。不要不停重开终端重复打印完整构建日志；不要每改一段文案重跑所有项目。相关测试失败先定位并修复，避免多 agent 同时争用同一输出目录。

每完成一组条目，提交可复核的结果：做了什么、涉及哪些编号、哪些测试实际跑过、哪些受阻、下一步依赖。无需长篇自述，也不以文件数量和代码行数代替功能进展。

必要交付物仅包括：实际代码与工程/资源接入、调用生产逻辑的自动测试和 fixture 生成器、可复用的受控辅助程序、简明使用/限制说明、逐项结果记录及相关日志/样本。不要求每模块生成一堆同义报告。

只有用户另外要求时才做完整发行包、提交到远程、发布 release 或修改 CI 大框架。本任务不授权远程写入、自动安装驱动、开启 Verifier、安全配置更改或重启；这些需要独立明确授权。
