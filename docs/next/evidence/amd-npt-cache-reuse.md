# NPT02 reuse candidate — 2026-09-24

The current v7 live run has not demonstrated a complete operating-system boot. The later coherent sample adds 3,025,071 L2 exits, including 2,776,931 NPFs, and 275,788 L1 VMRUN exits. The earlier five-second window with no L2 entries does not establish a permanent L1 loop. Evidence: `artifacts/hotspots-v7-live-20260924/`.

This candidate removes unconditional NPT02 destruction at each general-mode virtual VMRUN. A processor retains only its most recent context. Reuse requires the same translated VMCB identity, virtual ASID, NCR3, L1 paging/PAT state, outer translation contract and shadow epoch, with virtual TLB_CONTROL zero. All accepted nonzero TLB commands reset the cache; INVLPGA and pool recycling invalidate its epoch. The physical VMCB still requests a full hardware TLB flush on every entry.

An ownership slot also retains its previous acquisition token. Reuse requires uninterrupted ownership history for that VMCB: an intervening acquisition, including migration to another processor and back, discards the former cache. This metadata is accessed under the existing exclusive lease; no additional exit-path allocation or waiting is introduced. Bounded probe mode retains its original unconditional reset.

The architectural basis is AMD APM Volume 2, section 15.16.1: a hypervisor changing nested translations or reducing permissions must invalidate the corresponding ASID before reusing it. This implementation conservatively resets the whole local software cache for commands 1, 3 and 7 and INVLPGA. NPT01 remains immutable for the prepared lifetime; mutable outer mappings would require a separate invalidation mechanism before enabling this reuse policy. Source: [AMD APM Volume 2](https://docs.amd.com/v/u/en-US/24593_3.44_APM_Vol2).
