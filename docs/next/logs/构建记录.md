### 一次卡住的构建及其处置（如实记录）

03:32 启动的 Qt 构建在 12 分钟内没有进展。按 `.claude/memory` 里记的纪律核实：进程树是 `msbuild → cmd → powershell(Sign-KswordArkDriverVariant.ps1)`，该 powershell 12 分钟只消耗 1.2 秒 CPU，且**全机没有任何活跃的 `cl` / `link` / `signtool` / `ApiValidator` / `aitstatic`**。确认卡点在自动 variant 签名步骤之后，只结束了**这一次构建**的 signer 与它的宿主，随后用记录在案的 `KswordArkSkipAutoVariantSign=true` 重跑并通过。

**没有把被中止的构建说成成功**：上表的退出码来自重跑后的那一次。

### 另一个反复出现的现象

`Ksword5.1.exe` 在链接阶段多次报 `LNK1104: 无法打开文件`，但当时没有任何 KSword 进程在运行，文件也可以被重命名 —— 是共享读锁（构建末尾的签名步骤或本机杀软扫描）造成的瞬时占用。等待后重试即通过，**不是代码问题**，也没有为此改动任何构建配置。
