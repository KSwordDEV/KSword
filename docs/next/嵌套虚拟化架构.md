# KSword HVM 嵌套虚拟化架构

KSword HVM 可以在 Hyper-V 虚拟机内部通过嵌套虚拟化运行。外层 Hyper-V 始终是物理层的 L0
hypervisor，而 KSword HVM 在目标子分区里成为 L1 hypervisor。

```text
CPU
└─ Intel VT-x / EPT
   └─ Hyper-V (L0)
      ├─ 根分区
      │  ├─ 宿主 Windows
      │  └─ VBS / HVCI / 内核隔离
      │
      └─ Hyper-V 子分区
         └─ KSword-HVM-Target 虚拟机
            └─ KSword HVM (L1, VMX root)
               └─ 原本那个 Windows
                  （L2 执行上下文，VMX non-root）
```

## 它不启动第二个 Windows

这是最容易读反的一点。KSword HVM **不引导、也不创建**另一个 Windows 实例，它对**已经在跑的**
那个系统做一次**后期虚拟化接管**（late launch）。

`VMLAUNCH` 之后，原本那个 Windows 的执行上下文**原地**继续往下跑，只是从此运行在 VMX
non-root 模式；KSword HVM 在 VMX root 模式处理它产生的 VM exit。没有重启，没有第二个内核，
桌面上什么都不会发生 —— 这正是它容易被误判成"没生效"的原因。

从外层 Hyper-V 的视角看，KSword HVM 与被虚拟化的 Windows 始终在**同一个子分区里**：

```text
KSword HVM 启动前：

CPU
└─ Hyper-V (L0)
   └─ 子分区
      └─ 来宾 Windows


KSword HVM 激活后：

CPU
└─ Hyper-V (L0)
   └─ 子分区
      └─ KSword HVM (L1)
         └─ 同一个来宾 Windows (L2)
```

## 宿主与来宾的分工

宿主可以继续开着 VBS/HVCI —— 那些保护由**外层** Hyper-V 环境拥有，与子分区里发生的事无关。

但**目标来宾自己**不能再跑一套自己的 Hyper-V/VBS：KSword HVM 需要直接拿到嵌套 VMX 接口，
而来宾里的 Hyper-V 会先一步占住 VMX root。所以靶机的前置里有
`bcdedit /set hypervisorlaunchtype off`，那不是可选项。

一句话：

> **Hyper-V 拥有物理虚拟化层；KSword HVM 拥有嵌套来宾的执行层。**

## 嵌套给这一层带来的硬约束

嵌套不是"和裸机一样，只是慢一点"。外层决定了内层能看见什么，有三条是实测撞出来的：

* **没有 Monitor Trap Flag。** 嵌套 Hyper-V 不向来宾通告 MTF。默认的"写叶 + monitor-trap"
  隐蔽 Hook 后端因此在靶机上根本装不上，只有 EPTP 切换后端能工作 —— 它只要求
  execute-only EPT 叶，而那一位在同一台机器上可用。这是选那套后端的**唯一**理由。
* **跨核 TLB 失效要自己做。** 转发给 L0 的 flush hypercall 只会让 L0 去失效它认为的那个
  L1 VP，而那个 VP 正在跑我们的 L2，兄弟核上的陈旧翻译不会被清掉。修法是私有 host IDT +
  广播 NMI，见[嵌套下的跨核TLB失效](嵌套下的跨核TLB失效.md)。
* **必须显式声明允许嵌套。** 检测到外层已有 hypervisor 而请求里没带"允许嵌套"时，驱动直接
  拒绝启动常驻，而不是静默降级 —— 因为静默降级出来的东西没人能判断它到底在保护什么。

## 常驻（resident）是什么，为什么需要它

驱动里有两种进入 VMX 的方式，差别不是程度而是种类：

| | 一次性来宾（one-shot guest） | 常驻（resident） |
|---|---|---|
| 谁在 non-root 里跑 | 驱动自己造的一小段测试代码 | **正在运行的这个 Windows** |
| 持续多久 | 几条指令，立刻 VMXOFF | 一直，直到显式停止 |
| 能观测什么 | 只有那段测试代码 | 全机器的每一次 VM exit |
| 用途 | 证明 VMX 能进能出 | 真正的监控与拦截 |

**只有常驻期间，这一层才存在。** 停掉常驻之后 CPU 回到 VMX 关闭状态，EPT 不再被硬件遵守，
所有基于 EPT 的能力（隐蔽 Hook、分离视图、执行域、R-1 进程处置）全部**同时失效** ——
不是降级，是那一层不在了。这解释了几件反直觉的事：

* **EPT 规则、分离视图、R-1 处置都只能在常驻停着时安装。** 常驻期间退出路径不持锁就在读
  这些表，而安装要分页、要改所有处理器都会走的页表。所以界面上"装一条处置"实际是
  `停常驻 → 装 → 重启常驻`。
* **`sc stop` 在常驻期间返回 1052。** 驱动的卸载守卫在拦：映像正在 VMX root 里被执行，
  卸载它等于把机器打死。要停服务必须先停常驻。
* **`RESIDENT_ACTIVE` 置位不等于它还在跑。** 那是状态位，不是心跳。权威判据是
  `residentProcessorCount > 0`，更硬的判据是 `CR4.VMXE`（bit 13）—— 蓝屏转储里这一位为 0
  就意味着崩溃时我们根本没在跑，那次崩溃不可能是我们注入的。

常驻的代价也要说清楚：每一次 VM exit 都要经过我们的派发路径。嵌套靶机上实测 30 秒约
34000～68000 次退出，其中最大的一类是 HLT（外层已经在做 VMCS shadowing，所以 VMREAD
并不贵 —— 单次约占一次退出成本的 0.149%）。打开 CR3 追踪会让**每一次地址空间切换**都变成
一次退出，Windows 每秒切换数千次，机器会明显变慢 —— 所以它是按需开关，不是默认。
