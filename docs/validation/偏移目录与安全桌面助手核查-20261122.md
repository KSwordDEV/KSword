## 1. 偏移是否真正入库

`b2927455d` 只提交了代码。根 `.gitignore` 当时整体忽略主程序 `profiles/`，两个结构目录内的 TSV
和 `_versions.index` 没有进入该提交。此前“全部提交”的回答没有解决结构数据交付，不能算完整交付。

本轮改为仅放行两类结构 TSV、邻版说明及版本索引，其它生成资产仍忽略；并对这两个目录强制 LF。
二进制 TSV 加载器不能接受被 Windows checkout 改写的 CRLF，因此不能只修改忽略规则而不固定换行。

## 2. 没有精确命中时不应只有固定字段

风险判定与参考展示必须分开。仍只有同架构、同内核分支的无歧义前后来源才能证明 bracketed；
但缺一侧、同版不同 RSDS、最近一版有多个 PE 来源时，已有来源的字段仍应展示为只读参考并标明版本/RSDS。
本轮新增独立参考来源选择，保留这些字段，不再沿用风险判定清空后的候选来决定是否有字段可看。
参考布局不提供目标地址或实际值，不授权正文采样，不与固定字段回执合并。

本机磁盘内核是 `10.0.19041.7844`，正式 CLI 对精确布局返回 ETHREAD 766 行、EPROCESS 672 行。
该版也是当前 19041 目录的最高版本，没有严格更晚的同分支来源，所以按原要求仍为黄色。
截图中的“未找到精确符号布局”与当前 Release 的磁盘元数据查询不一致；没有运行中的主程序可供核验其原始路径，
不能仅凭这次查询反推截图当时的加载身份，也没有加载宿主驱动来冒充现场采样复验。

## 3. 主界面版本为什么仍是 5.2.1.0

排查时 `WelcomeDock.cpp` 已为 `5.2.1.1Pre`，但其修改时间晚于正式 EXE；EXE 内仍只有旧版本字面量。
版本显示直接来自该源文件的唯一发行标记，不是另一个设置项。问题是版本源变更后未生成对应的新 EXE，
不能把 Git 中版本号已修改说成用户运行的界面已更新。

## 5. UacDesk 自动启动链

助手已经在此前的改名提交中变为 `KSwordSecureDesk.exe`。主程序在首次显示后，仅对非救援、已提升实例
自动启动同目录的新名称；普通权限实例不自动请求另一轮 UAC，救援实例不重复启动助手。
旧 `KswordUacDesk.exe` 不是当前自动启动入口，本轮不删除历史产物，也不启动两个不同名字的助手。

确认并修复两个交付/诊断缺口：

1. 主工程缺少助手 ProjectReference，单独构建主工程不会保证同目录助手同步。现已登记构建依赖。
2. 原启动函数丢弃所有错误且只检查 CreateProcess。现记录缺文件、创建失败和跳过原因；
   使用 QWinEventNotifier 异步等待引导进程退出，区分真正收到 SYSTEM 就绪回执与阶段失败/超时。
   不增加轮询，不在 UI 线程阻塞等待，应用退出时注销通知并关闭句柄，不强杀助手或改变既有父进程绑定。

真实 SYSTEM/UIAccess、UAC/锁屏覆盖层、普通权限与管理员实例的 GUI 验收仍需用户手动完成。
本轮源码/构建检查不替代这些运行结论。
