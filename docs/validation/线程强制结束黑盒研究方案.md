# 线程强制结束：独立黑盒验证方案

本方案只验证已有实现的外部效果，不接入 Ksword 的工程、CLI 或菜单，也不实现替换 Windows 线程终止、调度或对象清理机制的代码。

## 要区分的三个结论

1. **界面不再显示目标**：只能说明某个枚举来源不再返回它，不能等价于结束。
2. **原线程真实退出**：采样前记录 PID/TID、两者创建时间，持有原对象的查询与同步句柄；关键证据是同一线程对象从未触发变为已触发，不是某次按 TID 打开失败。若测试的是进程终止，还要独立确认原进程对象触发。退出码作为附加证据，不单独判定生死。
3. **退出后系统保持正常**：复测目标原先使用的设备、文件和子进程是否还能正常工作，再做多轮、分版本重复；只确认覆盖过的环境与负载。即使全部通过，也不能由黑盒信息反推出内部实现是摘链还是调用了其他终止路径。

## 虚拟机测试矩阵

| 用例（仅测试者自有对象） | 对照或证据 | 判定 |
| --- | --- | --- |
| 普通可退出的测试进程和工作线程 | 正常退出；在前后分别执行零超时等待，保留原始身份 | 验证采集本身能区分运行和退出 |
| 退出前仅从一处表中隐藏结果的模拟 | 只过滤测试工具的显示；不改系统对象 | 验证报告不会把消失误判为退出 |
| 普通用户 APC 已入队、尚未投递 | 自有工作线程先进入不可警报等待；对照组放行至可警报等待，另一组保持原状态并用标准终止 API 结束自有夹具 | 要求确认已入队、窗口内未回调，且分别取得投递证据或原对象退出证据 |
| 自有可取消 I/O、主动延迟完成的 I/O | 使用公开终止流程作为基准；保存取消、完成和退出的时间边界 | 区分请求已接受、I/O 待清理和实际退出 |
| 合法取得且经过审查的待评估版本（如有） | 对相同夹具、同一精确 OS 构建、等长等待进行对照，保存哈希、版本、退出证据以及故障日志 | 只判外部效果与实测稳定性，不推定内部算法 |

两台客体各自先留独立快照并核对远程连接。每项逐轮登记 `对象身份、触发时刻、原始返回值、线程/进程等待结果、后续资源复测、崩溃或超时`。不得把超时当失败后的删行成功，也不得把成功轮次替换掉失败轮次。测试结束重新核对远程连接；只有需要清理或客体失效时才回滚到已经确认可连接的快照。

## 当前证据

- Win10 20H2：客体 `ntoskrnl.exe 19041.631`；VIX 非交互管理员连接可用，原有 Ksword 驱动已启动，原有 `thread detail` 对自有线程退出码为 0。没有候选实现的测试结果。
- Win10 普通用户 APC 对照（各一轮）：两次均确认入队，约 `506 ms` 的观察窗口内，原工作线程、原进程和回调事件均未触发。对照组放行后 `25.958 ms` 观察到回调；终止组保持门关闭，`TerminateProcess=1`，原工作线程和原进程分别约 `9.0 ms`、`46.1 ms` 观察到 `WAIT_OBJECT_0`，回调仍未触发。结果来自持有的原始或复制对象句柄；VIX 回读及测试对象清理成功。
- Win11 24H2：客体已恢复到运行，原有固定 SSH 连接和管理员权限可用；系统构建 `26100.9711`，预检时 Ksword 驱动服务未安装。没有候选实现的测试结果。
- Win11 普通用户 APC 对照（各一轮）：两次 `QueueUserAPC=1`，约 `507 ms` 和 `514 ms` 的观察窗口内，原工作线程、原进程和回调事件都未触发。对照组进入可警报等待后回调执行；终止组在同一等待门未放行、回调未执行时 `TerminateProcess=1`，原工作线程和原进程句柄分别约 `34.7 ms`、`35.7 ms` 观察到 `WAIT_OBJECT_0`。测试器保留原进程句柄和从原线程句柄复制的同步句柄，未按 TID 重新打开来判定。两组夹具清理后固定 SSH 仍可用。该证据只覆盖普通用户 APC，不覆盖拒绝入队、内核 APC 或第三方未完成 I/O。
- 目前没有提交可供比较的第三方构建或可独立重现的数据。聊天记录不构成实现或稳定性证据；Hime Display 现场只证明改变外部条件后原进程确实退出，不能作为这段实现的验证结果。

双机结果一致：同一类普通用户 APC 在不可警报等待中可以已入队但尚未投递，且这一状态本身不妨碍标准 API 结束自有测试进程。此结果不外推为任意内核 APC/未完成 I/O 均可结束。各耗时均为观测端一次测量，不是性能指标。

## 下一组研究的判据

- 必须明确 APC 类型。微软将普通用户、特殊用户、普通内核、特殊内核 APC 分开；例如临界区只延迟普通内核 APC 和用户 APC，不代表特殊内核 APC 也被延迟。只凭 `QueueUserAPC`、某个私有标志或线程未从列表消失，不足以给内核 APC 下结论。
- 自有夹具如需验证当前线程短时延迟，区分「已受理」与「实际已进入受控区间」，另记录原生退出信号和独立的释放/恢复判据。没有受控放行对照时，不能区分“被延迟”与“本来就不会执行”。对内核 APC 的延迟、拒绝入队和终止当前没有额外实测结论。
