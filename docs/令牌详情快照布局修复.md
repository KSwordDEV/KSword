# 令牌详情快照布局与滚动重绘修复

- 同类源码对照：`句柄/HandleDock.cpp` 的对象头/对象类型、`ServerDock/ServiceDock.Properties.cpp` 的依赖/审计，以及它们使用的共享卡片、表单和响应式分栏。

- 令牌采集、规范字段文字、原始预览、搜索、复制和导出的唯一文档源保持原实现；没有新增主程序用户可见文本。

## 复现与原因

真实 Release 主程序在850px宽的进程详情窗口、快照中部复现长名称裁切和raw字节预览纵向缺行。首轮修复静止后收敛，用户继续反馈滚动时仍有数帧的大面积重绘，因此另行增加动态回归，不能用静止结果代替滚动验收。

布局方面，外卡片 `layout->activate()` 不保证嵌套列布局与 `QFormLayout` 已使用当前宽度；旧宽度参与行高回写会使虚拟几何反复校正。名称列原来由当前可见子集决定宽度，滚动到长短字段时会重新分配。`QLabel::heightForWidth()` 还会被上一轮固定高度钳制，窄窗留下的高度直到字段被回收重建才消失。原来用零高占位行表达虚拟空白，也会引入额外的6px表单行距。

重绘方面，物化会先拆空表单，再把同一批标签挂回；卡片外框又随可见窗口移动和缩放。新标签从卡片重挂到最终表单面板时，会增加样式失效。正文虽然有实底，Qt仍未得到可靠的不透明绘制契约，小步滚动可能让整个可见正文失效。正文/视口的 `LayoutRequest` 同时触发下一轮物化，形成布局反馈。

## 实现

1. 在后台使用冻结的文档、翻译、字体和宽度，按整段字段确定稳定名称列宽并预计算行高；滚动不再由当前子集决定列宽。名称测量和绘制统一使用 `Qt::TextWordWrap | Qt::TextWrapAnywhere`，保持无空格长名称完整。
2. 原生列宿主、表单逐层激活后再读取真实宽度。文字自然高度按文本、字体和宽度缓存；失效时先解除旧固定高度再测量。只在高度实际变化时写入，并显式安排补轮消费新约束。
3. 前后虚拟空白使用精确表单边距，单列两段间距与共享分栏的16px一致，避免占位行额外行距。
4. 普通卡片保持完整外框，只按视口物化字段；超过 Qt 控件尺寸上限的卡片保留原有裁窗和逻辑/物理坐标映射回退。
5. 字段窗口保留上下320px预取范围、80px安全余量；安全范围内直接复用。越界时只增删边缘行，保留重叠行的布局项和原标签。新标签直接创建于最终表单面板。
6. 32项创建/回收预算及预算占位继续保留。有预算占位时仍完整重建该有界表单，使占位按规范顺序转为实体；该回退仍会使用 `takeRow(0)`，不能说所有拆行路径都已删除。选区和焦点仍通过原保活机制维护。
7. 专用 `Canvas` 自绘完整正文底色，只在实际颜色alpha为255时设置 `Qt::WA_OpaquePaintEvent`，允许Qt复用滚动像素；透明时撤销该属性。卡片自己的圆角、颜色和留白仍归共享卡片负责。
8. 移除物化对正文/视口 `LayoutRequest` 的反馈触发，真实变化由 Resize、Show、Move、滚动通知及显式高度补轮驱动。没有使用 `setUpdatesEnabled()` 或强制 `repaint()` 隐藏问题。

固定外框单独实施并未明显减少大面积绘制；画布不透明契约和窗口/表单复用一起实施后才显著改善，不能把改善全部归因于 `takeRow()`。

## 真实主程序验收

使用独立配置的真实 Release 测试副本，EXE哈希与上述生产产物相同。关闭该副本的防止多开和自动提权，仅对本轮测试PID操作；在自身进程的令牌页检查。

- 850px宽、790px高、96 DPI双列详情窗：快照中部长名称和raw多行预览完整。32次正向、32次反向原生滚轮输入，连续采集259帧，约8.18秒。证据：`.codex-build-logs/detail-card-resize/real-final-850-complete/`。
- 840px宽、790px高、96 DPI单列详情窗：同样64次正反向输入，采集260帧，约8.15秒。证据：`.codex-build-logs/detail-card-resize/real-final-840-complete/`。
- 两组最低文字量帧的接触表抽查均保留正文，未见整块空白。850px另有69帧短程正反滚动样本。

采集先连续取实际桌面帧，再写盘和分析；每次取帧前后检查前台窗口及矩形，失去前台或移动时整组拒绝，失败捕获未充当验收证据。本机 PyAutoGUI 的参数直接进入 Win32，一个原生滚轮刻度需传120，不能把传1当作一个刻度。

850px取帧耗时中位31.19ms、P95 37.67ms、最大64.84ms；840px为31.31/36.22/52.00ms。采样可能漏掉更短的闪烁，因此结论限于有效采样及抽查未见整块清空，不宣称所有呈现帧或所有瞬时闪烁已经消失。重复字段文字干扰光流匹配，光流异常不用于判定字段跳动；桌面帧证据与组件几何证据分别报告。

真实主程序的深浅主题热切换尚未完成：两次设置动作明确返回 `control_unavailable`；后续前台获取也被其它桌面活动打断，没有实际完成设置和切换。offscreen深浅主题回归通过不能替代该项GUI验收。
