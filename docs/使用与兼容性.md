# KSword 使用与兼容性

最近核对：2026-10-05。本文说明当前源码的启动与能力判断，实际发行包请同时核对其构建日期和配套文件。

## 下载与启动

1. 从 [项目 Releases](https://github.com/KSwordDEV/KSword/releases) 下载发行包，完整解压 `Release/`，保留可执行文件同目录的 DLL、插件、`profiles/`、`languages/` 和许可证。不要单独复制 Qt 主程序 EXE。
2. 从解压目录运行 `Launcher.exe`。需要驱动或采集受保护系统模块时按提示提升权限。安装器 `KswordSetup.exe` 是可选入口。
3. Launcher 核对系统、目标文件和支持清单。早期 Windows 可选择轻量版；命令行也可明确选择目标。

```powershell
.\Launcher.exe --launcher-main
.\Launcher.exe --launcher-light
.\Launcher.exe --launcher-check-only
```

`--launcher-check-only` 核对当前已加载模块与支持清单，不启动主程序；清单不存在或无法读取时显示清单错误。检查模式本身不会生成采集包，缺少偏移时需退出检查模式再按 Launcher 的报告流程采集。内部采集与崩溃恢复参数用于 Launcher 自身流程，不作为普通启动选项。

| 组件 | 适合的任务 | 部署特点 |
| --- | --- | --- |
| `Ksword5.1.exe` | 完整 Qt/ADS 调查、编辑和监控工作区 | 需要随包 Qt 与 ADS DLL、插件及语言包 |
| `KswordARKLight.exe` | 原生 Win32 快速调查、实体导航和证据导出 | 无 Qt 依赖；功能覆盖与完整版本并非完全相同 |
| `KswordCLI.exe` | 脚本、能力查询与有界取证 | 参数见 [CLI 使用文档](CLI使用文档.md) |
| `KswordARK.sys` | R0 枚举、内存和系统对象能力 | 驱动签名、加载与逐功能能力须分别满足 |

Light 用跨进程租约管理自行启动的驱动；已有驱动不因退出 Light 而自动停止。命令框中的 `pid`、`tid`、`hwnd`、`file`、`reg` 等用于实体导航，前导 `!` 才显式进入命令执行。

## Windows 版本与偏移支持

当前 Launcher 源清单将 Qt 最低 build 标为 **17763**（Windows 10 1809）；驱动启动协议保留最低 build **16299**（Windows 10 1709）的检查。Launcher 在低于 17763 的 Windows 10 上提供完整/轻量版选择，而不是把 Qt 最低要求当作 Light 的硬阻断；低于驱动最低 build 时不能据 Light 能启动就认定 R0 可用。两者服务不同组件，不能混为一个“全部功能最低版本”。当前产品定位仍是 Windows 10/11 x64，Launcher 拒绝 Windows 10 之前的系统。

2026-10-03 已停用 Launcher 和驱动的 **OS build 上限拦截**。源清单设置 `advertisedMaximumBuild=0`、`allowNewerWindows11=true`；原 `Windows 10 1809 - Windows 11 24H2` 文本是既有范围记录，不代表更新系统已经实机验证。

解除上限不会自动产生新系统的私有结构偏移。DynData 按模块 PE/RSDS 身份及精确 PDB profile 匹配；缺 profile、能力或有效布局时，相应功能仍可能是 unavailable、partial 或 unsupported。不要用相近 build 的偏移替代精确身份。

Launcher 的 12 类模块清单包含必需兼容模块、已有数据源及 collection-only 模块。collection-only 表示可以收集 PE/PDB 身份，不代表已经实现并发布该模块的完整偏移支持。`complete=true` 也仅描述对应 profile 的生成条件，不能代替运行态逐功能判断。

## 从工作区定位功能

主工作区由欢迎、进程、网络、内存、文件、驱动、内核、虚拟化、监控、硬件、权限、窗口、注册表、句柄、启动项、服务、杂项 **17 个主 Dock** 组成。日志、监视面板、当前任务是 **3 个辅助 Dock**；设置通过独立对话框打开。结构扫描器在文件扫描流程中使用。

完整版标题栏默认“搜索”模式，可按页面路径定位当前可索引的页签、控件及表格内容；点击结果跳转并高亮。切换到 CMD 模式后提交命令会打开命令控制台。搜索结果不是扫描审计结论，也不能证明未加载页面不存在某项能力。

| 任务 | 使用方式 | 如何理解结果 |
| --- | --- | --- |
| 隐藏进程、线程与模块调查 | 进程详情、R3/R0 cross-view、注入痕迹检查 | 先看 PID + 创建时间及来源；采集差异不单独证明恶意隐藏 |
| 内存调查与补丁 | 附加目标、选后端、读取快照，再进入统一 Hex/反汇编/文本/对比视图 | 修改先暂存在快照；显式应用后以实际回读判断结果 |
| 汇编编辑 | 选择 x86/x64、预览机器码、确认覆盖完整旧指令 | 支持常用 Intel 语法及局部标签；不是 CE Auto Assembler 脚本语言 |
| API、ETW、Syscall 监控 | 在监控模块选择目标和事件/规则，启动会话 | 会话就绪、Hook 覆盖、丢事件与 Raw 事件状态影响可推断范围 |
| 内核回调 | 内核回调清单与 Callback Monitor | 清单是当前注册证据；监控是会话期间事件；注销需相应类别身份和当前代次 |
| 文件调查 | 文件详情、哈希/签名/字符串、结构扫描、元数据 | 信任状态、采集失败和无签名分别解读；删除与恢复不是普通浏览操作 |
| 剪贴板保护 | 杂项 → 剪贴板保护 | Agent Hook 与规则会话负责拦截，驱动策略表本身不自动阻断所有访问 |
| 调试器 | 配套 CE/TitanEngine/x64dbg/x96dbg 后端 | 看实际机制与回退诊断；请求的 R0/HVM 路径不等于已生效路径 |
| Light 证据 | 实体跳转、导出、证据会话快照与差异 | 导出是本次成功采集结果；脱敏与比较不补齐缺失证据 |

详细入口、实现和能力限制见 [功能技术文档](功能技术文档.md)。

## 虚拟化与 DDMA

虚拟化页支持 Intel VMX/EPT 路径，也接入实验性 AMD SVM/NPT 与嵌套 SVM 的准备、自检、常驻和证据流程。AMD 完整内层多核 OS 启动及性能仍未通过最终验收；Intel 的特定嵌套实验结果也依赖记录中的 CPU、外层 hypervisor 和构建。启动前核对驱动发布的能力、拒绝原因、模式和逐核实际状态。

DDMA 是磁盘控制器实验通道：需要显式指定暂存磁盘/LBA、满足调试器状态及设备透传能力。一次操作包含暂存扇区备份与恢复，失败恢复必须处理。虚拟机中的模拟 DMA 不证明绕过宿主地址转换。普通进程查看器中的 DDMA 保持只读；其他独立入口是否允许写入，以该页的确认和会话状态为准。详细说明见 [高级取证与实验后端设计](高级取证与实验后端设计.md) 与 [CLI 使用文档](CLI使用文档.md)。

## 不可用与故障排查

| 现象 | 首先检查 |
| --- | --- |
| 主程序启动时缺 DLL 或 Qt platform plugin | 是否完整解压；`platforms/qwindows.dll`、Qt/ADS DLL 是否与 EXE 同包 |
| R3 可用，R0 页面不可用 | 管理员权限、KswordARK 服务状态、驱动签名/加载结果及设备是否可打开 |
| 驱动已加载但某项不可用 | 驱动能力页、DynData 的模块身份/profile/字段来源、权限及该功能的独立前提 |
| OS 更新后 Launcher 提示缺少偏移 | 记录实际 build 与内核身份；按提示生成报告供精确 PDB 接入 |
| 列表字段是横杠、未知或 partial | 区分未采集、不可用、预算/截断与真实零值；不要据此断言对象不存在 |
| API 监控启动后没有结果 | 目标位数、注入状态、会话互斥、Hook 就绪/覆盖、筛选规则和丢事件统计 |
| HVM 无法准备或启动 | 实际硬件能力、外层 hypervisor、拒绝原因与全核状态；具体流程见 [实验工具](../tools/hvm_lab/README.md) |
| 编辑后显示写回失败/冲突 | 保留原错误与实际回读；重新核对目标、后端、会话、地址和原字节，再建立新快照 |

报告问题时提供构建日期、Windows build、CPU/虚拟化环境、操作步骤、原始错误码和页面能力状态。Launcher 报告含系统模块与身份信息，分享前检查内容；开发者接入流程见 [构建与发布](构建与发布.md)。
