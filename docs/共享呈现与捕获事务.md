# 共享呈现与捕获事务

本文记录 2026-10-08 收敛后的主程序接口。旧阶段文档中的 `MemoryEditorWidget`、
`HexEditorWidget` 和旧 Tab4/Tab5/Tab6 是历史设计，不应作为新增宿主的接入入口。

## 呈现与数据来源

属性与证据详情以采集器直接产生的 `FieldDocument` 为唯一结构数据源，使用
`StructuredFieldView` 原生字段控件呈现。文件、进程、窗口及行内/浮窗详情共用分组、
树状、搜索、主题和安全复制；进程常规页可把同一模型投影为紧凑双列。
复制和文本导出按需从完整模型生成，不保存报告文本，也不再按冒号或缩进猜测字段。
旧报告解析器、旧字段呈现器及文件专用包装已删除。

`CodeEditorWidget` / `CodeTextEdit` 只承载真实正文、代码、输入和日志。静态原文使用
`setRawText`，连续日志使用 `appendRawText`、`replaceRawText` 和 `setMaximumBlockCount`。
原始内存字节默认保持文本；完整有效的 JSON/XML 可通过 `TypedSyntaxDocument` 显式
投影为结构，格式不符合或超过预算时保留原文。JSON 数值保留源词法，不经 double
重写；重复键、XML DTD/实体和不完整内容明确拒绝。

字段菜单进入嵌套事件循环前冻结值、行和全文；刷新/宿主销毁后不访问旧节点。
属性无选区复制与复制全部从完整模型生成，搜索和折叠不丢字段。原文控件保持
完整真实正文、CRLF、选区和撤销语义；语言切换不翻译外部字段名、路径和原始值。

共享 `TablePresentation` 去掉重复外框和单元格网格线，保留表头底线、业务颜色、
列宽、行高、排序和选中状态。专用表格可显式保留自有样式；冻结与暂停的镜像
沿用来源呈现策略，不改变数据采集与提交屏障。

## 内存与快照

实时 `MemoryWorkbenchView` 与捕获证据 `SnapshotWorkbenchWidget` 共用五种子页。
子页识别集中在 `IsFollowSubPage`，新增页必须同时覆盖导航、身份恢复和数据刷新。
C 请求使用当前冻结来源/代次/位置/字节，光标或同窗口导航变化不能沿用旧分析地址。

比较覆盖整份请求范围，以分块扫描和虚拟行避免整表生成字符串；超预算必须拒绝，
未读证据必须标记不完整，不能通过裁尾后显示 0 来表示整体没有变化。

`AssemblyPreviewDialog` 统一边界检查、NOP 和预览；各宿主明确提供覆盖预算并负责
实际提交、确认、写前核对与回读。共享预览不拥有目标写入权限。

## 磁盘捕获写回

`DiskCapturedRange` 冻结磁盘快照、设备 GUID、访问层、偏移、原字节及来源代次。
切盘、切后端、重新枚举、新读取或未验证写回都会使旧资格失效。没有可核验 GUID
的字节仍可展示，但不能建立可写基线。

UI 两次确认均绑定同一个来源及修改缓冲；返回后重新检查当前上下文。共享事务检查
原字节并以实际回读接受新基线。最终写入使用捕获专用 V2 请求：R0 在同一次持有的
设备上下文中验证 GUID、读取并核对原字节，再向同一实例写入；捕获读取和写前/后
回读也使用绑定 GUID 的 V2 请求。旧驱动不能接受该
请求时拒绝写回，不回退到只按磁盘号写入的旧接口。

成功回执必须保留请求范围内的实际完成量；超量回执拒绝，失败的部分完成不能被
隐藏。请求 FUA 时向 Windows stack 传递写透选项，下层后端仍使用各自写透标志；
这不是硬件掉电持久化保证。

这保证捕获来源与实际写目标一致；普通物理磁盘 I/O 仍不是文件系统事务，不承诺与
任意外部磁盘写入具有全局原子性。真实介质/过滤驱动/掉电场景须单独验收，不能用
内存夹具或编译通过替代现场证据。

## 注册表入口

正式入口为 `RegistryDock_Themed.cpp` 和 `RegistryDock/RegistryDock.Mutations.cpp`。
已删除未登记的旧 `RegistryDock.cpp`，新增逻辑不得再次复制私有默认 Win32 helper。
所有操作捕获 `RegistryAccessContext` 中的路径、32/64位视图和 R0 通道；优化配置自身
明确指定的 Win32/native/WOW64 来源保持不变。

值移动/重命名需要系统事务中的原值核对、目的不存在检查、目标创建、原删除及
提交。失败必须回滚且核验实际状态；通道没有所需原子能力时在写前拒绝，不能自动
切换数据来源或把普通多次读写说成原子操作。文档操作保存真实回执，更新树和导航
时仍需匹配动作启动时的来源。

树删除同样要求事务能力：混合计划先检查全部操作的能力，R0 树删除在任何后端
读写前拒绝，不能先执行计划里的其它写入。无调用的旧逐次 `removeTree` 入口已删除。
Win32 键改名逐组件 OPEN_LINK 核验并持有精确句柄，改对象自身，不重新按父路径
选中其它对象；R0 没有实例绑定能力时在访问后端前拒绝真实改名。

## 插件归档

普通 ZIP 与官方资源使用 `PluginHost.Archive` 的同一条目、路径、链接、冲突、深度、
数量及展开预算门禁；在写第一个文件前完成预检，分块提取核验实际展开长度。
普通包允许根 manifest 或单一安装目录包装；官方资源仍要求声明的包装目录。
调用方继续负责下载哈希、许可证、manifest、安装回执与事务推广，不运行包内程序。

## 新增宿主检查

接入共享组件时同步工程与过滤器、双语用户文本及调用入口。补有价值的失败回归：
同窗口定位、最后分块、来源更换、模态回调销毁、外部冲突、能力不足和实际回读。
将测试端口替换为内存实现，不在真实磁盘或注册表复现破坏性条件。
