# 通用字节组件的 C 伪代码

`MemoryEditorWidget` 的 C 伪代码页使用真正的 Ghidra 反编译器，把当前选中地址所属函数还原为 C 风格的类型、表达式和控制流。HEX、反汇编、文本和 C 页共用当前字节快照，未写回的暂存修改也属于分析输入。分析不会运行样本，也不会写回进程、驱动或原文件。

## 安装运行环境插件

默认入口是 KSword 插件商城的 Ghidra 反编译后端。安装时阅读独立载荷许可证，安装器从固定官方地址下载 Ghidra 12.0.4 和 Temurin JDK 21.0.12.1+1，分别校验 SHA-256，完整保留两个运行环境的许可和文件树。组件自动使用 `plugin/ghidra/` 中的后端与 Java，不需要配置系统 JDK；该后端不增加独立插件 Tab。插件元数据、构包步骤、校验和许可证边界见 `GhidraRuntimePlugin/README.md`。

## 高级自定义运行环境

从 [Ghidra 官方发布页](https://github.com/NationalSecurityAgency/ghidra/releases/tag/Ghidra_12.0.4_build)解压 Ghidra 12.0.4，安装或解压 JDK 21 或兼容的更高版本。此版本的 [application.properties](https://github.com/NationalSecurityAgency/ghidra/blob/Ghidra_12.0.4_build/Ghidra/application.properties)明确要求 Java 最低 21。配置按钮选择的是 Ghidra 根目录，下面应存在 `Ghidra/Framework/Utility/lib/Utility.jar` 和 `Ghidra/application.properties`。

也可在启动 KSword 前设置：

```powershell
$env:KSWORD_GHIDRA_DIR = 'D:\Tools\ghidra_12.0.4_PUBLIC'
$env:KSWORD_GHIDRA_JAVA = 'D:\Tools\jdk-21\bin\java.exe'
```

显式指定 `KSWORD_GHIDRA_JAVA` 时使用该 Java 路径。默认安装的 Ghidra 插件使用其随附 JDK；显式自定义目录可按 `JAVA_HOME`、`JDK_HOME`、`PATH` 查找兼容 Java。未指定 Ghidra 时优先发现已安装且通过验证的后端插件，并保留主程序目录下 `tools/ghidra/`、`ghidra/` 的高级兼容入口。源码仓库只包含安装配置和胶水，不提交大型运行时。首次反编译需要启动 JVM 并编译适配脚本；耗时受运行环境影响。

## 输入与跳转

- PE 文件传入扫描时捕获并在组件内暂存修改后的**完整文件字节**，不重新打开原文件路径。组件把选中的文件偏移转换成 RVA，再加 PE ImageBase 得到 VA。只有唯一、具有实际文件内容的节映射可以启动 PE 反编译；头部、BSS、覆盖区以及重叠歧义映射明确拒绝。
- 通用内存、物理内存或没有 PE 布局的文件片段作为 RAW 字节导入，偏移 0 映射到组件显示基址。没有 PE 符号和入口点信息时，选中地址被当作候选函数起点，界面明确提示函数边界是推断结果。中途选中指令不能保证自动找回真正函数起点。
- 目前支持 x86 与 x64。PE Machine 和 OptionalHeader 必须与所选架构一致，其他架构不会按 x86 误解码。
- C 页的可跳转行来自 Ghidra `ClangStatement` / `ClangToken` 中的真实指令地址。一个 C 语句可能关联多条指令，组件使用该行所属函数内的最小地址；声明、空行和没有地址的行不伪造跳转。C 是恢复的伪代码，无法还原原始变量名、宏、注释和全部类型。

## 资源与生命周期

每次分析在随机临时目录创建样本副本、Ghidra 项目、脚本、配置和缓存；分析结束或取消后删除整个临时目录。JVM 通过 `QProcess` 直接启动，参数作为数组传递，不经过 `cmd.exe` 或批处理字符串展开。Windows JobObject 将 JVM 及其原生反编译子进程放入同一取消范围，超时、取消和组件销毁会终止这组进程。

RAW 输入最多 16 MiB，完整 PE 输入最多 64 MiB。默认总超时 120 秒，调用者可在 10–300 秒内设置；JVM 最大堆为 1 GiB，分析使用最多 2 个 CPU。C 文本最多 1 MiB，JSON 结果最多 4 MiB，进程或单个日志最多 8 MiB；诊断保留最后 256 KiB。分析程序的 PDB 选项关闭，避免根据样本内的调试路径加载或下载外部符号。

输入快照 SHA-256、选中 VA 和协议版本都必须与输出吻合。组件的快照代次、来源、架构或分析上下文改变时，取消分析并拒绝旧结果。因此不会把旧文件或旧内存的 C 代码显示为新的分析结果。刷新与写回仍由原有组件所有者控制，反编译器只有快照副本。

## 许可证边界

KSword 当前是 Community Source License 1.6，不能把要求整个结合物使用 GPL 的反编译器直接编入或复制进主程序。本后端使用 Apache 2.0 的 Ghidra 公开接口与独立运行环境，未引入 GPL 反编译器，也未更改 KSword 的许可证。依据 KSword 第 9.3–9.5、16.4 条与 Apache 2.0 的独立组件、保留通知规则，各组件保持原有许可。

主程序适配说明与原始 Ghidra 通知在 `third_party/ghidra_headless/`；独立插件的组合许可、完整 KSword 胶水许可及原始通知在 `GhidraRuntimePlugin/`。安装器直接下载原发布者的未修改运行环境，完整保留 Ghidra `licenses/`、`GPL/`、模块许可与 JDK `legal/`，不会把 JDK 的 GPL v2 + Classpath Exception 改成主程序许可证。若今后重新发布包含二进制运行环境的合并包，仍需满足具体组件的通知和对应源码提供义务，不能仅复制 Apache 许可证或 JDK 的 Java `src.zip` 代替完整审计。主程序发行包和源码仓库不内置这两个大型运行时。

协议夹具回归仅验证组件与异步进程协议。实际 Ghidra 运行时回归另用 `tools/tests/ghidra_decompiler_backend_tests.cpp`，运行脚本是 `tools/Invoke-GhidraBackendTests.ps1`，支持 `-GhidraDirectory`、`-JavaExecutable`、`-QtRoot` 参数；`-BuildOnly` 只构建，`-TestArguments '--pe-only'` 只重跑 PE 实际分析与取消，`'--validation-only'` 只验证输入拒绝规则。脚本使用独立 MinGW/UCRT QtCore 夹具，实际运行结果与协议夹具结果分别记录。

2026-10-08 已使用官方 Ghidra 12.0.4、JDK 21.0.12.1 和独立 QtCore 测试宿主执行通过：x64 高位无符号地址 `FFFFF80000001000` 的类型化加法 C、修改快照后的减法 C、条件分支 `if`、x86 栈参数 C、PE 函数中间地址定位与行地址映射，以及实际 JVM 异步取消。还验证了节对齐填充、ARM64/架构不符、重叠映射、BSS、截断 PE、64/32 位 RAW 地址溢出和空快照均明确拒绝。最终节映射边界修改后单独重跑 PE 与取消均通过，所有请求目录完成清理。本证据不替代生产 MSVC/Qt 主程序构建、真实 GUI 集成或驱动加载验证。
