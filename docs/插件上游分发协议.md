# 插件上游分发协议：upstream-assets

`upstream-assets` 让客户端从原发布者的 GitHub Release 下载完整 ZIP。`KSwordDEV/Plugins`
维护版本、发布者仓库、下载 URL、文件 SHA-256、目录映射和插件清单，不托管这些运行环境的二进制。
分发方式与 `command`、`tab`、`hybrid`、受支持的 `backend` 运行协议独立。

完整 Ghidra/JDK 条目见 [`GhidraRuntimePlugin/marketplace-entry.json`](../GhidraRuntimePlugin/marketplace-entry.json)。
[`PluginMarketplace/catalog.json`](../PluginMarketplace/catalog.json) 是客户端初始目录快照；将其中条目并入
`KSwordDEV/Plugins/catalog.json` 即可由在线市场维护。在线有效条目按 `id` 覆盖快照。

## 市场条目

市场 API 仍为字符串 `"1"`。公共字段 `id`、`name`、`version`、`description`、`targets`、
`install_directory`、`license_name`、`license_url` 保持不变。新条目用 `distribution` 替代
单包的 `archive_url`、`sha256`；旧条目不写 `distribution`，继续走原 ZIP 安装流程。

```json
{
  "id": "vendor-tool",
  "name": "Vendor Tool",
  "version": "1.0.0",
  "description": "A process-isolated upstream tool.",
  "targets": ["process"],
  "install_directory": "vendor-tool",
  "license_name": "Upstream license",
  "license_url": "https://raw.githubusercontent.com/OWNER/REPOSITORY/v1.0.0/LICENSE.txt",
  "distribution": {
    "type": "upstream-assets",
    "platform": "windows-x64",
    "manifest": {
      "ksword_plugin_api": "1",
      "id": "vendor-tool",
      "name": "Vendor Tool",
      "version": "1.0.0",
      "description": "A process-isolated upstream tool.",
      "targets": ["process"],
      "runtime": "executable",
      "entrypoint": "payload/VendorTool/Tool.exe",
      "default_command": "info",
      "license": "LICENSE.txt"
    },
    "assets": [
      {
        "name": "Vendor Tool",
        "repository": "OWNER/REPOSITORY",
        "url": "https://github.com/OWNER/REPOSITORY/releases/download/v1.0.0/tool-windows-x64.zip",
        "sha256": "REPLACE_WITH_64_HEX_DIGITS",
        "root_directory": "VendorTool",
        "destination_directory": "payload",
        "max_archive_bytes": 268435456
      }
    ],
    "metadata": [
      {
        "path": "LICENSE.txt",
        "url": "https://raw.githubusercontent.com/OWNER/REPOSITORY/v1.0.0/LICENSE.txt",
        "sha256": "REPLACE_WITH_64_HEX_DIGITS",
        "max_bytes": 65536
      }
    ]
  }
}
```

示例中的 owner、仓库、文件与哈希为占位符。维护者必须核对原发布者身份、实际 ZIP 布局及插件协议；
声明 `repository` 不会自动将一个 GitHub 仓库认证为官方。下载器验证 URL 与该声明逐字一致。
直接启动的程序仍必须实现 KSword 插件运行协议；此分发协议不会自动把任意上游程序变成插件。

## 字段与限制

| 字段 | 约束 |
| --- | --- |
| `type` | 固定 `upstream-assets`，未知类型拒绝。 |
| `platform` | 首版固定 `windows-x64`。 |
| `manifest` | 安装时生成的 `plugin.json`；身份、版本、名称、描述和能力与市场字段一致。 |
| `assets` | 1–8 个完整 ZIP；URL 必须是声明仓库的固定 Release 标签，禁止 `latest`。 |
| `repository` | 原发布者的 `owner/name`。 |
| `sha256` | 下载文件原始字节的 64 位十六进制 SHA-256，不是 URL 字符串的哈希。 |
| `root_directory` | ZIP 唯一顶层目录；不移除该目录。 |
| `destination_directory` | 插件目录内的落点；各资源不能相同或嵌套。 |
| `max_archive_bytes` | 正整数，最大 1 GiB；展开上限为其四倍且不超过 4 GiB。 |
| `metadata` | 1–16 个固定哈希的小型文本，单文件最大 1 MiB。允许 `.txt`、`.md`、`.json`、`LICENSE`、`NOTICE`。 |
| `metadata.url` | 已声明的上游仓库、`KSwordDEV/Plugins` 或 `KSwordDEV/KSword` 的 HTTPS raw 文件。推荐不可变提交或固定标签。 |
| `manifest.license` | 必须指向一项元数据，且其 URL 必须等于市场 `license_url`。 |

整个分发对象不超过 64 KiB。路径排除绝对路径、穿越、Windows 保留名称、结尾空格/点和控制字符。
清单、回执、元数据和各组件目录不能互相覆盖。运行入口必须位于官方 ZIP 树中。

初始下载只允许指定 GitHub Release URL。跳转限于 HTTPS GitHub Release CDN，最多五次；
不能跳到其他 GitHub 仓库、任意官网或镜像。raw 元数据不允许跨 URL 重定向。

## 安装和更新

1. 解析市场条目，核对平台、URL、仓库、路径、预算和清单一致性。
2. 下载并校验许可证哈希；展示全文，用户同意后才下载载荷。
3. 为该插件取得安装锁，在插件根目录建立私有暂存区。
4. 逐项流式下载、限量、验 SHA-256；完整检查 ZIP 条目后解压。
5. 保留 ZIP 中所有文件。下载并验证元数据，生成 `plugin.json` 与 `upstream-install.json` 回执。
6. 用现有清单/后端结构验证器检查整个目录，成功后以现有事务替换旧版本。

任何资源失败、超限、取消或清单验证失败，都清理暂存区并保留旧安装。安装阶段不执行插件、
Java、样本或远程安装脚本。同一插件的并行安装互斥。

上游分发插件只由用户点击安装/更新，不进入普通 ZIP 插件的已授权自动更新队列。
客户端比较市场固定的包 `version`，不查询上游 `latest`。

## Ghidra/JDK

Ghidra 的 `plugin_type=backend`、`runtime=ghidra` 和 `targets=["decompiler"]` 保持不变。
市场清单额外声明 `runtime_version`、`java_version`、`runtime_root` 和 `java_executable`。
包版本可独立递增，例如仅更新 JDK 时仍需提高包 `version`，使更新检查能够发现变化。

安装器将 Ghidra 和 JDK 当作同一通用事务中的两个资源。后端按已安装清单读取路径，验证实际
Ghidra/JDK 版本、amd64 架构和许可文件。历史固定版本包继续兼容；参考离线构包配置仍保留在
`GhidraRuntimePlugin/runtime-assets.json`，生产下载不再读取它作为固定 URL 来源。

维护者升级时需同步组件 URL、哈希、ZIP 根目录、运行路径、实际版本及相关许可证/说明的 URL 和哈希。
首次快照中的元数据来自已经核验的不可变 KSword 源码提交；无需向 plugins 仓库上传 Ghidra/JDK ZIP。

## 回归验证

已初始化 x64 MSVC 开发环境时，可以使用仓库 Qt 和已有输出目录：

```powershell
tools/Invoke-GhidraPluginPortableTests.ps1 -UseMsvc `
  -QtRoot .deps/Qt/6.9.3/msvc2022_64 -OutputDirectory output
```

测试直接链接生产分发解析器、下载器和后端验证器，提取生产市场/事务解析函数。
本地 URL 仅存在于测试编译入口；ZIP 含惰性夹具，不执行 Java/Ghidra 或样本。
