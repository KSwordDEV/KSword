# 操作心智模型审查

本轮覆盖用户指定的三类：进程/文件/注册表操作、各类工具的参数与执行、全局导航及结果查看。以完整流程“找到入口 → 选择对象/范围 → 设置参数 → 明确执行 → 确认结果来源 → 失败后恢复”为检查单位，不以共享控件调用次数代替可用性判断。

用户禁止操作窗口自动化测试。本轮仅修改及检查源码、执行适用的非 GUI 检查和构建；实际交互、深浅主题、窄窗和 DPI 效果由用户手动验收。

## 规则与用途

- 范围是层级目录时提供可展开的目录树；目标是单文件时使用带类型过滤的文件选择器；源数据必须来自整卷时使用卷选择。结果路径摘要不能充当范围选择器。
- 选择和参数编辑默认形成待执行意图；有系统副作用的动作须明确显示动作名称、对象和执行时机。
- 批量动作直接说明对所选集合执行什么，不用首行的勾选状态代表混合集合。
- 结果以发起请求时的对象、范围、来源和时间解释；控件里的新输入不重写旧结果身份。
- 成功空结果、未加载、进行中、部分完成和失败分别呈现。失败保留原因与重试路线，不能画成叶节点或成功的零条记录。
- 复制已有数据只依赖可读值；执行、写入和破坏动作仍遵守各自的身份与权限要求。
- 未保存的编辑草稿与列表选择/刷新分离；恢复动作回填原任务参数后，仍需用户明确执行。
- 共享组件承担外观、布局和公共行为；页面按实际用途选择树、列表、输入、编辑器、执行器和结果视图。

## 源码与边界

- 空间/文件入口：`FileDock/DiskSpacePage.*`、`DirectoryScopePicker.*`、`DirectorySpaceScanner.*`、`FileDock.cpp`；共享适配 `UI/ParameterWorkspace.*`。初阶段详情见[空间分布独立页面](空间分布独立页面.md)。
- 进程操作：`ProcessDock/ProcessDock.cpp`、`ProcessDetailWindow.Module.cpp` 及同模块状态回执实现；以进程创建时间、模块身份和真实选中集合为边界。
- 注册表：`RegistryDock_Themed.cpp`、`RegistryDock/RegistryDock.Search.cpp`；区分当前导航、搜索请求与结果身份。
- 设备：`HardwareDock/HardwareDeviceManagerPage.*`；读取接口的错误与正常枚举结束分别检查，不扩大为真实设备写操作验证。
- 参数工具：`MiscDock/VirtualLocation/VirtualLocationPage.*`、`MiscDock/RenderBenchmark/RenderBenchmarkPage.*`；网络相关源码按各页面实际入口核对。
- 全局搜索：`Framework/CustomTitleBar.cpp`、`UI/GlobalUiSearch.*`；只改可见范围、结果与恢复反馈，保留原搜索及命令执行边界。

这是本轮实际查到的问题清单。三个类别均有具体流程覆盖，但未逐页检查的存量页面不标记为通过；源码审查也不代表全部实机交互已验收。
