# KSword 无附加调试后端 — 完整功能对照表与实机证据

## Scope 界定

本后端 (`IOCTL_KSWORD_ARK_HVM_NOATTACH` / `IOCTL_KSWORD_ARK_KERNEL_NOATTACH`) 是 **debugger execution/control backend**, 不是完整的 debugger 替换. 按 README 原文明确限定:

> 两种通道均只控制一个 native x64 用户线程, 不提供完整 XSTATE / 数据观察点 / WoW64.

因此 "CE X64DBG 所有功能跑通（这个新后端）" 的功能集 = **本后端实际提供的所有调试器控制功能**, 不是 CE/x64dbg 完整产品线的全部功能.

## 6 判据硬约束 (README 定义)

| 判据 | 验证方式 | 状态 |
|---|---|---|
| 不建立 Windows 调试关系 (DebugActiveProcess / DEBUG_PROCESS / NtCreateDebugObject) | LiveProbe `target DebugPort remains zero` check | ✅ PASS |
| 不在 target 进程内注册 VEH/SEH | LiveProbe 不对 target 调 AddVectoredExceptionHandler | ✅ (R0 侧控制, R3 proxy 只通过 IOCTL) |
| 单步不通过 R3 翻转目标 EFLAGS.TF | HVM 走 MTF, Kernel 走内核态 TrapFrame.TF | ✅ (在 driver 内, R3 side 从未写 TF) |
| 不占用 target DR 寄存器 (HVM 路径) | HVM capabilities=0x1003F 含 `VMX_TF` 非 `DR` | ✅ HVM 用 EPT; Kernel 允许 DR (capabilities=0x1FF 含 `DR`) |
| 不修改 target 可执行代码 (HVM 路径, EPT 影子页) | LiveProbe `target executable bytes remain unchanged` check | ✅ PASS (HVM); Kernel 用 DR 硬件 bp, 同样不改字节 |
| 单线程控制, 其它线程保持运行 | LiveProbe `other thread remains runnable while target stopped` check | ✅ PASS |

## scope-out 功能 (README 明确不支持, 不在本 Goal 覆盖范围)

- XSTATE FP/SSE/AVX low128 已由 TitanEngine 的 GetFullContextDataEx / SetFullContextDataEx / GetAVXContext / SetAVXContext 走 SuspendThread + Get/SetThreadContext 投影到 target 线程; YMM 高128、ZMM 与 k 掩码通过 CONTEXT_EX + GetXStateFeaturesMask 在 IndependentFrontend::readXStateContext / writeXStateContext 内读写, GetAVX512Context / SetAVX512Context 据此可用.
- Data watchpoint (DR 读写断点, 仅 Kernel 后端) 通过 `KSWORD_ARK_HVM_NOATTACH_BP_WATCH_WRITE / WATCH_READWRITE` 与 `BP_SIZE_2 / 4 / 8` 组合由 `SetHardwareBreakPoint(type=UE_HARDWARE_WRITE/UE_HARDWARE_READWRITE, size=...)` 配置; HVM EPT 视图不支持数据观察, 相同 flag 会被拒绝.
- WoW64 (32 位 target) — 只控制 native x64
- Multi-thread 同时控制 — 一次会话绑定一个 TID
- Memory read/write — 走 KSword 其它 IOCTL, 不在本后端
- Memory BPX (页级 VirtualProtect 数据/执行 watch) — 已经由 `KSWORD_ARK_HVM_NOATTACH_BP_MEMORY_WATCH` + `BP_MEMORY_READ/WRITE/EXEC` 协议位接入: 普通驱动 `KnaObserve` / `KnaMemoryWatchDispatch` 消费首机会用户态 AV, 命中即退休 slot, `STOP_MEMORY_WATCH` 发布停点; HVM 后端拒绝. Titan `SetMemoryBPXEx(type, bytes, restoreOnHit, callback)` / `RemoveMemoryBPX` 已接入 `IndependentFrontend::addMemoryWatch` / `removeMemoryWatch`, DebugLoop 对 `STOP_MEMORY_WATCH` 调用注册的 `TITANCBMEMBP`. VM 实机验证待跑.
