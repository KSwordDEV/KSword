# 无附加、无目标注入执行后端

## 范围与当前状态

“无附加”指后端不建立或借用 Windows 用户态调试关系；“无目标注入”指不向目标安装 DLL、VEH 或执行控制组件。两种后端分别报告实际机制，不能把普通 Titan/CE 的 Windows 调试循环当成独立停止通道。

当前已落地的 HVM v2 只控制一个强身份绑定的 native AMD64 用户线程：EPT 执行断点、MTF 边界单步、继续、一次性运行到地址，以及 GPR/RIP/RSP 编辑。其它线程和内核保持可运行。完整 XSTATE、数据观察点、WoW64、AMD 以及完整前端 F7/F9 调试循环尚未由此通道提供。

普通驱动异常后端正在独立实现。它使用 TF/DR 与内核异常消费者；不以 HVM 不可用时静默改成普通 Windows 附加的方式实现。

## HVM v2 结构

- 唯一协议：`shared/driver/KswordArkHvmNoAttachIoctl.h`。请求 232 字节，响应 480 字节，版本 2；旧版必须成套升级。
- 会话由确切设备文件、所有者对象、PID/TID 和各自创建时间绑定。执行与修改必须消费匹配的 `sessionId/stopId`。
- 最多八个执行地址。两个预分配 EPT bank 在普通控制面重建；每次发布配置后经全核屏障，逐核在使用新代次之前 INVEPT，旧 bank 才可重用。
- 同页其它指令及其它线程通过当前 CPU 的普通 EPTP 临时放行，下一次退出恢复受限视图。不会临时放宽共享叶子而让其它核一起通过。
- 安装时锁定 backing，查询重新探测 VA/PFN。映射变化明确标为失效，要求删除后重装；不静默迁移至新代码。会话累计锁页容量为 64，成功全核退出后统一归还。
- MTF 恢复和用户单步分别记账。中断、异常或不匹配线程不报告单步完成；`STOP_STEP` 表示已核对的 MTF 边界，REP 等特殊边界不保证 RIP 一定改变。
- GPR 修改在下一次匹配取指处提交，并生成新的 `STOP_CONTEXT`。不编辑 RFLAGS、DR、SIMD/XSTATE。
- 关闭失败保留恢复身份。所有者/目标退出及文件 Cleanup 撤销当前执行权，不以历史 ring 冒充当前停止。

## GUI 与操作身份

入口为 **内存 → 内存调试 → HVM 无附加调试（实验）**。

原页面属于专业内存/反汇编工作台，外围复用 PrimaryPageStyle、NormalizeToolbarRow，内部控件身份和滚动不由通用框架重排。新增“无附加调试 · 断点与寄存器”工具窗属于参数/执行页，使用 ParameterWorkspace，并以 SecondaryPageLayout 管理独立工具窗主题。断点表显式选择 Compact 操作条，使用 TablePresentation/ResultTableHost。寄存器查看沿用同一 StructuredFieldView 文档与详情投影。

流程为：选定进程和线程 → 只读查询能力 → 显式确认开启 → 请求暂停 → 等待真实停点 → 编辑断点或寄存器草稿 → 明确提交/运行 → 根据新停点确认结果。工具窗关闭不自动继续目标；显式关闭运行控制保留独立内存会话。旧会话的工具草稿不能操作另一个会话。

源码对照了 SystemTimePage、VirtualLocationPage、ParameterWorkspace 及既有 MemoryDebugPage/ExecutionPanel。构建与 GUI 结构验证不能替代深浅主题、窄窗、DPI、背景模式和实际执行的完整验收。

## x64dbg / CE 接口

`KSwordDebuggerCall` 命令 **33 / KSWORD_DEBUGGER_NOATTACH** 使用独立的持续控制句柄。命令 3 可在离线状态查询此命令的大小与版本；调用新通道不会初始化 Titan 的 Windows 调试事件适配。当前不允许与该适配器已有原生会话、EPT/Shadow 绑定混用。

CE 使用 `KSword.noAttach.query/open/pause/step/continue/close/addBreakpoint/removeBreakpoint/runTo/setRegister`。`open` 必须显式传入确认。请求接受和完成由 `state/stopId` 区分，非停止响应不暴露历史寄存器为当前现场。

独立 x64dbg 插件为 `KSwordNoAttach.dp64`，提供 `ksna_open PID, TID, confirm [, nested]`、`ksna_query/pause/step/run/close`、`ksna_bp`、`ksna_bc`、`ksna_runto`、`ksna_set`。PID/TID/ID 使用十进制，地址/值使用十六进制。其控制结果在日志显示，原生 x64dbg F7/F9 和 CPU 窗口仍使用原生引擎语义；此插件不把自有停止伪装成原生调试事件。完整 CPU/寄存器前端投影仍需后续适配。
