# 权限工作台

权限 Tab 将本地账号、组成员、权限策略和进程令牌放在同一个工作台中，便于追查权限来源、比较运行身份和解释访问失败。新增页面按需加载；枚举和新页面的 Windows 查询在后台执行。

| 页面 | 用途 |
| --- | --- |
| 账号 → 账号管理 | 查询本地账号、启用/禁用、查看所选账号所属组，并跳转关联页面 |
| 账号 → 创建与重置 | 保留原有创建本地用户、重置密码工具 |
| 权限 | 保留原有用户、组和 KSword 自身特权概览 |
| 用户组 | 组内成员、账户所属组、成员加入/移除 |
| 权限分配 | 账户自身及其组的 LSA 权限来源、直接分配反查及编辑 |
| 令牌对比 | 比较两个实际进程的令牌 |
| 访问诊断 | 查询对象安全描述符，结合令牌评估所需访问权限 |
| 登录会话 | 查看登录身份及按登录 LUID 关联的进程 |
| 指定身份启动 | 普通用户、管理员、SYSTEM、TrustedInstaller 启动及实际令牌对比 |
| 权限快照 | 手动采集、保存、加载和比较权限证据 |

## 1. 用户与组管理

在“账号 → 账号管理”中刷新本地账号，按名称、SID、状态或说明搜索。选择账号后，下方列出直接和间接所属的本地组；“查看用户组”“查看权限分配”“查看登录会话”将所选账号的 SID 传给目标页面，避免仅按显示名称关联。

启用或禁用账号时，预览显示账号、SID 和前后状态。确认后后台修改账号禁用位，并回读验证；其他账号标志保留。变更已提交但回读失败或不一致时，会明确提示，请重新刷新检查。创建用户和重置密码仍位于“创建与重置”子页，沿用原有提权和确认流程。

在“用户组”中刷新组列表，选择组查看成员。列表会继续读取 Windows 返回的分页数据，而不会只展示第一页。输入账户名或 SID 后可加入所选组；选择成员后可移除。变更预览展示组 SID 和成员 SID，确认后应用并回读成员关系。

页面下方支持“账户 → 所属本地组”查询。直接成员和经全局组继承的间接成员分别标明；直接查询不完整时显示来源未知，不能据此断言仅有间接关系。双击所属组可定位到上方对应组。组、成员和账号表支持搜索以及右键复制 SID、复制行。

## 2. 用户权限分配

“权限分配”左右分区展示本机 LSA 策略分配，支持三种查询：

- 输入用户、组或服务身份的账户名/SID，查询该 SID 的直接策略权限。
- 左侧选择“账户 → 自身及其组权限”，汇总自身及可解析本地组的分配。同一权限按来源 SID 分别保留；A 显示权限、说明及来源，B 显示权限、来源 SID 及一条成员关系路径。
- 选择权限名称，查询被直接分配该权限的账户；双击账户可回到该 SID 的权限查询。

左侧两个查询按钮并排显示；右侧反查、分配和移除三个按钮并排显示。两侧分别搜索、分别显示查询状态。改变账户或权限输入会清除对应旧结果；本地组关系递归去重，域组、动态登录组及采集失败的关系不保证完整，页面会提示范围限制。

目录包括交互、网络、批处理、服务、远程桌面登录权限，相应的拒绝登录权限，以及调试、加载驱动、备份、恢复等特权。登录权限提供说明，特权说明来自 Windows。

“分配此权限”“移除此权限”位于右侧权限选择下方的固定操作区，目标预览同时显示左侧账户与右侧权限。只修改输入账户自身的直接分配，不会修改汇总结果中的来源组。分配和移除前会解析账户 SID、查询当前直接分配状态并显示变更预览；确认后修改 LSA 策略并回读。已处于请求状态的分配不会重复修改。

直接策略分配与实际进程令牌是两类证据。组继承、登录类型、拒绝登录策略、UAC 和令牌限制可能改变实际结果。修改策略不会立即改写已有进程令牌；需要新的登录/令牌后，再用“令牌对比”检查实际效果。此页不会把“账户直接分配为空”解释为账户没有任何有效权限。

## 3. 令牌对比

选择进程 A 和进程 B，也可以输入 PID，然后刷新令牌。进程身份以 PID 和创建时间复核，避免已退出进程的 PID 被复用后误关联。支持只看差异和文本筛选。

比较字段包括用户、所有者、主组、普通组及属性、启用/拒绝专用组、受限 SID、特权及启用状态、完整性级别、提升类型、UIAccess、AppContainer、会话编号和登录 AuthenticationId。可读取时也展示关联令牌字段。

无法读取、确实不存在和已读取的字段分别表达。访问被拒绝或进程退出时显示采集错误，不能把空结果理解为两个令牌相同。需要进一步检查进程时，可从相关页面打开进程详情。

## 4. 访问权限诊断

选择目标进程令牌、对象类型和目标，再选择所需操作或访问掩码。支持文件、注册表键和服务；注册表目标需要明确根键，服务目标使用服务名称。页面展示所请求权限、映射后的访问掩码、安全描述符及 ACE 证据，并结合完整性级别提示潜在限制。

结果需要按证据层理解：

| 证据 | 含义 |
| --- | --- |
| 描述符检查 | 使用取得的安全描述符和令牌评估所请求权限；保留允许/拒绝 ACE 及其顺序、属性和 SID |
| 完整性提示 | 结合对象标签、令牌完整性和强制策略提示可能的向上访问限制；标签或策略不可读时明确提示 |
| 实际打开探测 | 在页面启用相应探测后，尝试以请求权限打开对象句柄并关闭，记录实际调用结果 |

描述符评估通过不保证实际操作成功。文件共享占用、路径遍历、对象状态和其他 Windows 检查可能影响实际打开；反之，失败的安全描述符读取也不等于所需操作必然被拒绝。实际句柄打开成功只证明那次打开请求成功，不证明后续读写、执行或服务操作已经完成。诊断不修改对象 ACL、文件内容、注册表值或服务配置。

## 5. 登录会话与进程关联

刷新后，上方显示账号、SID、登录 LUID、登录类型、登录时间、认证包、终端会话编号和关联进程数。可按账号、SID 或登录 LUID 搜索。

选择登录会话后，下方筛选对应进程；“显示所有关联进程”恢复总览，下方还可搜索进程名、PID 或查询错误。双击进程或使用“打开进程详情”进入详情，打开前复核进程身份。从账号管理跳转时按该账号 SID 精确定位，可读结果中没有对应会话会明确提示。

关联依据是进程令牌 `AuthenticationId` 与 LSA 登录 LUID。WTS/终端会话编号只作为显示字段：同一终端会话可能有不同登录身份，不能用这个编号替代登录 LUID。令牌不可读的进程、LSA 未枚举的身份和已退出进程保留错误/未关联状态，不会被静默并入某个账号。

## 6. 指定身份启动

选择存在的 `.exe` 文件，输入参数并选择普通用户、管理员、SYSTEM 或 TrustedInstaller。工作目录固定为程序所在目录。页面先检查身份可用性，不可用身份禁用，可重新检查。

管理员启动使用 Windows UAC；SYSTEM/TrustedInstaller 需要当前 KSword 已提升，TrustedInstaller 模式可能启动相应服务。启动确认明确列出身份、程序和参数。程序会立即运行，因此应由用户交互确认实际需要启动的程序。

启动成功后显示实际子进程 PID、账号、SID、提升状态、完整性和令牌字段。请求身份是输入，实际子进程令牌才是结果；如子进程快速退出、无法读取或身份无法复核，会显示验证不完整。“再启动普通用户实例并对比”会再运行一个实例，保留两份令牌供比较；刷新时仍按原 PID 和创建时间检查身份。

## 7. 权限快照

快照按用户请求手动采集，不进行周期监控。采集账号状态、组成员和直接 LSA 权限分配；可选择是否包含指定 PID 的令牌。

1. 选择是否包含令牌及目标 PID，点击“采集设为基线”。
2. 完成需要观察的操作后，点击“采集当前并对比”。
3. 可分别保存基线/当前 JSON，之后加载重新比较；文本框筛选条目、原值或现值，支持复制当前差异。

差异包括新增、移除、修改、启用、禁用和无法确认。比较保留 JSON 值类型，字符串 `"1"` 和数字 `1` 不会合并。账号与成员关系以 SID 建键，显示名称变更不会改变其身份键。

采集错误作为证据保存在快照中。采集不完整时，缺失项标为无法确认；字段不可读也不被断言为权限变化。两份快照必须来自同一计算机，并使用相同的令牌采集选项。读取限制、未知版本、重复键、非标量值、非法状态或超限文件会被拒绝；JSON 导入上限为 64 MiB。快照用于证据比较，不会还原、执行或自动应用其中的权限。

## 复现检查

下面的命令从仓库根目录运行。便携检查使用 Windows MinGW 版 Qt 6.9.3 和 `g++`；`$qtDir` 应指向实际 `mingw_64` 目录，不能用 MSVC 版 Qt 替代。检查产物写入单独目录。

```powershell
$qtDir = 'C:\path\to\Qt\6.9.3\mingw_64'
$testOutput = '.codex-build-logs\privilege-workbench'
python tools\privilege_workbench_test.py --qt-dir $qtDir --output-dir $testOutput
```

该入口严格编译实际页面、后台查询、快照模型及语言/主题代码，执行只读收集、差异与页面生命周期检查，并输出离屏截图。它不执行账号、组、策略写入，也不启动管理员、SYSTEM 或 TrustedInstaller 测试程序。

账号分页及 SID 导航夹具可单独编译：

```powershell
New-Item -ItemType Directory -Force -Path $testOutput | Out-Null
$qtIncludeArgs = @()
foreach ($part in @('include', 'include\QtCore', 'include\QtGui', 'include\QtWidgets')) {
    $qtIncludeArgs += @('-isystem', (Join-Path $qtDir $part))
}
$testCompileArgs = @('-std=c++23', '-Wall', '-Wextra', '-Werror', '-Wno-unknown-pragmas', '-DNOMINMAX', '-DUNICODE', '-D_UNICODE') + $qtIncludeArgs
g++ @testCompileArgs tools\privilege_accounts_tests.cpp Ksword5.1\Ksword5.1\Internationalization\LanguageManager.cpp Ksword5.1\Ksword5.1\UI\ThemeStatusRole.cpp -L "$qtDir\lib" -lQt6Widgets -lQt6Gui -lQt6Core -lnetapi32 -ladvapi32 -o "$testOutput\privilege_accounts_tests.exe"
$env:PATH = "$qtDir\bin;$env:PATH"
$env:QT_QPA_PLATFORM = 'offscreen'
$env:QT_PLUGIN_PATH = "$qtDir\plugins"
& "$testOutput\privilege_accounts_tests.exe"
```

访问检查夹具只使用内存中的安全描述符和隔离测试令牌，不修改实际对象：

```powershell
g++ -std=c++23 -Wall -Wextra -Werror -Wno-unknown-pragmas -DNOMINMAX -DUNICODE -D_UNICODE tools\privilege_access_tests.cpp -ladvapi32 -lauthz -o "$testOutput\privilege_access_tests.exe"
& "$testOutput\privilege_access_tests.exe"
```

账号分页夹具已在本机通过 229 项只读检查，覆盖 7 个账号、22 个组及异步页面销毁；全局 LSA 权限枚举返回 `Access is denied (code=5)`，该错误保留在快照中。受限运行令牌也可能使 `NetUserEnum` 返回错误 5，应记录实际权限环境，不将失败说成完整采集。具体检查结果以本次命令输出为准。

独立检查不替代仓库规定的主程序 MSVC/Qt 构建。主程序构建仍使用 `tools\Invoke-KSwordBuildCheck.ps1` 和 `AGENTS.md` 指定的 x64 工具链。实际账号/组/LSA 策略写入、UAC 交互及高权限身份启动，需要用户在目标 Windows 环境中交互使用和验收；当前只读与隔离夹具不构成这些操作已通过实机验收的证据。
