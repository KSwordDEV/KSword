# 构建与发布

本页按当前工程、`AGENTS.md` 与构建脚本核对（2026-10-05）。命令均从仓库根目录执行，发布产物统一在 `Ksword5.1/x64/Release/`；贡献规则见 [CONTRIBUTING](../CONTRIBUTING.md)。

## 工具链与依赖

- Windows x64、Visual Studio 2022 / Build Tools 的 v143 C++ 工具链和 Windows SDK；驱动另需匹配的 WDK。
- **64 位 MSBuild 和 HostX64 编译/链接工具**。默认入口为 `C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\MSBuild\Current\Bin\amd64\MSBuild.exe`。不要因为安装目录名含 `(x86)` 而改用 `Bin/MSBuild.exe`。
- 主程序、Taskbar、HUD 使用 Qt 6.9.3 `msvc2022_64`，优先 `.deps/Qt/6.9.3/msvc2022_64/`，Qt/MSBuild 集成优先 `.deps/QtVsTools/msbuild/`。缺少依赖时按 `AGENTS.md` 约定的备用安装配置，不能降为 32 位入口。
- Python 用于 i18n、主题和 profile 构建门禁。PDB 工具另需其 [依赖说明](../tools/pdb_offset_generator/README.md) 中的 Python 模块和 `llvm-pdbutil`。

`Ksword.ReleaseOutput.props` 统一各 x64 Release 工程的最终目录；`IntDir` 仍由各工程管理。x86 API Agent 属于目标进程架构支持，和 x64 构建宿主是两个概念：主程序项目引用会构建 `APIMonitor_x86.dll`，并把它部署到同一发行目录。

## 主程序构建

先进入 x64 VS 开发环境，例如从 VS 的 **x64 Native Tools Command Prompt** 启动 PowerShell。Qt 部署需要 VS 的 `VCINSTALLDIR` / 运行库目录，不要只检查 exe 链接是否成功。

```powershell
& tools\Invoke-KSwordBuildCheck.ps1 -RepositoryRoot (Get-Location).Path -Action Build
```

该脚本会校验 MSBuild PE 体系结构，读回 `PreferredToolArchitecture` 与 `VC_ExecutablePath_x64`，确认 HostX64 后才构建；输出日志到 `.codex-build-logs/`。所有构建均同时传递：

```text
/p:PreferredToolArchitecture=x64
/p:PROCESSOR_ARCHITECTURE=AMD64
/p:PROCESSOR_ARCHITEW6432=AMD64
```

仅设置 `PreferredToolArchitecture` 可能被 MSVC 导入规则覆盖。完成应同时满足 `BUILD_RESULT=SUCCESS`、`EXIT_CODE=0` 和非空的 `Ksword5.1/x64/Release/Ksword5.1.exe`。Qt/VC 运行库部署失败仍是整体 Build 失败。

主程序工程自动执行 i18n/主题门禁、复制语言包、压缩 profile、增量部署 Qt，并构建 API Agent 与 DWM 排序 DLL 的项目引用。主程序默认还会尝试开发测试签名；制作明确标为未签名的包时使用 `-SkipAutoTestSign`，并核对最终文件签名状态。测试签名不等于正式发行签名。

### 链接器内部错误恢复

日志出现 `LNK1000`、`IMAGE::BuildImage` 或 `.iobj` 时，保持同一 MSVC x64 工具链，只执行一次干净重建，并仅为此次构建关闭 WPO/LTCG：

```powershell
& tools\Invoke-KSwordBuildCheck.ps1 `
  -RepositoryRoot (Get-Location).Path -Action Rebuild -DisableWholeProgramOptimization
```

开关通过临时 props 生效，不改工程。恢复成功后不要立即普通 Build；普通增量缓存会因 WPO 配置改变失效。需要读回产物时使用：

```powershell
& tools\Invoke-KSwordBuildCheck.ps1 -RepositoryRoot (Get-Location).Path -VerifyArtifactOnly
```

`MODE=ARTIFACT_ONLY` 只证明已有产物存在及其哈希，不能替代尚未执行的构建。只有上述恢复也失败后才考虑 VS servicing update 或并列 v143 工具集，不自动切换 LLVM、TargetName 或 MSVC 版本。

## 其他用户态组件

主程序检查通过后，构建与发行包匹配的 Launcher、轻量版、Taskbar、HUD、API Agent 和 CLI。以下示例使用首选依赖布局；每个命令均检查退出码：

```powershell
$msbuild='C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\MSBuild\Current\Bin\amd64\MSBuild.exe'
if (!(Test-Path -LiteralPath $msbuild)) { throw '请按 AGENTS.md 配置可用的 64 位 MSBuild。' }
$env:KSWORD_QT_DIR=(Resolve-Path '.deps\Qt\6.9.3\msvc2022_64').Path
$qtMsBuild=(Resolve-Path '.deps\QtVsTools\msbuild').Path
$hostToolArgs=@('/p:PreferredToolArchitecture=x64', '/p:PROCESSOR_ARCHITECTURE=AMD64', '/p:PROCESSOR_ARCHITEW6432=AMD64')
$projects=@(
  'Launcher\Launcher.vcxproj',
  'KswordARKLight\KswordARKLight.vcxproj',
  'Taskbar\Taskbar.vcxproj',
  'KswordHUD\KswordHUD.vcxproj',
  'APIMonitor_x64\APIMonitor_x64.vcxproj',
  'KswordCLI\KswordCLI.vcxproj'
)
foreach ($project in $projects) {
  & $msbuild $project /t:Build /p:Configuration=Release /p:Platform=x64 @hostToolArgs "/p:QtMsBuild=$qtMsBuild" /m:1 /v:minimal
  if ($LASTEXITCODE -ne 0) { throw "Build failed: $project ($LASTEXITCODE)" }
}
```

`Launcher/Launcher.vcxproj` 的 `GenerateLauncherSupportManifest` 在构建前从源 v4 pack 生成输出目录的支持清单。更新 profile 后要重新构建 Launcher，不能只换 exe 而保留旧清单。`KswordDwmZOrder.dll` 必须与主程序位于同一目录；`APIMonitor_x86.dll` 与 `APIMonitor_x64.dll` 要随同一套定义文件发布。

`tools/hvm_ctl/build.cmd` 可构建独立 HVM 实验探针；它不属于默认主程序发行内容。调试器插件、安装器和其它独立组件按各自项目说明构建。

## 驱动构建与后置验证

使用标准 MSVC/WDK，传递同样的三个宿主体系结构属性：

```powershell
$solutionDir=(Resolve-Path 'Ksword5.1').Path + '\'
& $msbuild 'KswordARKDriver\KswordARKDriver.vcxproj' /t:Build `
  /p:Configuration=Release /p:Platform=x64 "/p:SolutionDir=$solutionDir" `
  @hostToolArgs /m:1 /v:minimal
if ($LASTEXITCODE -ne 0) { throw "Driver Build failed: $LASTEXITCODE" }
```

完整 Build、SYS 编译/链接、ApiValidator、INF/CAT、签名和实际加载是独立状态。签名与加载诊断见 [测试签名脚本](../scripts/Sign-KswordArkDriverTest.ps1)，执行该脚本会修改文件签名或证书信任，不能用它替代只读的产物检查。

如果 SYS 已在链接阶段更新，而 WDK 后置阶段误选 ARM64 验证器或没有子进程地卡住，先记录精确 MSBuild PID/命令行，确认失败在链接之后且没有活动 `cl.exe`、`link.exe`、`ApiValidator.exe`、`aitstatic.exe` 子进程，再停止唯一卡住的 MSBuild。不要把被中止的 Build 报为成功。对刚链接的 SYS 使用本机 WDK 的 **x64** 验证器：

```powershell
# 版本号替换为本机已安装的 WDK 版本。
$apiValidatorX64='C:\Program Files (x86)\Windows Kits\10\bin\10.0.26100.0\x64'
& $msbuild 'KswordARKDriver\KswordARKDriver.vcxproj' /t:ApiValidator `
  /p:Configuration=Release /p:Platform=x64 "/p:SolutionDir=$solutionDir" `
  @hostToolArgs "/p:ApiValidator_ApiExtractorExePath=$apiValidatorX64" /m:1 /v:minimal
```

`Driver is 'Universal'.` 是独立 API/体系结构验证的通过标志，不证明签名、CAT 或加载通过。链接前失败时应修复原始错误，不能用此路径绕过构建。

当前机器没有 WDK时，可以沿用统一 Release 目录已有的 `KswordARK.sys`、`KswordARK.pdb` 与 `KswordARKDriver.inf` 制作包；发布说明必须记录它们的来源、哈希、签名状态，并明确驱动未在本次重建。

## Launcher 支持策略与报告接入

当前清单定义见 [support_manifest_source.json](../Launcher/support_manifest_source.json)，生成器见 [generate_support_manifest.py](../Launcher/tools/generate_support_manifest.py)。

| 项目 | 当前行为 |
| --- | --- |
| GUI 系统最低要求 | Qt 对应 Windows 10 1809 / build 17763；驱动启动协议最低 build 16299 是另一层门槛。 |
| OS build 上限 | R0 与 Launcher 的上限拦截已停用；`advertisedMaximumBuild=0`、`allowNewerWindows11=true`。 |
| 清单范围字符串 | `Windows 10 1809 - Windows 11 24H2` 记录既有范围，不证明所有更新 build 已验证，也不是当前上限。 |
| 支持判断 | 精确模块类别、PE machine/timestamp/SizeOfImage 和 PDB name/GUID/Age；相同 Windows build 号不能替代身份匹配。 |
| `complete=true` | 满足生成器当前核心字段/全局条件；可选字段缺失不一定导致整个身份不完整。它不等于全部功能或硬件实验通过。 |
| `collectionOnly=true` | 收集 PE/PDB 研究材料，不生成该类别的发布 profile，也不阻止启动。NTOS/NTKRLA57 是兼容性必需模块；CI 是非必需的独立 v4 profile。 |

报告目录必须先只读验证，再入库；不要直接把用户附件复制进发布矩阵：

```powershell
$reportDir='<解压后的 Launcher 报告目录>'
$corpusRoot='<私有 PE/PDB 语料库根目录>'
$pdbutil='<本机 llvm-pdbutil.exe 路径>'
python tools\pdb_offset_generator\launcher_report_intake.py $reportDir
# 仅在 valid=true 后执行：
python tools\pdb_offset_generator\launcher_report_intake.py $reportDir `
  --corpus-root $corpusRoot --llvm-pdbutil $pdbutil --commit
```

验证会核对 SHA256、amd64 PE 和 RSDS 身份；Wine、非 amd64、无 RSDS 或校验和不一致的报告不得进入正式矩阵。commit 阶段下载并验证精确 PDB，按报告类别与 `collectionOnly` 合同生成适用 profile；纯收集模块只保存 PE/PDB。重复导入应显示 `existing`。

入库和发布是两个步骤。从已验证语料库重新生成唯一 v4 源 pack 与 Launcher 源清单：

```powershell
python tools\pdb_offset_generator\ksword_profile_release_sync.py `
  --source "$corpusRoot\profiles\ark_dyndata" `
  --release-root 'Ksword5.1\x64\Release' --pack-only --emit-pack --pack-version 4 `
  --pack-output 'Ksword5.1\Ksword5.1\profiles\ark_dyndata_pack_v4.json' `
  --manifest 'Ksword5.1\Ksword5.1\profiles\ark_dyndata_manifest.json' `
  --report "$corpusRoot\logs\ark_dyndata_publish_report.launcher-intake.json"
python Launcher\tools\generate_support_manifest.py `
  --source Launcher\support_manifest_source.json `
  --pack Ksword5.1\Ksword5.1\profiles\ark_dyndata_pack_v4.json `
  --output Launcher\launcher_support_manifest.json
```

确认新增 PE/PDB 身份在清单唯一，所发布核心 profile 的 `complete=true`；随后构建主程序以生成 `ark_dyndata_pack_v4.json.qz`，再构建 Launcher 更新发行目录清单。`.qz` 是 Qt `qCompress` 格式（4 字节原始长度加 zlib），不能把普通 zip/zlib 文件改名充当它。CI/FLTMGR 等精确 PDB 的研究与运行时能力还应参考 [PDB 工具说明](../tools/pdb_offset_generator/README.md)。

## 组装发行目录

包根目录必须为 `Release/`。建议在 `dist/` 下使用本次专用 stage，从已知参考包提取完整 Qt/plugin 布局，再覆盖本次构建产物。不要把 stage 的父目录打进包。参考包只能复用依赖布局，不能作为新二进制版本证据。

必须同步这些内容：

| 内容 | 文件或目录 |
| --- | --- |
| 用户态组件 | `Ksword5.1.exe`、`Launcher.exe`、`KswordARKLight.exe`、`Taskbar.exe`、`KswordHUD.exe`、`KswordCLI.exe`、`KswordDwmZOrder.dll`、`APIMonitor_x64.dll`、`APIMonitor_x86.dll` 及适用 PDB。 |
| 驱动 | 根目录 `KswordARK.sys`、`KswordARK.pdb`、`KswordARKDriver.inf`；`KswordARKDriver/` 子目录中的 SYS/INF 同步覆盖。CAT 与签名按实际构建状态另行记录。 |
| Profile | `profiles/ark_dyndata_pack_v4.json.qz`、`launcher_support_manifest.json`、`api_monitor_definitions.json`、可用的深度 PDB offset 库。 |
| 系统优化资产 | `profiles/registry_optimization_items.json.qz` 与 `registry_optimization_assets/`，包含 `Config/Data.zip`；源 JSON/本地资产可能不随 Git 检出，缺失时应如实记录。 |
| 语言包 | 用本次 Release 的完整 `languages/` 替换旧目录，至少确认 `zh-CN.json`、`en-US.json`。禁止重排语言 JSON 来制造无意义差异。 |
| 运行依赖 | Qt DLL、VC runtime DLL、`qtadvanceddocking.dll`，以及 `platforms/`、`styles/`、`imageformats/`、`iconengines/`、`generic/`、`networkinformation/`、`tls/`、`translations/` 等实际部署目录。 |
| 许可证 | 根 `LICENSE`、`COMMUNITY_COVENANT.md` 与下述 `licenses/third_party/`。主程序许可证页从 exe 同目录读取 `LICENSE`。 |

第三方许可证至少保留 System Informer、easy_hwid_spoofer、FLTK、Qt Advanced Docking System、zstd 的原文与已有 NOTICE；来源在 `third_party/`。发布 x64dbg/CE 插件等附加包时同时保留其额外第三方许可证。

参考包提取与覆盖操作都应限制在已解析、位于仓库 `dist/` 的本次 stage；删除旧 stage/语言目录前核对绝对路径。使用原生 PowerShell 文件操作，不跨 shell 拼接删除命令。

## 压缩与校验

先准备 `$stageRoot`（内含本次 `Release/`）、`$seven`（本机 `7z.exe`）和描述性 `$archive` 路径，再执行：

```powershell
$archive=Join-Path (Get-Location) ('dist\KswordARK评估版本-' + (Get-Date -Format 'yyMMdd') + '-未签名R0-功能描述.7z')
if (Test-Path -LiteralPath $archive) { throw '目标压缩包已存在，请选择本次独立文件名。' }
Push-Location $stageRoot
try {
  & $seven a -t7z -mx=9 -mmt=on $archive 'Release'
  if ($LASTEXITCODE -ne 0) { throw "7z create failed: $LASTEXITCODE" }
} finally { Pop-Location }
& $seven t $archive
if ($LASTEXITCODE -ne 0) { throw "7z integrity test failed: $LASTEXITCODE" }
& $seven l $archive 'Release\*'
```

包名中的“未签名R0”必须与实际驱动签名一致。`7z t` 应输出 `Everything is Ok`；列表还需确认上述关键文件、两个驱动副本、双语语言包、profile 与 `platforms/qwindows.dll` 都已入包。把 stage 文件哈希与统一 Release 的本次 exe/dll/sys 哈希逐项比较，记录复用驱动或旧依赖的例外。

归档完整性、文件入包、静态门禁、Windows 构建、驱动加载与真实硬件功能验证各自报告，不互相替代。尤其 AMD SVM/NPT 和 HVM 生命周期的实验状态应遵循 [HVM 实验说明](../tools/hvm_lab/README.md)，不能因构建通过就宣称完整内层 OS 已验收。
