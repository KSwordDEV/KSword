# 硬件 USB 字段回填与采集状态

## 问题与修复范围

用户报告硬件 Dock 的 USB 设备初始化约一分钟，期间及之后 UI 无响应。

源码检查发现，`requestAsyncDeviceAuditRefresh` 已把 PowerShell/CIM 和 R0 审计放在线程池中；不能再简单增加一个后台查询线程来解决回填开销。`createReadOnlyFieldPage` 仍使用 `StructuredFieldView` 的兼容原生树路径：`setDocument → rebuild` 在 GUI 线程创建全部 `QTreeWidgetItem`、保存/恢复展开状态、逐字段搜索和布局。R0 摘要会保留全部风险行，最多 1024 行可形成上万字段；之后搜索、字体和尺寸变化仍涉及这棵树。

普通硬件审计页现显式接入既有 `setValueModelProjection()`，复用后台纯值准备、分页 `FieldTreeModel`、分片展开与隐藏投影延后。没有新增页面私有异步或布局框架。此修复消除了这条已确认的同步整树路径；尚未通过用户机器上的真实主程序复现，不能把源码检查和组件计时等同于已证明现场所有卡顿来源。

`queryPowerShellFieldsSync` 的失败文档将“采集状态”设为默认折叠。状态字段、原始诊断、搜索和完整复制/导出仍来自同一规范文档。显式用户展开后，后续同身份更新沿共享组件保留展开状态。
