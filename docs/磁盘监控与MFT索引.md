# 磁盘监控与 MFT 索引

本次功能覆盖硬盘监控的队列指标与文件 I/O 事件日志，以及文件页的 NTFS 快速搜索和文件空间分布。

## 数据口径

- 硬盘监控的进程传输计数、Kernel-File ETW 文件请求与卷性能计数是不同来源，不能将文件请求字节解释为物理落盘字节。
- 队列深度是查询瞬间的值；平均队列使用相邻有效性能样本的累计服务时间差计算。响应时间以实际请求计数差为分母。首份样本只建立基线，设备身份或计数器重置后重新建立基线。
- MFT 索引只读本地 NTFS 卷，通常需要管理员权限。索引与查询均不创建、删除或重置 USN Journal。
- USN Journal 用于更新已建立的 MFT 索引。日志被删除、重新创建或截断时，旧索引不能冒充已更新的数据，应重建索引。
- 文件尺寸来自未命名 `$DATA`。硬链接共享同一个文件引用，容量只统计一次；驻留数据没有独立的数据簇分配。未知尺寸、属性列表未解析等情形须单独报告，不可当作零字节。
- 文件名称会合并基础记录与所属扩展记录中的非 DOS 名称，并校验完整文件引用的序列号。容量归入一个确定的规范名称所在目录，不把同一硬链接文件重复分摊到每个目录。搜索结果定位会打开所属目录、显示隐藏及系统项，并沿原异步导航选中目标。
- 文件分布是索引中的默认文件数据流分布，不等于卷全部已用空间。可计量的 `$MFT`、`$LogFile` 等系统文件默认数据流也会纳入；目录索引等其他元数据、备用数据流、驻留记录自身空间及未能解析的部分可能使它与系统容量显示不同。活动卷也不是某一时刻的原子快照。
- 普通文件的非驻留属性列表尚不解析，页面会报告名称覆盖不完整的文件数量；这类文件可能漏掉扩展名称，大小仍按未知处理。
- `$MFT` 自身的非驻留属性列表按完整映射有界读取，最多16MiB，并验证扩展记录序列与所属基础记录；不能仅因其非驻留就拒绝卷。扫描期间真实 MFT 映射、身份或有效长度改变仍会失败并提示重试，正常 LSN/USA 等记录更新不会被误报为映射变化。增量更新遇到变更普通文件的非驻留属性列表时仍要求重建，不返回半份成功结果。

### 快速搜索操作流程

参数区按“1. 选择磁盘 → 2. 搜索文件”排列，底部固定一个主要搜索动作和“停止”。用户选择磁盘、输入名称关键词后点击“扫描并搜索”，或在输入框按 Enter；第一次自动准备该磁盘的文件列表，再执行搜索。已有该磁盘的可用列表时，主动作变为“搜索”。留空可浏览全部文件。空间统计从独立的“空间分布”导航进入。默认按名称包含关键词匹配；完整路径、通配符和结果类型都有明确标签及示例。

“索引维护与说明”默认折叠，提供“更新文件列表”和完整重扫；MFT、USN、硬链接及空间计量的详细说明保留在该区。公共结果头同时呈现任务状态和进度；不完整名称的覆盖警告保持可见。搜索页签称为“搜索结果”，有双击/打开所在文件夹说明，空间页有方块面积及进入目录的说明。

切换磁盘会取消旧搜索和空间计算，保留上一次可用快照，但明确显示其来源以及所选新磁盘尚未加载；定位和空间导航在磁盘身份不匹配时禁用，直接调用也有相同保护。再次搜索准备所选磁盘，不继续查询旧盘。显式搜索切到搜索结果页签；索引维护完成后的自动搜索保留当前结果页签。

本页仍由原 `ParameterWorkspace` 负责参数独立滚动、固定动作及窄窗上下排列；不增加第二套自适应骨架。搜索表与文件类型汇总表使用 Compact 操作条，目录树使用 None；模型、完整字段、复制/导出、后台排序和地图专业内部结构保留。

本轮源码核对及双语/主题门禁通过。原生 HostX64 界面回归通过209项，覆盖首次点击与 Enter 自动准备、名称/路径/通配符/类型筛选、切盘失败回滚、旧异步提交失效、固定动作和公共进度；夹具显式加载雅黑并核对中文字符，但隔离翻译、主窗口和部分标准控件主题。合并远端更新后，真实主程序 Release/x64 构建成功、退出码0，标准 EXE 已更新为32145920字节；完整双语审计通过29875条文本。真实主程序完整视觉矩阵及整卷搜索验收尚未完成，不能以这些夹具预览或构建结果替代。

日志保留开始/完成阶段、事件头 PID、路径、请求字节、文件偏移、IRP、耗时和 NTSTATUS。事件头 PID 表示记录上下文；完成事件可能来自系统线程。无法解析的路径仍保留为 `N/A`。待显示缓冲上限 2,048 条、显示历史上限 10,000 条；缓冲覆盖、显示淘汰和 ETW 丢失计数分别显示。取消“记录文件 I/O”暂停日志捕获，不停止卷队列采样。

## 后续功能与界面修复

截图中的索引失败有实际后端原因：原实现拒绝 `$MFT` 非驻留属性列表，且把整条 FILE 记录字节相等作为布局稳定条件。现在读取完整有界属性列表并比较实际映射/身份；保留真实 Win32 错误。raw 读取还使用对齐缓冲，并处理碎片化映射中后续 extent 的目标地址对齐，避免卷句柄隐式 noncached 时返回无效参数。

真实 Windows NTFS 卷进一步暴露了首次 USN 刷新的记录校验缺陷：`FSCTL_GET_NTFS_FILE_RECORD` 已返回经过 NTFS 恢复的逻辑记录，缓存写入后 sector tail 不必等于旧 USA 数组。解析器现在保留这类逻辑字节，只有原始磁盘记录才校验并恢复 USA；MFT 映射提取遵循同一格式边界。回归覆盖跨 sector 的文件名、runlist，以及逻辑尾字节恰好等于保护标记的情况，防止二次恢复悄悄改写有效内容。

另修正 USA 格式步长与磁盘 I/O 扇区的混用：4096字节 FILE 仍按512字节保护步长解析9项 USA，卷几何与原始读取对齐继续使用真实扇区大小。专门用例覆盖4K记录的恢复、损坏拒绝及 FSCTL 映射提取；该格式回归不等于已在真实4Kn设备上完成验收。

磁盘页不再把三块结果挤在同一竖分隔器中，也不再用全宽 checked 按钮作为标题；活动、日志、卷队列各有适合自身的工具面和表格操作。采样、过滤、选择、日志留存和队列数值口径保持原语义。MFT 页共同状态、Tab、独立工具行与表格槽由共享入口负责，索引失败有重试和明确依赖说明，异步取消不再把旧空间图和新目录身份混用。

## 2026-11-01：合法稀疏续段导致固定校验失败

用户现场 C: 每次建立索引均返回“MFT 记录校验失败，卷可能正在变化；请重试。”。有界只读探针定位到第401条记录：卷脏位为0，两个 USA 尾标记均匹配；原始记录和 `FSCTL_GET_NTFS_FILE_RECORD` 返回的逻辑记录均在同一属性头检查处被拒绝。该 `$DATA` 属性长度784字节，稀疏标志 `0x8000`，VCN 范围30464–55183，映射偏移64，属于合法的非首段记录。

原解析器把首段的尺寸字段及 `TotalAllocated` 扩展头要求应用于所有非驻留 DATA 段，错误要求该续段的映射偏移至少为72。现在仅 `LowestVcn == 0` 读取和验证尺寸及扩展头；续段仍验证 VCN 范围，但不使用未定义的尺寸字段，大小保持未知，MFT 映射续段的 `logicalBytes` 归零。首段尺寸、非法 VCN、属性边界和 raw USA 校验保持严格。尺寸有效范围参见 [Microsoft ATTRIBUTE_RECORD_HEADER 定义](https://learn.microsoft.com/en-us/windows/win32/devnotes/attribute-record-header)。

另补充活动卷的单记录复核：仅当 raw FILE 解析失败时，对同一索引调用一次 FSCTL，并以逻辑记录格式验证。返回较小索引代表原槽已释放，不能把较小记录插入为请求身份；调用错误、畸形返回或逻辑记录仍不合法均继续失败。扩展身份从复核后的同一缓冲读取，调用前后检查取消，不将缺失或损坏数据冒充完整成功。FSCTL 的向下查找语义参见 [Microsoft FSCTL_GET_NTFS_FILE_RECORD 定义](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_get_ntfs_file_record)。

- `ntfs_index_record_test.cpp` 使用原生 HostX64 MSVC `/W4 /WX` 编译并通过5000组突变输入；覆盖 raw/FSCTL、未定义续段尺寸、紧凑稀疏/压缩头、首段严格负例和非法 VCN。
