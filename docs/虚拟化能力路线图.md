# KSword 虚拟化能力路线图

核查日期：2026-10-05。本文区分当前代码、已保存的运行证据和后续目标，替代早期“仅 Intel、AMD 未实现、完整嵌套不做”的阶段基线。接口存在或能力位可用，不等于任意硬件、外层 VMM 或完整内层操作系统已验收。

适用范围：`KswordARKDriver/src/features/hvm/`、`shared/driver/KswordArkHvmIoctl.h`、主程序的 `ArkDriverClient`、`KvmDock`、`UI/Kvm*`，以及共享调试后端。操作概览见 [功能技术文档第 25 节](功能技术文档.md#25-虚拟化与-r-1-工作区)。

## 当前实现与准入

| 能力 | 当前实现 | 运行边界 |
| --- | --- | --- |
| Intel VMX/EPT 常驻 | VMCS builder、MSR bitmap、退出模拟、逐核资源、自检/常驻/停止与 SOAK | 必须满足 VMX/固件/EPT/INVEPT、完整 CPU 集合、电源代次与卸载保护；未识别状态不能猜测继续。 |
| AMD SVM/NPT 常驻 | `hvm_backend.*`、`hvm_svm_*`、`hvm_npt.c`，准备/自检/原生返回与逐核诊断 | 实验后端；SVM/NPT/NRIP、ASID 和 MSR 有效位独立核验，不能拿零值代替未读取。 |
| R-1 内存 | 私有物理映射窗口、虚拟翻译、按 PID 定位、读写与实际回执 | 窗口失败时读取可报告降级，写不可用；不是通用绕过一切监控的保证。 |
| EPT 规则与策略 | Tripwire、ALLOW_ONCE、WATCH_ONCE、MSR/CR 策略、事件消费 | 依赖能力与模式；ENFORCE 被明确拒绝为 UNIMPLEMENTED，不能宣传持久拒绝已完成。 |
| 双视图与 Hook | 原始/执行视图、影子页、Hook 向导、每处理器私有 EPT 与域管理 | 安装前核对映射/页内容；域权限收紧与全进程隔离不同，页级执行视图不能冻结普通数据。 |
| 共享调试器接入 | CE/TitanEngine 复用 `DebuggerBackend`，真实 Windows 事件、EPT/Shadow 执行断点与策略 | 原生回退必须明确记录；执行/数据/内存断点及 replay 按前端能力区分。 |
| Intel 嵌套 VMX | vmcs12、退出反射、影子 EPT、后代页/区域覆盖与租约 | 支持/准备/armed 与瞬时 L2 状态分开；eVMCS 与具体外层路径不因存在字段自动变 active。 |
| AMD 通用嵌套 SVM | VMCB12/02、退出反射、NPT 合成、操作数读取、事件协调/邮箱、NMI window、首故障记录 | 实验 PARTIAL；完整 L2 OS、内层多核并发与复杂事件硬件语义仍需单独验收。 |

这些能力不是后端对称的清单。Intel EPT 调试/双视图及嵌套 EPT 的运行记录，不能证明 AMD NPT 已支持同样上层操作；请求需通过 `shared/driver/KswordArkHvmRequest.h` 和实际能力过滤。

现行常驻生命周期按已识别 Intel/AMD 分支注册：完整保护链成功后才发布常驻能力；注册失败仅关闭 HVM，不使整个 KswordARK 驱动无法加载。未知外层和不满足条件的 Hyper-V/VBS 环境仍拒绝；显式允许来宾运行不能绕过硬件或版本门。

## KVM 工作区与内存编辑

标题栏 KVM 按钮和独立“虚拟化 (KVM)”Dock 使用同一 `KvmState`。就绪、常驻与不可用分别显示，具体错误来自后端状态；不能用一个 UI 开关代替驱动状态。

- 启动经过 PREPARE、SELF_TEST、START_RESIDENT，成功必须是完整预期 CPU 集合及同一电源/准备代次。
- 准备配置与所请求模式不同，应明确停止、释放和重新准备；不能自动替换外部调用者的资源。
- R-1 写权限默认关闭。用户开启后仍经过协议、目标、确认与后端门禁；耗时 IOCTL 在后台执行。
- R-1 内存、双视图和 Hook 向导共用 `MemoryEditorWidget`。Hex/文本/反汇编/汇编只改本地快照，所属页面显式写回或安装。
- 物理地址和 CR3 不能推断 x86/x64。写回绑定成功读取时的地址、目标、后端和会话，写前比对原字节、写后检查实际字节；比较与写入之间不具备硬件原子性。

组件与语法见 [内存编辑器组件清单](内存编辑器组件清单.md)。监视及有限现场归因见 [HVM 内存监视](next/hvm-memory-watch.md) 和 [连续监视可行性](next/hvm-continuous-watch-feasibility.md)。

## 后续路线与验收门

### 1. 保持常驻生命周期可恢复

现有电源、拓扑、transition phase 和 DriverUnload 保护继续作为所有新增功能的前置约束。

验收必须覆盖：prepare/self-test/start/stop 的逐 CPU 集合一致；失败回滚及 ROLLBACK_REQUIRED 保留；睡眠/Modern Standby（设备支持时）后的证据失效与重新自检；CPU 热添加拒绝；完整退出后恢复卸载。停止部分失败时不得释放仍被硬件引用的栈/页表或报告服务可卸载。

硬件与 Windows 环境必须分别记录处理器组、CET/XSTATE、外层 VMM、VBS/HVCI、启动配置与精确 SYS/PDB 身份。模型与 WDK 构建不替代这组验收。

### 2. 收敛 AMD 通用嵌套

生产入口、退出反射、NPT 和事件协调已存在，重点应转为冻结候选上的硬件错误定位与修复验收。

- 首故障记录保留原始 SHUTDOWN/INVALID、VMCB12/02、注入/中断状态、逐核代次与候选哈希；查询必须只读，不先 reset/teardown 覆盖现场。
- EVENTINJ 清除、NMI window、TF/RF/DR6、PUSHF/POPF/IRET、EXITINTINFO 碰撞及跨 CPU owner 邮箱分别测试。离线通过不能证明真实指令/中断语义。
- 先完成单核完整 L2 OS 启动、工作负载、关闭、stop/teardown/卸载，再完成同一内层 VM 的多个 vCPU 同时持续前进。
- 受控固定探针、prepare 成功、VMware 识别 AMD-V 或到达 EFI，均不满足完整 L2 OS 验收门。

新结果必须追加对应证据文档，并保留首次失败。只有硬件场景通过才调整实验成熟度与宣传范围。

### 3. 扩展监视与策略

WATCH_ONCE 当前针对首次访问归因，不保证所有后续写入。ALLOW_ONCE 依赖 MTF 与每核私有页表条件；持续精确监视需先解决并发权限窗口、重装开销与退化语义。

ENFORCE 的 guest #PF 无法修复 EPT 权限会导致活锁，现实现明确返回 UNIMPLEMENTED。若重启该方向，须先设计 guest 可理解的拒绝/恢复契约，再实现和验收；不能仅重新开放旧 flag。

每项新策略要有 actual/unsupported/partial 状态、原始错误、事件丢失计数和导出证据，不以事件表暂时为空宣称无访问。

### 4. 保持调试器与内存路径一致

共享后端必须保持真实 Windows 停止事件、进程/线程实例身份、自有 HVM 资源及失败回滚。CE 与 Titan 前端支持范围分别维护，不把执行断点回退推广为精确数据断点。

Shadow 代码修改需要私有页证据；执行视图不是普通数据视图。自修改代码、映射替换、COW、恢复隔离和退出清理必须有独立场景。详细矩阵见 [公共调试后端](../DebuggerBackend/README.md)、[TitanEngine 适配](../TitanEnginePlugin/README.md) 和 [x64dbg 后端说明](ksword-x64dbg-backend.md)。

### 5. 后代页/区域控制与隔离研究

当前后代覆盖按 EPT12 root、GPA、源路径与进程所有权建立租约，支持发布、失效、撤销与 retired 回收；这比裸 GPA 更明确，但不是通用安全隔离域。

后续需分清：预留/固定 RAM 页、源映射变化、root 重用、VM 生命周期、移除后 drain、region 粒度、大页拆分和配额。未知 DMA/设备语义及恶意中间 VMM 不在现有保证内。契约见 [EPT 租约](next/ept-lease-contract.md)、[嵌套 EPT 页控制](next/nested-ept-page-control.md) 与 [执行域设计](next/嵌套虚拟化实现设计.md)。

## 开发与记录规则

1. 共享 ABI 唯一定义在 `shared/driver/`，handler 仅在 `ioctl_registry.c` 注册；主程序经 `ArkDriverClient` 调用。
2. feature 位、prepare 配置、实际 armed、逐 CPU active 与回执状态各有语义，不能合并成一个“支持”布尔。
3. 根模式保持预分配与有界操作；不新增 pageable 分配、无限等待或未验证私有指针读取。
4. 发布和撤销涉及跨核 TLB/EPT/NPT 失效时，必须先完成 drain 再释放硬件可能引用的资源；失败保留原错误与独立回滚结果。
5. 新源码同步 `.vcxproj/.filters`，新可见文本定点同步双语包，CLI 命令同步 help/使用文档。
6. 测试分别报告离线、生产函数、构建/API/CAT、签名、加载、GUI 和硬件结果；验收失败/NOT_RUN 不折进 PASS。
7. 构建使用仓库 HostX64 MSVC/WDK 流程；不要为绕过链接或后置签名问题切换未经批准的工具链。

更底层规范与裁剪背景见 [虚拟化规范要点](虚拟化规范要点.md)；实验报告、架构与原始数据入口见 [文档索引](README.md) 的虚拟化专题。
