## 1. 已明确的需求

| 项目 | 已明确要求 |
| --- | --- |
| 行为语义 | 将原始事件及其组合解释为有依据的语义，例如注册表访问解释为虚拟机线索探测；不限于给 API 改名，也不是只有处置规则 |
| 默认展示 | 默认显示聚合语义行，可展开原始依据和时序 |
| 默认范围 | 自有规则默认同一线程；扩大到同进程、对象、传播分支或会话时明确声明 |
| 导入范围 | 保留上游关联键、目标字段绑定、作用域及时间条件；不能自动改成默认同线程后仍称等价 |
| 缺字段 | 每条规则配置 unknown、跳过、覆盖提示等策略；未采集、截断或未知不当作事实 |
| 收集广度 | 覆盖所有可找到的类别和候选；不能以首批 30–50 条代替完整目录 |
| 语法方向 | 有限 C# 风格表达式，编辑器旁有示例；希望支持字符串、缓冲区、多参数、计数、序列及复杂组合 |
| 两层执行 | 同步调用前的有界单事件谓词，与本端控制器的多事件状态处理分开 |
| 三端组织 | Qt、Win32、CLI 各自组织本端实现，不新建共享宿主、公共追踪 DLL、统一 runtime 或跨端 IPC |
| 性能 | 谨慎划分代码职责，约束程序内存及 UI 更新；完整目录不等于运行时全部加载 |

### 2.3 组合规则不等于原始事件关联

现有引擎的 `dataContains`／`dataRegex` 对不同字段采用 OR，`allDataRegex` 要求各指定字段命中，`dataContainsAll` 检查全部子串但不保证顺序。正则超时 100ms 是该源引擎参数，不是 KSword 已确定的预算。

以下测试直接填写了聚合结果：

- `BehaviorRuleV28ExpansionScenario.cs` 在单条 `api.sequence` 的 operation 字符串里写入完整 API 链。
- `BehaviorRuleCombinationQualityScenario.cs` 在注册表事件中填写 dropped-file correlation，在网络事件中填写 interval、jitter 和 classification。

这些测试验证的是“已有聚合输入能否命中模板”，不能证明从多条原始事件恢复目标、顺序、地址和因果关系。本次相关生产源码搜索没有找到这些精确组合／统计字段的通用生产链；外部 sidecar 仍可能传入预计算字段，不能写成绝对无法输入。

并入时分别登记原生采集、外部导入、稍后富化、合成测试和预计算语义，不能把后两类当作原始采集覆盖。

## 5. 全类别目录、来源 manifest 与支持状态

初始全量目录覆盖本地 601 条行为规则及适用静态模板，并枚举 9 个来源快照中的候选与依赖。执行、线程／内存、注入、文件、注册表、持久化、任务／服务、WMI／COM、权限、凭据、发现、反分析、防护干扰、网络／C2、外传、横向、驱动、加密／破坏和静态能力等均纳入登记。

| 字段组 | 必要内容 |

| 转换 | 适配器／schema 版本、字段映射、派生 ID、修改说明与非等价处 |
| 本端与验证 | 三端分别登记支持条件、正反例、良性回放、预算和证据版本 |

建议分别统计 inventoried／collected、supported、needs_fields、needs_semantics、license_pending、deprecated，以及独立的 tested 维度。本轮只确认本地计数及来源快照，没有生成上游全量逐规则 manifest，也没有待支持／已支持条数可填。上游 `status: test` 不等于 KSword 已测试。

一条规则可同时缺字段、缺语义、待授权，应保留全部阻塞原因。不能删除必要条件使其“能跑”；另建较弱规则时使用 KSword 派生身份，展示差异并重验，不称等价导入。

## 6. 当前 KSword 输入及缺口

自有[API 定义](../APIMonitor_x64/api_monitor_definitions.json)为 898 项；定义、安装成功、字段足够、关联正确是不同条件。依据包含[Hook 包装](../APIMonitor_x64/hook/HookTargets.cpp)、[摘要格式](../APIMonitor_x64/hook/ApiCaptureFormatters.inc)、[API 协议](../shared/WinApiMonitorProtocol.h)、[注册表回调](../KswordARKDriver/src/features/callback/registry_callback.c)、[回调协议](../shared/driver/KswordArkCallbackMonitorIoctl.h)与[ETW 入口](../Ksword5.1/Ksword5.1/MonitorDock/MonitorDock.cpp)。

| 语义 | 已核对基础与必要边界 |
| --- | --- |
| VM 注册表探测 | R0 有 PreOpenKey／PreQueryValueKey、源 PID／TID 和目标路径，可以解释探测尝试；不是成功读取，更不等于返回了 VM 标识 |
| 注册表路径／值链 | R3 摘要有 root／HKEY、subkey、值名、类型、大小；已核对 RegOpen 包装没有新 HKEY，Query 未保存值内容，不能完整恢复句柄链 |
| Run 与文件落地 | RegSetValue 摘要不复制 dataPointer，R0 该回调也不保存值数据；仍需值内容、规范文件身份及实际结果 |
| 注入组合 | WPM 有句柄、目标地址、请求／实际写入及结果；远程线程有入口、参数、flags、TID。仍需目标实例、句柄代次和区间顺序，参数地址不等于 DLL 路径，创建不等于执行 |
| PowerShell | 有命令行与 Provider 预设；需确认日志配置、ScriptBlockId、分片重组和正文，不能把可订阅当已采集 |
| 网络 | DNS 名称／类型、HTTP 主机／端口／方法／对象／句柄及部分长度；仍需请求／socket 生命周期。长度不等于正文，DNS answers／TLS／周期统计另有来源 |
| WMI | consumer、filter、binding、command template 使用真实对象字段，不能用普通注册表路径代替 |
| 通用关联 | 有会话、PID／TID、时间、结果类别及部分来源序号／丢失信息；仍需稳定事件 ID、实例、对象代次、时钟和可靠顺序 |

API detailText 为 320 wchar 的固定摘要，不承担所有控制判据。Raw EntryOnly 没有返回结果，0 不能解释成功。ETW 头身份不一定是操作对象，相同时间戳不证明跨线程顺序，后查模块／符号不等于事件时事实。

## 7. 本端代码职责与生命周期

建议每端采用“传感器 → 字段／身份规范化 → 紧凑不可变事件 → 归档／有界语义处理 → 证据引用／控制请求／UI 投影”的内部职责划分。不由 Dock 表格倒取事实，不把全部逻辑塞进一个监控窗口类。

| 职责 | 约束 |
| --- | --- |
| 紧凑事件 | 固定头保存 ID、来源序号、时钟域、对象实例、种类与字段有效性；专有字段有类型，可变字节引用有界块，不逐事件构造巨大字符串字典 |
| 不可变发布 | 富化另存来源、时间和版本，不改写历史；字符串池／对象索引／富化缓存也有上限 |
| 规则准备 | 按启用且受支持的规则及必要依赖闭包建立索引；按事件种类、精确 API 和字段选候选，不逐事件遍历全部目录 |
| 状态处理 | 规定窗口、关联键、部分匹配、证据数、状态字节和处理预算；退出／过期／失效有清理，超限报告覆盖降级 |
| 文本与昂贵分析 | 正则在准备阶段编译；脚本重组、符号、内容扫描使用独立有界任务，不静默改写上游模式以适配本引擎 |
| 归档 | 与语义工作集、UI 窗口分别预算；区分接收／排队／写入／刷盘。慢盘、写失败、队列满按策略降级或停止，不无限积压 |
| 证据生命周期 | 命中只持有限字段与事件引用，不复制整事件；引用不能意外固定整段会话内存。按归档位置异步分页读取，证据不可用显示原因 |

同步异常、Agent 调用前谓词和 park 路径只使用已准备的快照、入口字段、预分配现场与独立控制通道；不做符号下载、正则编译、脚本解析、文件／网络 I/O 或任意目标查询，不等待 UI 或完整语义引擎判定。同步路径读取必要参数的方式须另审有界、安全和重入条件。

跨事件判断在本端控制器产生后可以申请暂停或配置后续观察点；不能声称已经在早先调用前停止。规则版本切换、日志队列和控制责任不能共用导致停驻互等的锁。

## 8. 有界语义与 C# 风格表达式

关联键使用进程／线程实例，未知 TID 按缺字段策略处理，不自动扩大作用域。无序共现、有序序列、计数和因果分别解释。保留上游同进程、跨阶段目标 PID、地址绑定及异常排除，无法表达则登记 needs_semantics。

白名单类型、运算符、字符串／字节函数、窗口／三值及数值预算已在[筛选器与规则语言设计](ActionAnalyze筛选器与规则语言设计.md)提出具体规范；A0机器契约与A2执行器仍待实现，不能把已有设计继续表述为整体“待设计”。上游不支持算子保持needs_semantics，不借转换改变原作用域／排除；absence定案及迟到修订另按[缺口复查G13](ActionAnalyze规划缺口复查与补齐任务.md)补充。

以下仅是编辑器旁的示意语法，不是已实现接口或已批准默认值：

```csharp
Semantics.Rule("ksword.vm.registry-probes")
    .Scope(SameThread)
    .Window(Seconds(30))
    .OnMissing(Unknown, CoverageNotice)
    .When(RegistryOpenOrQuery()
        .Where(e => e.Registry.Path.InSet("vm-artifacts"))
        .Distinct(e => e.Registry.Path).Count() >= 2)
    .Emit("多项虚拟机注册表线索探测尝试");
```

这个结果不说明 VM 存在或规避成功。路径集合也要版本与来源；30 秒及计数 2 只说明写法，不是已定阈值。Agent 调用前谓词则只能读取本次入口已知字段，例如 API 身份与输入长度，不引用未来返回值或跨线程后续事件；暂停动作由独立策略配置。

缺失、未采集、读取失败、截断、真实空值分别处理。not／排除项／字段不存在／没有后续事件尤其需要覆盖前提，不能把 unknown 偷换成 false。表达式长度、缓冲区读取、正则、窗口、状态字节和依赖闭包都有预算；配置 unknown／跳过／提示不允许生成不存在的事实。

## 9. 聚合表格与 UI 性能

默认一行代表明确行为实例，显示语义、对象、时间范围、证据数、证据强度与覆盖状态。依据按需展开，继续使用现有详情与专业工具。

- 使用现有模型或 owner-data 列表，不逐事件创建 item／widget／永久展开树。
- 后台生成增量批次，GUI 按时间预算提交；追加、聚合计数、淘汰采用范围更新，不频繁 reset 整模型。
- 筛选／搜索／排序用后台快照与代次，迟到结果不覆盖新条件；高频变更合并，更新可见且变化的部分。
- 脚本正文、原始字节、大字段分页异步解码，展开缓存有界；关闭后释放显示缓存，保留归档身份。
- 图与瀑布流增量／密度聚合，不因每条规则命中重建全图。跨对象、跨版本不能只按标题合并。
- 隐藏页暂停展示工作，后台采集、归档和必要语义继续；待绘队列也有界，不能把隐藏当成无限缓存。
- 显示过滤不改变语义输入；真正关闭来源或前置丢弃时，受影响规则显示覆盖边界。

本次只规划必要数据模型及接入，不重做整个 UI。后续按项目共享组件规范验收。

## 10. 版本冻结、回放与覆盖账目

每个会话冻结规则包、启用集合、依赖闭包、适配器、schema、字段映射和预算配置，保存 hash。编辑形成草稿，新版本用于新会话或明确的新分析批次，不热改运行会话的判据。

按用户新增的[分析项目层级](ActionAnalyze分析项目与多次采样设计.md)，规则选择与草稿由项目保存，每次采样独立冻结实际规则及配置快照，运行中的明确新分析批次保留对应版本。项目内后续修改不覆盖旧采样；多次采样横向比较暂列待做，先保存比较需要的规则、环境、输入覆盖与缺口依据。

更新只发现官方候选、对比固定版本，经语法／依赖／授权核对、正反例、良性回放和预算检查后发布，可回退。只获取所需数据，不执行上游脚本或原规则携带的 kill 等响应动作。

回放保留原始身份、时钟、来源序号及缺失账目；无可靠顺序时不能排序后冒充等价回放。各版本结果分别保存。

传感器未启用／未安装／不支持、采集与传输丢失、字段截断、解码失败、归档失败、语义积压／超时／状态超限和 UI 窗口淘汰分别统计。已知计数精确记录，未知尾部损失明确标未知。正常窗口过期与资源不足淘汰分开；受影响语义标 incomplete／coverage notice，没有匹配不等于没有行为。
