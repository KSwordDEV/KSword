# 快捷键与常驻任务

新增或修改 KSword 快捷键、跨 Tab 轮询、原生常驻会话以及相应管理界面时，先核对本规范。页面布局和主题继续遵守根目录 `AGENTS.md` 的全页面 UI 规范。

## 入口与职责

| 入口 | 页面类型 | 共享实现与数据来源 |
| --- | --- | --- |
| 工具 → 救援模式 | 菜单动作 | `shared/rescue/SosHotkeyLauncher` 派发当前 `Ksword5.1.exe` 的 `RescueDesktopHost` 入口 |
| 工具 → Taskbar | 菜单动作 | 启动同目录 `Taskbar.exe`，使用独立的会话内单例门闩 |
| 工具 → 快捷键管理 → KSword 快捷键 | 二级清单管理工具 | `StyleSecondaryManagerWindow`、`ShortcutRegistry`、`TablePresentation`；列表占主要空间，选中项在底部紧凑编辑，操作条为 None |
| 工具 → 快捷键管理 → 系统快捷键 | 现有程序快捷键与注册热键清单 | 迁移 `WindowDock` 的同一份页面、模型、缓存与扫描控制器；原窗口与杂项入口保留转接 |
| 工具 → 后台任务 | 独立任务管理工具窗 | `TaskManagerDialog` 复用 `ProgressDockWidget` 和同一 `TaskSnapshotFeed`；单次任务与常驻任务共享窗口，后台业务来源保持唯一 |

快捷键窗口固定为上述两页，系统页内部保留程序快捷键与系统注册热键两个来源。窗口关闭只隐藏并保留草稿、结果及控制器；再次打开不创建第二份扫描实例。常驻任务清单的展示刷新只在该页显示时运行。

管理清单按“搜索/筛选 → 选中项目 → 修改或控制”组织，保持上下布局：上方分类、筛选，中间列表占主要高度，底部固定自然高度操作区。暂停、恢复、间隔、绑定、清除等动作置于表格外，随真实选择及实时资格启用，不在每行放按钮。清除绑定不等于清除系统占用；不得通过删除常驻登记假装停止业务。管理表逐张声明 `TableActionBarMode::None`，不放复制、导出或快照工具条。使用 `StyleSecondaryManagerWindow` 保留顶部导航与列表结构，避免详情框架再次转换成侧栏；此角色不关闭标准控件主题。独立任务窗口通过共享响应式几何入口确定初始/最低尺寸，不继承原 Dock 的窄条几何。

操作区使用 `FlowLayout` 与 `NormalizeToolbarLayout`，窄窗自动换行，按钮、数值框、快捷键编辑器等高。普通控件使用标准主题绑定；二级窗口、设置容器和任务容器只持有自己的表面样式块，不能再用后代选择器覆盖输入/下拉框皮肤。下拉列表统一调用 `ThemedComboBoxPopupViewStyle`，含首次继承规则和弹出后的局部规则；容器与列表使用同一不透明底色，只由列表绘边界。保留共享展开动画、模型/委托和键盘行为，不提前创建所有隐藏 Popup。确有专业 Popup 外观时以 `ksword_combo_popup_custom` 显式声明并单独验收，不以任意旧 QSS 自动豁免。

## 快捷键登记

统一入口为 `Ksword5.1/Ksword5.1/UI/ShortcutRegistry.h`。登记步骤：

1. 为逻辑动作选择稳定 ID、短标题、真实作用域和默认绑定。ID 与枚举位置、翻译文字、控件地址无关；多个同类控件可绑定到同一个逻辑动作。共有目录在 `InstallCommonShortcutCatalog` 登记，内存工作台继续以 `WorkbenchActions` 为动作规范源。
2. `QAction` 使用 `bindAction`，`QShortcut` 使用 `bindShortcut` 或已登记目录的 `bindDefaultShortcut`。保留原 `Qt::ShortcutContext`、启用条件、焦点条件、业务回调和控件身份。
3. 自有事件过滤器使用 `matches` 查询当前绑定；不再额外硬编码同一按键。绑定更改必须同时影响实际执行路径，不能只更新清单文字。
4. 新增用户文字同步双语语言包。需要显示按键的控件通过 `setShortcutHint` 绑定说明和动作 ID；提交绑定、清除、恢复默认及语言切换后同步提示，不另存一份默认键文字。

管理器以明确的“应用绑定”“清除绑定”“恢复默认”提交草稿；键盘录入和选中行变化不自动写设置。更新先检查同作用域及应用/系统范围冲突，再应用到已加载目标，最后保存。任一目标拒绝更新或保存失败时回滚已应用目标。空绑定是合法的禁用状态；恢复默认移除覆盖项。惰性页尚未创建时可先保存，创建真实控件后再接入。

目录目前覆盖主菜单、全局刷新、共享文本编辑器、文件浏览、注册表工作台、进程结束、内存工作台、内存调试及无鼠标模式的主要动作。原生文本输入、Tab/方向键导航、菜单助记键、临时弹窗确认/取消继续由所属控件处理。专业编辑器保留自身焦点与输入模型；不得把局部动作升级成应用全局动作。

SOS 序列、救援返回、键盘焦点恢复与特殊模式切换手势保留固定入口并在清单解释；不通过普通绑定编辑移除恢复路径。组合键录入控件不能被应用刷新和无鼠标导航过滤器抢键。物理 SOS 与救援桌面的输入鉴真须另行实机验收，模拟键盘事件不作为通过证据。

救援监护入口由 `Ksword5.1.exe` 在 Qt 初始化前分派，主程序从自身绝对路径启动监护，Taskbar 将 SOS 转交给配套主程序。监护端从自身模块路径启动救援界面，用空字符串 `lpDesktop` 让 Windows 从白名单继承句柄选择初始桌面。监护端的桌面绑定、输入 Hook、等待和清理在专用新线程完成。客户端在 Qt 前校验句柄并确认绑定，失败阶段记入其 PID 对应的救援日志，退出码由监护进程传回主界面。窗口和输入守卫就绪后才切换桌面。

配置位于 exe 同目录的 `config/runtime-controls.ini`，快捷键使用 `shortcuts/<id>`。不使用可视行号或 Qt 运行时对象编号作为配置键。

## 系统占用查询与解除

- 应用内冲突来自登记目录；系统占用来自实际系统注册热键查询。窗口激活热键、`.lnk`、菜单文字、PE Accelerator 与 `RegisterHotKey` 保留原来源，资源或菜单记录不能被当作系统占用证据。
- 注册热键刷新只读取热键，沿用既有异步与表格提交屏障；不连带执行窗口、GPU、剪贴板等整页审计。筛选使用已有快照；查找占用是明确的查询动作。保留采样时间、失败状态、前次结果和重试入口。
- 程序快捷键扫描沿用共享 `.lnk` 索引、最多四个扫描线程和有界批次提交；独立窗口不自动开始慢扫描。取消在文件/进程边界合作完成，等待在途读取结束，保留已采集结果并将单次任务标记为取消。关闭控制器时请求取消。
- 解除操作继续复用 `HotkeyClearController`、`WindowHotkeyClearUi` 与原确认/回执流程。冻结真实记录身份，保留 PID 创建时间、Session、快照 token、代次和变更后复核。部分结果与失败不能显示为成功。
- 管理器的“强制解除占用”只是既有注册热键清除入口；不可新增绕过现有目标校验、隐藏失败或以 UI 状态代替驱动回执的分支。程序资源等不可清除来源继续明确说明限制。

## 常驻任务登记与控制

统一入口为 `Ksword5.1/Ksword5.1/Framework/BackgroundTaskRegistry.h`。登记、快照和控制均在 GUI 线程执行；工作线程通过原有线程安全状态或投递返回 GUI。登记本身不启动定时器，不复制业务采样器。

### QTimer 适配

1. 在业务所有者构造定时器、设置默认间隔后调用 `addTimer`。提供稳定 ID、任务名称、分组、间隔范围、暂停资格和限制说明；按需要提供原所有者的 `eligible`、`inFlight` 回读。
2. 检查登记结果。同一单例 ID 只允许一个定时器；冲突定时器被停止，其后续 Timer 事件也被拦截，不能通过再次 `start()` 形成第二套轮询。
3. 任务间隔由原业务参数统一控制时，管理器保留该参数入口并禁用重复编辑。可调任务的间隔限制来自任务策略，禁止零间隔忙循环。
4. 暂停只阻止后续派发，不代表取消已在途工作。恢复必须重新检查原所有者资格，不能复活已停止会话或已关闭的页面任务。
5. 多个临时实例显式设置 `allowMultipleInstances`；实例独立暂停，实例间隔仅本次有效，不把临时地址或创建顺序保存为长期配置。

普通单例间隔保存在 `polling/<id>`，恢复默认移除覆盖项；暂停不跨进程持久化。定时器/所有者销毁后登记自动移除；代次校验阻止旧销毁回调移除新登记。

### 原生线程与会话适配

使用 `addExternal` 登记所有者、真实运行/暂停回读及原有暂停入口。回读函数应只读取现有状态，不执行查询或枚举。暂停委托必须回读结果；所有者结束或会话不接受变更时明确失败。

SOS 监听、WMI/ETW 会话属于此适配。界面将其间隔显示为会话控制，派发计数留空；不捏造 Qt 定时间隔或采样次数。WMI/ETW 暂停复用原页面的控制流程，停止、过滤与归档仍归原页面。

### 调度与性能边界

- 常驻业务继续使用原异步派发、单个在途任务、取消与代次门禁。新增耗时轮询必须在共享异步入口中执行，保持单个在途查询；界面线程只提交和展示结果。
- 常驻周期不能每轮创建 `kPro` 单次任务。明确由用户启动/停止的一次采集会话可保留原会话进度，同时提供常驻控制登记；不得因此创建第二个业务会话或第二套采样器。
- 事件排空、归档、恢复与安全关键任务按实际语义限制控制；页面隐藏不能误停仍承担采集/归档的业务。局部可见页刷新、动画、输入防抖和一次性超时保持其局部生命周期，不为凑目录统一改成常驻任务。
- 管理器只观察明确登记的所有者；不循环扫描整页对象树，不逐帧重建模型、图标或 QSS。统计只记录真实派发与时间；派发次数不代表业务成功或耗时，活动状态不代表数据查询成功。

当前接入的任务类型包括：权限/驱动状态、任务快照、通知、日志展示、系统/硬件/进程采样、窗口清单、硬件浮窗跟随、网络报文与 R0 流量、下载展示、内核回调/文件监控/防火墙事件排空、WMI/ETW 排空，以及 SOS、WMI、ETW 原生会话。惰性页面仅在真实控制器存在后出现；不能把未构造页面算作已运行任务。

### CPU 分析

- 分析默认关闭，由常驻任务页显式开始/停止；重新统计开启新会话，离开页面停止测量并保留已完成统计。不写跟踪文件、不添加后台扫描或第二套业务定时器，关闭时事件路径不读取时钟。
- 进程摘要来自 `GetProcessTimes` 用户态＋内核态时间，除以实际经过时间和全部逻辑处理器数，显示本次分析的平均占用。查询失败或处理器数变化时显示不可用，不将其当成 0%。这包含界面、单次操作及未归因工作，不等于常驻任务之和。
- `TaskCpuMeasurement` 使用 `GetThreadTimes` 统计执行线程 CPU 时间，分为派发、后台工作、结果提交。`QApplication::notify` 仅对登记的真实 QTimer 事件建立任务身份；嵌套事件隔离并扣除父范围，避免重复计费。它测量 CPU 时间，不能用等待时长、派发次数或任务间隔估算占用。短操作的 0 值可能低于系统计时精度。
- `AsyncOperation` 在请求提交时捕获测量身份并随排队请求传递，`AsyncUiDispatcher` 将身份带回结果提交；禁止借用页面指针做跨线程归因。直接原生线程、线程池或 `invokeMethod` 业务须以 `TaskCpuScope::capture()` / `TaskCpuScope(token, phase)` 显式接入，作用域围绕一轮工作而不是整条常驻线程。进程、硬件及监视面板的主要采样链已接入；其它独立后台查询和 SOS/WMI/ETW 原生会话不承诺完整覆盖。
- 列表显示已完成片段累计 CPU 时间、其中后台 CPU 时间及片段数；悬停显示三个阶段、在途片段和读取失败数。片段数不是业务成功次数，部分覆盖不是任务总耗时，未测量会话显示“未测量”，没有完成样本显示“尚无样本”。数值列按数字排序；刷新保持真实行身份、选中项和未应用草稿。
- 停止/重置后，旧令牌禁止提交迟到统计；未完成片段不计入冻结结果，任务销毁后令牌只能持有独立值计数器。原生回归验证嵌套排除、跨线程归因、CPU 查询失败、停止冻结、重置代次、真实计算与睡眠的区别及共享异步回投。

计量依据：[GetThreadTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getthreadtimes)、[GetProcessTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesstimes)。新增计量接入不能用构建成功代替真实性能测量或 GUI 验收。

## 交付检查

1. 源码：逐一列出新增/变更动作和常驻任务的 ID、作用域、默认值、实际所有者、清理及可控性。核对原入口、草稿保留、旧结果来源、临时实例和保护例外。
2. 原生回归：`tools/Invoke-RuntimeControlTests.ps1` 验证冲突、目标回滚、持久化、真实 Qt 定时器暂停/恢复、所有者销毁、重复单例和原生会话委托。输出固定为 `Taskbar/x64/Release`，复用仓库 Qt，不部署运行副本；测试配置位于同目录并在结束时清除。`-CheckUiCompilation` 只增加新界面源码编译，不替代 GUI 验收。
3. 救援/Taskbar 回归：`tools/Invoke-RescueDesktopTests.ps1` 检查隐藏桌面、继承、主程序监护入口的权限与会话互斥、Taskbar 单实例。使用真实输入另行验收物理 SOS 和桌面切换。
4. 完整构建使用仓库 `tools/Invoke-KSwordBuildCheck.ps1`，核对 HostX64、语言/主题门禁、退出码和非零产物。
5. 真实 GUI：核对二级工具菜单、两页切换、慢扫描取消与重复打开、绑定/草稿、占用筛选、任务暂停/恢复/间隔、窄窗、缩放、深浅主题和背景模式。系统热键变更仍需明确目标与原有确认；自动回归不得清除用户现有占用。

分别记录源码、原生回归、整合构建和实际 GUI 结果。没有受控运行数据时，不宣称 CPU、唤醒次数、帧率或响应耗时已经改善。
