# 隐藏进程检测

从「进程 → 进程列表 → 检测方法…」选择要运行的方法。列表里的「检测线索」显示采集结果，可以直接查看常规枚举遗漏的 PID 和原始证据。要做另一组调查，打开进程 Dock 的「深度隐藏进程检测」。两处各自保留本次会话的勾选和上次执行结果。

## 选择与运行

两个入口都提供 **66 个带原始编号的研究点**。「按采集来源选择」保留原有 42 个采集项，可同时使用。搜索支持编号、方法名称和预计耗时。「选中可见项」和「清除可见项」仅作用于当前页的筛选结果，恢复默认会同时重置本入口的研究点和来源勾选。点确定后生效，取消保留上一次选择。

进程列表默认选 Toolhelp 进程/线程、当前桌面窗口及 **#41 网络端点**。深度页在此基础上增加 **#1、4、7、9、31–35、42、66** 和三个 R0 公开枚举/线程 CID 来源。镜像、硬件和特别耗时的方法需手动选择。普通列表的定时刷新沿用原有配置。

每个所选编号都有单独回执。多个编号共用一次源采集时，行上显示同一来源实测耗时，不能把它们相加当作整轮用时。确认选择时保存的输入和勾选会在开始检测时一起冻结。历史、离线和本机数据分别保留范围，主列表只接纳 PID 和真实创建时间相符的现场关联。

第 1、7、27 项需要特定的内核数据结构。已有布局足够时直接使用。当前专用布局取自微软发布的 26100.9974 内核 PDB，随主程序放在 `profiles/process-detection`。驱动核对已加载映像身份，客户端核对磁盘映像与字段摘要，只在适用时装入独立的枚举组并回读。其它版本或已有不同配置时，回执保留实际可用性和原因。
