# 隐藏进程检测

从「进程 → 进程列表 → 检测方法…」选择要运行的方法。列表里的「检测线索」显示采集结果，可以直接查看常规枚举遗漏的 PID 和原始证据。要做另一组调查，打开进程 Dock 的「深度隐藏进程检测」。两处各自保留本次会话的勾选和上次执行结果。

## 选择与运行

- 进程列表默认使用 Toolhelp 进程快照、线程所属进程和当前桌面窗口。深度页的默认组合另外检查网络端点、内核进程和线程多视图、系统进程句柄及已记录的回调事件。
- 两个选择框提供相同的方法。预计耗时只决定分组和默认勾选。点「恢复默认值」后确认可恢复当前页的组合，取消可放弃这次编辑。
- 选好后手动执行。每项回执给出采集状态、用时、记录数和诊断。R0 同组来源合并在一次驱动请求里时，回执注明共用时长。普通进程列表的定时刷新沿用原有采集配置。
- 现场对象、历史事件、内存镜像各自保留来源。查看历史 PID 时使用事件记录号、时间或 ProcessGuid 核对身份。列表向存活进程关联检测提示时需要同一 PID 和创建时间。

## 方法和输入

| 数据来源 | 可选择的检查或观测 | 需要的输入 |
| --- | --- | --- |
| 本机 R3 | 进程和线程快照、窗口、TCP/UDP 所属 PID、系统及 CSRSS 的进程句柄 | 当前会话。无法访问的句柄计入回执 |
| 本机驱动 | 活动进程链、进程 CID、公开进程枚举、线程链、线程 CID、公开线程枚举及线程入口 | 可提供相应能力的 KSword 驱动 |
| 本机内存 | 全物理 PFN 私有页归属、工作集/PTE/PFN 映射复核、逐进程映像与线程及 VAD/PTE、内核可执行映像页和大池 | 各方法分别核对驱动能力、目标身份和读取覆盖 |
| 本机内核执行 | 驱动对象与模块、CPU 和 IDT、工作队列与工作线程、定时器 DPC 归属 | 相应内核查询接口 |
| 生命周期和调度 | 现有内核回调记录、安全日志 4688/4689、Sysmon 1/5/25、ETL 进程和线程生命周期与 CSwitch | 已有监控记录、最近 24 小时的日志，或选择 ETL 文件 |
| HVM | 读取已有 EPT 监视命中的 CR3、CPU、访问和物理地址，再查询该地址空间目前可匹配的 PID | 具有既有监视命中记录的 HVM 环形缓冲区 |
| 平坦物理镜像 | 找出具有内核侧自引用且能走通用户映射的四级页表根候选 | 文件偏移等于物理地址，物理空洞按原位置保留 |
| MemProcFS | 已解析的 DTB/PML4 与 EPROCESS 归属、PFN 私有页按 PID 汇总 | 选择挂载根目录。页表根分析须达到 100% |
| Volatility 3 | 活动进程链、EPROCESS 池、ETHREAD 池、四视图比对、网络端点池、空洞化、Ghosting、PEB 与映射、可疑可执行内存、线程入口、驱动对象与模块、内核回调、SSDT | 选择本机安装的 Volatility 3 可执行文件和内存镜像。离线运行需要已具备目标符号和相应插件 |

有自引用和有效用户映射的 PML4 是地址空间候选。进程归属需要其它证据。短命进程、已退出但仍被引用的对象、采样期间变化和缺失来源都可能造成不同视图之间的差异。线程与映像异常可能属于一个正常列出的进程。

## 本机计时样例

一次 Windows 原生回归在 959 个进程、14,886 个线程的现场取得下列结果。快照行与主表关联时，进程和线程快照另外共用 77 ms 身份核验时间，核实了 757 个 PID 的创建时间。其余行保留为弱身份线索。下面是一次样本，表中的对象数、权限和当时的系统负载均会影响耗时。

| 方法 | 采集耗时 | 本次结果 |
| --- | ---: | --- |
| 当前桌面的顶层窗口 | 4 ms | 842 个窗口 |
| TCP/UDP 端点 | 6 ms | 533 个端点 |
| Toolhelp 进程快照 | 41 ms | 959 个进程 |
| Toolhelp 线程快照 | 184 ms | 14,886 个线程 |
| CSRSS 句柄反查 | 347 ms | 934 个候选均无法核实，回执为不可用 |
| 系统进程句柄反查 | 4,795 ms | 737,875 个候选中读到 723,675 个，回执为部分完成 |

## 研究覆盖边界

下表沿用研究材料中的编号，便于区分某项检查能直接执行、只能从已有证据辅助核对，还是仍需专用采集器。

| 研究编号 | 当前能做的检查 | 尚缺少的能力 |
| --- | --- | --- |
| 1–12　进程与线程对象 | 现场活动链、CID、线程链、进程句柄和 CSRSS；镜像 EPROCESS/ETHREAD 池扫描及四视图；现有驱动的对象身份和生命周期校验；当前桌面顶层窗口归属 | 3 的无标签 EPROCESS 恢复、11 的完整会话/GUI 内核线程视图、12 的独立对象头扫描 |
| 13–18　调度 | 17 可从 ETL 读取上下文切换及已记录的 TID；线程对象、线程入口可与其它来源对照 | 13–16、18 的每核瞬时采样、就绪/等待队列、内核栈搜索和同步跨核验证 |
| 19–30　地址空间与物理页 | 自引用 PML4 候选、MemProcFS 页表根归属、已有 HVM 命中的 CR3；PFN 归属、工作集映射复核、Section/ControlArea 来源及每进程可执行 PTE/VAD 比对 | 22 的连续 CR3 采集、23 的完整地址空间重建、30 的跨地址空间内核映射比较；29 仅沿已取得的映射检查关联 |
| 31–43　事件与行为 | 31、33–35 和 42 读取已开启的相应回调记录；36–37 读取 ETL；38–39 读取安全审计和部分 Sysmon 事件；41 有现场端点和镜像池视图 | 32 子系统专用通知、40 WMI 实时订阅、43 Prefetch/Amcache 等历史痕迹聚合；已有记录的开始时间和保留窗口限制覆盖 |
| 44–53　虚拟化与硬件 | 可分析宿主导出的兼容镜像和已挂载的 MemProcFS 数据。已有 EPT 监视命中可以显示访问类型、GPA、RIP、CR3 和当前可查询的 PID | 独立宿主实时 VMI、自动布控页表/对象页、全部 CR3 装载追踪、Intel PT、DMA 采集、宿主暂停快照及带外调试控制 |
| 54–66　可疑执行 | 54–59 可从逐进程调查或对应镜像插件获得线索；61 受现有映像取样范围限制；62–66 提供内核可执行页/大池、模块、回调、IDT/SSDT、工作项与定时器 DPC 证据 | 60 的 APC 执行归属、系统所有可执行页的穷举、全代码与全部关键寄存器的完整性证明 |

Volatility 的四视图在同一份镜像中比较活动链、进程池、独立线程扫描和 CSRSS 句柄。MemProcFS 的页表根与 PFN 两项分别读取挂载中的 `misc/procinfo/dtb.txt` 和 `sys/memory/pfndb.txt`。[Volatility 四视图实现](https://github.com/volatilityfoundation/volatility3/blob/stable/volatility3/framework/plugins/windows/malware/psxview.py) · [MemProcFS 页表根格式](https://github.com/ufrisk/MemProcFS/wiki/FS_Misc_ProcInfo) · [MemProcFS PFN 格式](https://github.com/ufrisk/MemProcFS/wiki/FS_SysInfo_Memory)
