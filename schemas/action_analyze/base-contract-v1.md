# A0.1 / A0.3 base contract v1

This first subset gives A1 a Stored segment codec target and gives A1/A2 a common representation for primitive values, sample-local references, process and thread evidence, roles and two raw clock domains. The subset is versioned independently of the full event, project and control contracts. The applicable sources are [event identity §§2–4](../../docs/ActionAnalyze事件身份与协议契约.md), [storage §§2–4 and §5.2](../../docs/ActionAnalyze项目存储格式与恢复设计.md) and the [engineering baseline §1](../../docs/ActionAnalyze工程开工基线.md).

## Decisions and open points

| --- | --- | --- |
| Stable IDs have a canonical spelling. Existing evidence boot identifiers need not originate as UUIDs. | `uuid` validates lowercase hexadecimal 8-4-4-4-12 spelling. `machineId` and `bootId` are opaque nonempty text. Writers allocate new project/sample IDs randomly and preserve their spelling across reads. | Producer-specific machine/boot namespace and verification, UUID generator and sentinel policies. |

## Value and identity rules

- `u64`, `i64` and `nonzeroU64` use canonical decimal strings and numeric bounds. `u32`/`i32` are bounded JSON integer tokens. `-0` as a JSON integer token canonicalizes to `0`. `"-0"` fails the signed decimal-string rule. Addresses are lowercase `0x` plus 16 digits. An `address` pairs that text with `pointerWidth`; width 32 requires a zero high half.
- A `range` contains `base`, `pointerWidth` and `length`. Compute its exclusive end without narrowing. `base + length` must fit in u64 and, at width 32, may reach but cannot exceed `2^32`. Thus the last byte in a 32-bit range is addressable. Length zero denotes an empty interval. For blob slices, byte offset plus length must fit in u64. If both captured and original lengths are supplied, captured is at most original, and is strictly less for `truncated`.
- A `known` field carries `value`. `truncated` permits `value`. The other states omit `value`. An empty array, empty string and zero are known values when tagged `known`. A complete `null` is distinct from an absent field. Fixed-width float bit strings use the `f32Bits`/`f64Bits` types and preserve every bit pattern.
- Process identity compares `(machineId,bootId,pid,createTime100ns)` using typed equality. A thread compares its resolved process identity plus `(tid,createTime100ns)`. The identity includes observed source and `[firstReceiveQpc,lastReceiveQpc]` evidence, both from the same receive clock. These intervals describe the observation, not lifetime bounds. A strong classification needs a verified source and creation evidence. Equal bare PID/TID or weak observations can only yield candidate matches. Contradictory available identity components yield distinct instances. Sample/local IDs label observations, and a thread owner reference must resolve to its stated sample. Structural validity alone cannot establish the producer's evidence quality.
- Actor and target process/thread, observed thread, and header PID/TID occupy separate slots. Role links are same-sample references with type checked on resolution. An absent actor is never filled from the header or target. Raw FILETIME/QPC values retain `bootId` and `clockId`. QPC additionally requires `frequencyHz > 0`. Comparing clocks or interpreting causality also requires calibration and source evidence.

## JSON and Stored read contract

- Segment UUID bytes are the 16 hexadecimal pairs in canonical UUID text order, reading left to right and skipping hyphens. For `12345678-9abc-4def-8123-456789abcdef`, offsets 32–47 are `12 34 56 78 9a bc 4d ef 81 23 45 67 89 ab cd ef`. A native writer working from a Windows `GUID` must emit `Data1`, `Data2` and `Data3` most-significant byte first and append `Data4` unchanged. The segment's little-endian integer rule is separate from UUID encoding.
- Parse strict UTF-8 without BOM, repeated decoded keys, lone surrogates, exponent/fraction numbers or oversized JSON. For these fixtures the internal JSON bounds are 4 MiB per JSON object document, depth 32 (root container counts as 1) and 64 KiB per UTF-8 string value or key. The framing checker enforces integer token range `[-2147483648,4294967295]` in JSON areas. A schema determines which integer type a field accepts. External document BOM handling is a separate import step.
- Validate typed data before `aa-cjson-v1`. Sort keys by unsigned decoded UTF-8 bytes. Preserve array order in this subset. Preserve Unicode scalars exactly. Emit no BOM, insignificant whitespace or final line break. Escape U+0000–001F as lowercase `\u00xx`, escape quote and backslash, and emit other scalars literally. Hash original bytes as SHA-256. Hash semantic bytes as SHA-256 of `KSAA`, one NUL, ASCII domain, one NUL and canonical bytes. Each schema assigning a meaning to a hash must bind its domain. The vectors use `aa-base-fixture-v1` plus `query-v1` solely to test domain separation.
- Validate each header, size bound and checked slice before accessing variable bytes. Stored has equal stored/decoded size and a CRC for each domain even though the bytes are the same. The framing prefix advances only after the entire block passes record framing and CRC checks. A consumer can separately track the prefix that passes the declared v1 RawRecord/CanonicalEvent payload checks. On short header/payload or invalid framing, stop at the previous complete block. A valid segment header by itself is an empty readable prefix. A normal writer starts a segment when it has a block to write.
- An unknown codec or unsupported layout/version/flag stops this subset's decoder at that boundary. An unknown optional record can be preserved and skipped. An unknown required record preserves bytes and prevents complete semantic interpretation. Proposed numeric assignments by themselves do not supply a payload decoder. The checker treats other record payloads as opaque and reports `raw-only` when a required record's payload schema is outside this subset. A scanner reports readable framing separately from semantic completeness and archival durability.
- The fixed segment UUIDs, stream kind and segment ordinal must match the expected identity for the opened file. A1 binds segment identity to the catalog, validates required features, resolves source/epoch and other cross-stream dependencies, and publishes checkpoint watermarks. The readable prefix and a published durable or sealed prefix have separate meanings.

## A1 handoff

Use `archive-format.json` and the literal `vectors/stored-v1.json` for the CLI segment writer/reader and corruption scan. A test can write opaque record framing, inline raw bytes and an event core, reopen and independently check the bytes and prefix. Use the `$defs` in `value.schema.json` and `identity.schema.json` for small-document IDs and exact comparisons. The field catalog covers the declared normalized projection. Native byte-for-byte comparison, power-loss recovery and three-end interoperability have their own acceptance checks.

### Pending project manifest semantics

Storage §3 supplies the design input for future `project.ksaproj`, `sample.json`, revisions, journal and checkpoint contracts. Commit-pointer and catalog roots, required-feature negotiation, hash domains, document versions, cross-document identity checks and declared versus resolved watermarks still need an agreed schema. Dictionary payload and `.ksapack` schemas also remain pending. The segment vectors carry no manifest, checkpoint or seal assertions.
