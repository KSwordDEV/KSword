# A0.2 offline CLI contract v1

The offline shell has two entry points. `analyze capabilities [--json] [--backend offline]` returns one ordinary CLI result. Its JSON `data` is the capabilities object. `analyze session [--input repl|jsonl --output text|jsonl] [--backend offline]` keeps one controller alive. It defaults to `repl/text`. Machine clients select `jsonl/jsonl` and use byte streams for both stdin and stdout. Inside the REPL, `help [command]` shows local usage. The shell currently registers `hello`, `capabilities` and `quit`. See [Commands.cpp](../../KswordCLI/ActionAnalyze/Cli/Commands.cpp) and [Controller.cpp](../../KswordCLI/ActionAnalyze/Cli/Controller.cpp).

## Admission

1. Decode one JSON object per UTF-8 line with LF or CRLF. A line body can contain at most 1 MiB. The body excludes the delimiter. Reject a BOM, stray CR, malformed UTF-8, lone surrogates, repeated decoded keys, leading zeros in number tokens, fraction or exponent numbers, and integer overflow. Use at most 128 keys per object, 4096 items per array and 65,536 JSON value nodes, counting the root and every value. Count at most 32 nested containers along any path, with the root object at level 1. Objects and arrays both count, including empty ones. A 33rd container returns `depth-limit`. A scalar inside the 32nd container is allowed by the depth rule. The offline shell limits `requestId` and `method` to 128 UTF-8 bytes each and rejects ASCII C0 and DEL in both. Strings preserve their spelling.
2. Validate the closed envelope in `request.schema.json`. If a frame cannot provide a valid request ID, emit `protocolError` with `requestId:null`, one-based `inputSequence` and a zero-based `error.byteOffset` when available. JSON parsing failures occur before the ID is extracted. Shape errors detected after a valid ID is extracted, including an otherwise parseable empty container at level 33, return a `response` with that ID. Envelope and parameter errors with a valid decoded ID also return a `response`. Unrecognized envelope keys, including `session` and `expected`, return `unknown-field`. A nonempty unterminated JSONL line at EOF or an overlong input line closes the input protocol after the error.
3. Match `method` exactly and use its `paramsSchema` from `method-catalog.json`. For a valid envelope with a fresh request ID, an unavailable or unknown method returns `unsupported-method` with CLI error code 5. A failed request generally leaves the controller available to receive further requests. `controller.hello` accepts 1–16 positive uint32 integer tokens. It selects version 1 if present or returns `no-common-version`. Requests always carry `schemaVersion:1`. A client can send a supported request before negotiating.

`availability:"shell"` identifies the baseline controller methods. `availability:"project-integration"` identifies the project provider methods. At runtime read `projectStorage` and the exact entries in capabilities `methods` before calling a project method. The baseline shell advertises `projectStorage:false`. Project-enabled source populates capabilities and REPL help from the provider's dispatch table.

## Project provider

The adapter holds one project at a time. `project.create` takes a new directory path and full `settings` and opens the project for writing. `project.open` takes a directory or `project.ksaproj` and defaults to `read-only`. Specify `access:"read-write"` to acquire the writer. `project.query`, `project.close` and all sample methods require the exact `projectId` returned for the open project. A valid UUID for another project fails with `project-id-mismatch`. Paths locate documents. The opened document supplies the identity. `project.close` releases the reference and file locks. [ProjectCommands.cpp](../../KswordCLI/ActionAnalyze/Cli/ProjectCommands.cpp)

`project.save` replaces the whole settings object. `sample.create` records one descriptor and its frozen settings with status `not-collected`. Both require a canonical, non-nil, lowercase `expectedRevisionId` UUID and a writable project. The serialized provider checks the expected revision against the current saved revision before making persistent changes. `stale-revision` creates no new revision or sample. A successful save of identical settings keeps the current revision. Sample creation uses the current revision and advances the project generation. REPL supplies project identity from the open document. The short forms `project save TITLE [NOTES]` and `sample create TITLE` also take the current revision from that document. JSONL clients supply both IDs. `title` requires 1–1024 UTF-8 bytes and forbids ASCII C0. `notes` is required in JSONL settings, allows empty text, and accepts up to 64 KiB of UTF-8 with LF and tab as the permitted C0 characters.

`project.save` accepts `settings.breakpointDefinitions` as a complete set of up to 64 offline definitions. A new row uses an empty `breakpointDefinitionId` and `definitionRevision:"0"`. An existing row supplies its committed ID and definition revision. An empty array explicitly clears the set. After migration to the definitions feature, each save supplies the complete set. `project.query` and successful save responses return the committed definitions in `settings`. Sample responses return the configuration at creation time in `frozenSettings`. `project save settings EXPECTED_REVISION QUOTED_JSON` is the REPL form for full settings. It uses the explicitly supplied revision and the open project identity. The JSON object occupies one quoted REPL argument with doubled inner quotes. `project create` and the older REPL save form accept the title and notes fields. [Definition and storage contract](../../docs/action-analyze-planning/project-breakpoint-definitions.md)

`sample.query` resolves the `sampleId` inside the open project. Its frozen settings and hashes describe the sample's saved revision. Its `generation` describes the current project snapshot. `sample.list` defaults to `start:"0"` and `limit:256`, with `limit` an integer in 1–256. `start` requires `generation`. Any supplied generation must match the open snapshot or the request fails with `stale-generation`. Restart paging at `"0"` with the current generation. A start equal to the sample count yields an empty page. A start beyond it fails with `invalid-params`. At most 4096 samples belong to one project. Time, count, generation and offsets use canonical decimal `u64` strings. `createdUtc` is FILETIME in units of 100 ns. Hashes use lowercase 64-character SHA-256 hex text. The list result is capped at 260,096 serialized bytes to leave space in a 256 KiB output frame. `nextStart` equals `start` plus the actual number of rows returned and is null at the end. A nonterminal page returns at least one row.

Successful open, close, create and save operations and successful sample creation yield `effectPhase:"observed"`. Query and list successes use `not-applicable`. A project opened on its recovered previous manifest is read-only and sets `recoveredPrevious:true` with `primaryFailure` describing the primary-manifest failure. See `projectError` in `request-message.schema.json` for the stable provider IDs. `error.source:"cli"` carries the CLI error code. `error.source:"win32"` carries the original native code. The response `error.errorId` identifies the failure independently of its source code. For stale revision, mismatched project ID, invalid params and read-only writes, no persistent change occurs. Other storage errors report the observed failure. A failed write can leave staged files pending recovery. [ProjectDocument.cpp](../../KswordCLI/ActionAnalyze/Project/ProjectDocument.cpp)

The offline profiles leave live capture and control, general archive record queries, rule execution and request cancellation unsupported. Project, sample and archive methods operate on local project files.

With `includeCapture:true`, `sample.query` returns a historical `captureArchive` receipt for the selected `captureOrdinal` (default `"1"`). For a passive API follow archive, it verifies consecutive [raw-only checkpoints](api-archive-checkpoint.schema.json) from the first segment through the requested ordinal, with a limit of 128 segments per request and 512 KiB per segment. The receipt exposes the verified raw prefix and the segment's exclusive start and inclusive end source-row coordinates. A missing or invalid checkpoint preserves the preceding verified ordinal. Legacy follow archives without checkpoints report `legacy-unpublished`. The terminal describes the local end of following and source coverage stays `unknown`.

## Archive inspection

`archive.inspect` is available when capabilities reports `archives:true` and lists the method. The standalone shell and project-only profiles report `archives:false`. The REPL form is `archive inspect SAMPLE_ID raw|records|control ORDINAL [END_OFFSET]` and supplies the open `projectId`. JSONL calls send the exact open `projectId` and a registered `sampleId`, both canonical, lowercase, non-nil UUIDs. `stream` is `raw`, `records`, or `control`. `ordinal` is a canonical decimal string in `1..18446744073709551615`. `endOffset` is optional and is a canonical decimal string in `0..1073741824` when present. Invalid streams and ranges return `invalid-params`. [Method schema](archive-inspect-method.schema.json)

The provider verifies the sample in the open project's committed catalog. It resolves one segment using the sample ID, fixed stream directory, and 20-digit zero-padded ordinal plus `.ksaseg`. The request accepts logical identity fields only. The project storage layer opens a read-only handle and the scanner verifies the project, sample, stream and ordinal in the segment header. The `analysis` stream requires a run binding outside this method. [ProjectArchive.cpp](../../KswordCLI/ActionAnalyze/Project/ProjectArchive.cpp)

Scanning begins at byte zero. `framingCoverage` echoes `requestedEndOffset` or `null`. `fileBytes` is the length observed at scan start, and `scanLimitBytes` is the minimum of that length, any requested endpoint, and 1 GiB. If the length is unknown, both fields are `null`. `framedBytes` ends at the verified header or the last complete validated block. The block ordinal, sequence and record counts describe that prefix. `createdUtc100ns` comes from the identity-checked header. Both last-value fields are `null` when zero blocks were verified. `interpretedBytes` and `durableBytes` are always `null`. They indicate unknown record interpretation and unknown durable coverage, respectively. [SegmentInspection.h](../../KswordCLI/ActionAnalyze/Archive/SegmentInspection.h)

`framingStatus` is `framing-complete`, `truncated`, `corrupt`, `unsupported`, or `io-error`. A completed inspection delivers this status and any validated prefix in `result`, with response `error:null` and `effectPhase:"not-applicable"`. `framingError` is `null` on complete framing. Otherwise it has `reason`, decimal-string `offset`, and `win32Error` as a native code or `null`. The offset identifies the framing issue and may lie after the validated prefix. An explicit endpoint inside a block can produce `truncated`, including on a file whose entire framing would pass. A header-only result with zero verified blocks describes the inspected range. [SegmentReader.cpp](../../KswordCLI/ActionAnalyze/Archive/SegmentReader.cpp)

Missing stream directories and segment files produce top-level `archive-stream-unavailable` and `archive-segment-unavailable` request errors with `result:null`. Sample lookup can separately fail with `project-data-not-found`. These outcomes describe availability of the requested data. Activity is undetermined in all three cases. `generation` identifies the open project snapshot and supplies context for the returned identity. The ledger retains completed inspections with a result, including framing findings. A matching request ID replays the captured inspection. Use a fresh ID to inspect the current file bytes. [ProjectCommands.cpp](../../KswordCLI/ActionAnalyze/Cli/ProjectCommands.cpp)

`archive.inspect` also accepts the explicit `view:"graph"` for `stream:"raw"`. Its REPL form is `archive inspect SAMPLE_ID raw ORDINAL graph [LIMIT [AFTER_SEQUENCE EXPECTED_SHA256]]`. The graph request resolves the endpoint from the verified archive and disallows `endOffset`. `limit` is a JSON integer in 1–100 and defaults to 100. `afterSequence` is an exclusive raw record sequence encoded as a canonical decimal `u64` string and defaults to `"0"`. A nonzero cursor requires `expectedSha256`, a lowercase 64-character hex digest. Continue within the same project, sample and ordinal using `nextAfterSequence` and `prefix.sha256` with a fresh request ID. A changed raw prefix returns `stale-revision`. A null cursor marks the end of observations for that segment.

For a mixed API and ETW sample, use `stream:"raw-etw"` with `view:"graph"` to read the separately checkpointed ETW segment. Retain the stream with each cursor and coordinate. The framing view accepts `raw`, `records`, and `control`.

The graph view reads verified API imports, passive API segments with a continuous chain of published raw checkpoints, ETW segments with a verified two-stream checkpoint, and complete KSword callback batches. It returns the frozen sample description hash, raw prefix digest and endpoint, total segment observation count and page of observations. Each observation includes source identity and epoch, optional source sequence and verified Stored block, record and inline-data coordinates. Its header PID and TID are source hints. The optional `tree` object groups the page's raw record sequences into `unresolvedCandidates` and `contextObservations`. Current formats carry `null` instance, execution and finding fields, empty `nodes` and `relations`, and `sourceCoverage:"unknown"`. Passive API returns `archiveSource:"api-follow-checkpoint"` and the verified segment's `finalSegment` flag. Reading verifies up to 128 consecutive API checkpoints. A missing preceding checkpoint prevents the requested page from opening. Missing or invalid source evidence produces a request error with `result:null`. [Method schema](archive-inspect-method.schema.json)

Callback archives use `archiveSource:"ksword-callback-batch"` on `raw/1`, with `finalSegment:null`. Their `callbackHints` distinguish the notification context from the target PID and TID. These identifiers do not establish instance identity, outcome or execution.

For callback archives, `callbackHints.notificationUtc100ns` is the recorded notification time as a decimal string, or `null` if the source value is nonpositive. It is independent of thread creation time. The `callbackBatch` receipt is the same on every page, including a complete empty batch. Its `afterSequence`, `nextSequence` and `latestSequence` are native cursors. `returnedCount` includes native rows omitted from this thread-creation archive. `lostBeforeFirst` is the reported overwrite count before the first returned row, and `droppedCount` is the ring's cumulative counter at read time. A missing count remains `null`. `caught-up` refers to the recorded native cursor, and does not change `sourceCoverage`.

API import observations expose the packet's exact `operation` and stable `apiFamily`. `apiCategory` is `memory` for `memory-write` and `section-map`, and `thread` for `thread-create`, `apc-queue` and `thread-context`. These fields describe the archived call and are recomputed from its packet. Both fields are `null` for ETW observations.

## Output and closure

Machine stdout uses the `request-message.schema.json` union. The first record is a `hello` containing capabilities. Subsequent records use the same opaque `controllerId` and increasing `streamSequence`, independent of request input ordinals. The output sequence starts at `"1"`. The shell uses only `completed` responses. The nonnull result is an object. Errors carry a stable `errorId` and distinct source/code. Use `errorId` to make decisions. `effectPhase:"observed"` on `controller.shutdown` acknowledges the shutdown request. The later `summary` reports the terminal controller outcome. Stdout frames have a 256 KiB body limit. The current queue permits 16 frames including the in-progress write and applies a 5-second age limit to the oldest output frame.

For JSONL, both profiles cache successful queries. The project provider also retains successful and failed receipts from project open, close, create, save and sample create once dispatched. Failed queries, pre-dispatch rejections and shutdown create no replay entry. After envelope validation, a cached ID takes precedence over new dispatch and current project or revision checks. Matching method and parameters replay the whole captured receipt including `phase`, `effectPhase`, `result` and `error`, with a new `streamSequence`. The server does no new project work on replay. A repeated stale rejection stays stale even if the expected revision later becomes current. A changed method or parameter under an already retained ID returns `request-id-conflict` with CLI error code 1 and no new effect. Comparison sorts object keys and preserves array order. Fields supplied explicitly remain distinct from omitted fields. The ledger belongs to the running controller and exposes no portable effect hash. Use a new request ID for a fresh read or a deliberate new write.

The baseline shell caps the ledger at 4096 entries. The provider caps it at 4096 entries and 32 MiB, charging the request ID, method, normalized parameters, serialized result and fixed entry overhead. It reserves capacity before dispatch. Capacity exhaustion returns `request-ledger-full` with CLI error code 6. Cached receipts remain replayable. The provider reserves one entry and 2 KiB for a valid `project.close` on the current project. Both profiles retain shutdown with a fresh ID. [Controller.cpp](../../KswordCLI/ActionAnalyze/Cli/Controller.cpp)

EOF and successful shutdown finish the controller with exit code 0. The console handler consumes Ctrl-C and keeps the shell running. Ctrl-Break requests orderly closure with exit code 6. The shell has no cancellable job, and `request.cancel` with a fresh ID returns `unsupported-method`. A fatal input error emits `protocolError` and then a terminal summary when stdout is available. Framing failure reports `protocol-failed` and exits 1. A fatal read failure reports `input-failed` and exits 3. An internal exception handled by the session loop reports `internal-error` and exits 3. A failed request does not decide the exit code. Broken or stalled stdout can prevent summary delivery and is surfaced by exit code 3. `clean:true` reports the offline controller's lack of unresolved live or archive responsibility. With project integration, release the read-only project reference before successful closure is reported. The shell neither monitors the caller process nor provides recovery after controller death.

## Static validation

Run `python -B schemas/action_analyze/vectors/validate-request.py` from the repository root. The validator uses Python `jsonschema` and resolves schemas locally. It checks baseline framing and responses, the three capability profiles, project arguments and receipts, and archive request, framing and availability vectors. Actual pipe I/O, timeout, signal delivery, replay dispatch and file inspection require product tests.
